## The five whose failure would block the release candidate most

Judged from what each script actually asserts. Three of the five are the release-candidate gates
themselves; two are the proofs an RC is a controlled change. Their current state is named, and a
`skipped` row is a gate that this harness cannot judge (it writes its verify page into `Builds/` or
`Working/RC/` and the write guard stops it) - not a pass.

1. **`v01_gates.py` - V-01 file gates on the candidate.** It is the gate set that decides whether an
   RC is shippable at all: aafdiff (only planned files changed), `.toc` records internal where
   required, `spec_check.py`, both hard budgets from `settings/asset_memory_budgets.bin` (Model
   <= 4,915 KB, Texture <= 7,065 KB), parts re-read, `jc3adf` re-read of every edited module, the
   `.epe` ConvertProperty round trip, and read-back of every edited value through the packed `.ee`.
   A red here means the build ships bytes the game cannot read or blows a memory cap. **Status in
   this sweep: skipped** - blocked writing `Builds/bm-RC1/verify/v01`; unjudged, and it targets RC1.
2. **`v05_predictions.py` - the V-05 predicted-results sheet.** Every Q check in `GRAB_BACKLOG.md`
   section 9b must have a predicted number and pass band *before* any in-game test; an id without a
   row fails the check, and a blocked row is a value absent from every source on disk. A red sheet
   means the RC cannot be judged against its own plan - every later "it works" claim loses its
   baseline. **Status: real failure** - sheet differs from the re-derivation; 28 Q checks parsed,
   20 predicted, **7 blocked**, 1 excluded.
3. **`v_joint_trace.py` - row -> manifest -> generator -> built tree, joint by joint.** This is the
   chain that decides whether the turret and cannon carry a real constraint rather than
   `constraint_index = -1`, which is exactly the payload RC3 adds (two hinges, 11 and 12). Its 21
   oracles recompute the chain and compare the verify page byte for byte, so a red here puts the
   RC's newest content in doubt at the level the card cares about. **Status: real failure** -
   20/21 oracles pass; `Builds/bm-RC2/verify/joint_trace.md` differs from the regenerated bytes.
4. **`v03_wiring2.py` - V-03 wiring gates on the candidate.** G1 every `SWeaponPoint` names a part in
   the built parts module, G2 every `objectid` resolves, G3 every asset path in the `.epe` and the
   edited `.vmodc` modules resolves in the build or the shipped index, G4 audio (5 slots / 45 GUIDs /
   5 events, via `bm_audio.py --check`), G5 the Rebel Drop item hash and leaf ship in the dropzone.
   A dangling reference is an RC that crashes or silently loses a weapon, and G4's delegate is
   already red in the a..g half (`bm_audio.py: Working/Audio/bm_bank_manifest.json differs`).
   **Status: skipped** - blocked writing `Working/RC/verify-bm-RC2/_v03.epe`; unjudged.
5. **`rc_diff.py` - RC1 vs RC2, file by file.** It is the only proof that the candidate differs from
   its predecessor *only* where the plan says: payload / release metadata / per-run artefacts, with
   module-level decoding applied only to files that changed. Without it an RC cannot be certified as
   a controlled change, whatever its own gates say. **Status: real failure** - `check FAIL` with 2
   failing assertion(s) (the md placeholder assertion still passes).

Also red and release-adjacent, so they belong on the same watch list: `t23_closeout.py`
(`build_batches.json` differs, 3 problems - gate TX bookkeeping), `v05_combat.py` (guard-blocked),
`reset_status.py` / `reset_status2.py` (both status pages stale) and `t_rows.py` (its `--check` is a
subcommand, so this sweep never exercised it).

## Verdict key

| verdict | meaning |
|---|---|
| `ok` | exit 0 |
| `real failure` | nonzero exit with no dependency or missing-file signature in its output |
| `missing dependency: X` | `ModuleNotFoundError: No module named 'X'` |
| `missing input file: P` | `FileNotFoundError` (or an explicit missing-file complaint) for `P` |
| `skipped - writes outside tmp/: P` | the write guard blocked a write to `P`; the check never ran |
| `usage error - --check not accepted` | argparse rejected `--check` (or demanded another argument), so the file only *mentions* `--check`; no check exists to run |
| `timeout` | exceeded the wall limit |
