## 6. UNKNOWN

1. **The badge coordinates** (`Upgrade1` -10.0/96.3, `Upgrade2` -10.5/100.6). They are
   `PlaceObject2` matrices in the GFx tag stream, not AS3 constants: a search for `96.3`,
   `100.6` and `182.5` over the whole decompile returns nothing. The report's tag parse decoded
   them; this audit did not re-parse the tags, so they rest on the report's own tool. Settled by
   re-reading the badge placements in the movie `bmak_hud.py` carves.
2. **The clip frame counts** (FillMovie 102, Health 162, badges 65, Background 32). Frame counts
   are SWF timeline lengths, absent from both the spec and the AS3. Consistency only:
   `this.FillMovie.gotoAndStop(this.BoostLevel + 1)` with `level` 0..100 needs at least 101
   frames, so 102 is possible - the count itself is not proven here.
3. **Which clip owns each frame label.** The spec's labels are a flat set. Every label the report
   attributes to a clip is a member, but membership is not attribution; the per-clip mapping is
   the report's tag read.
4. **`ch1040`'s identity.** Unnamed third child of `BoostMovie` at (5.0, -83.7), 1 frame, no
   setter - the report marks it UNKNOWN; nothing in the spec or the AS3 names it either.
5. **The report's `Health` sub-clip offsets** (`Healthbar`, `ArmourForeground`, `BG`, `XPbar`).
   They use `PlaceObject3` (MATRIX3D), which the report says its tool does not decode, so it
   quotes no offsets - and this audit quotes none either.
