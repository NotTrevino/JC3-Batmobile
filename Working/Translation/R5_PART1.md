## What the four classes mean here

| class | meaning |
|---|---|
| built-and-equal | the member exists in `bm-RC2` and holds the value the row states, at the row's precision |
| built-and-different | the member exists and holds another value (or the row's count differs) |
| absent | the member / entry / asset the row names is not in the build |
| cannot-read | the data is in a container this script cannot decode (`.epe`/`.physicsc` RTCP, opaque `CarPaintMM` bytes) or no member carries the value |

## Limits (and why the remaining rows say cannot-read)

- `sportsmuscle.physicsc` and `v0300_car_kensington_sportsmuscle_debug.epe` are RTCP containers, not 
  ADF: `jc3adf.Adf` rejects them (`0x43505452` magic). Their shape/socket/preset data is not read here.
- `rbm_geom` decodes CarPaintMM blocks and their texture lists, but exposes `static_params` as opaque
  bytes: a named diffuse colour/opacity member does not exist in the decoder, so T-MA3/T-MA5 stay
  cannot-read rather than being called absent.
- the class is about **presence**, not about whether the value is correct for the car. A row can be
  built-and-equal and still be out of date (e.g. `T-P2`'s 42/17 versus the build's 61/20 is
  `built-and-different` because the part set grew, not because the number is wrong in itself).
