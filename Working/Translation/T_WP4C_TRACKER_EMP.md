### 2.2 Gating: does it need a tracked target?

Lead (b) is **partly proven and partly refuted**. Proven: the lock is fed by the tag -
`TagTarget` is typed `RVehicle`, `SetLockOnTarget(RVehicleNPC)` takes the vehicle, and
`LockOnTime` accumulates to `MissileLockOnDuration` = 2.0 s (civilian 1.0 s).
Refuted as a hard gate: the same class carries a **dumb-fire path** -
`GetDumbFireTarget(AimDirection)` and `FireMissile(FireDir)`, plus
`bTryingToAcquireNewTarget` and `SwitchLockOnTarget(WorldDirection)`. So there are two firing
paths in the class, one locked and one aimed; **whether a dumb-fired missile still disables is
UNKNOWN** (native), and that is exactly the difference the tracker makes.

What happens with no track, as far as the data goes:

| tag lost mid-lock | `UnTagTarget`, `UntagWarningEvent` = `Play_HUD_fail`, `LoseLockTime`, `PromoteUntagPromptTime` | the failure is *audible and prompted*, not silent: a HUD-fail event and an untag prompt timer exist |

## 6. COMPROMISES (unapproved - the operator approves through Claude)

### C1 - the tag half of the tracker
**What:** ship the tracker missile and the HUD lock marker, but not a tag that gates the missile.
**Why:** JC3 has no tag/allegiance member on any vehicle (HACKABLES: `allegian` 0/295), so the
lock would have to be a script-side convention.
**Accuracy lost:** BmAK's core loop - mark once, then the EMP missile follows *that* car - becomes
"aim again for every shot"; a tagged car cannot be remembered, and the untag failure prompt has
no state to fire from.
**RECOMMENDED COMPROMISE:** R1 + R3 marker only. It keeps the missile, the blast and the HUD
reticle; it drops the memory of the tag.

### C2 - the disable
**What:** ship the Immobilizer as a missile whose impact pulse is `truck_emp.ftune` (100 dmg / 25 m).
**Why:** the disable itself has no decoded member on either side; the pulse is the only EMP object
the fleet actually carries.
**Accuracy lost:** if the pulse does not disable, the missile is a weak blast - the gadget's whole
point (T-WP4's original block).
**RECOMMENDED COMPROMISE:** R1 first (one file edit), and only fall back to C2's plain blast if the
5-minute shot shows no disable.

### C3 - the booster mesh
**What:** keep the donor's nitro force and add a jet part at the `Afterburner` socket without the
BmAK gadget mesh.
**Why:** the mesh object lives in BmAK's weapon packages and the donor chassis has no jet part.
**Accuracy lost:** the flame/booster silhouette is a JC3 part, not BmAK's, so the rear of the car
will not match frame-for-frame.
**RECOMMENDED COMPROMISE:** R5 placeholder now, T-12's part pass later - the socket is decoded,
so the geometry can be swapped without moving anything else.
