## Answer

- BmAK banks the Batmobile references: **27** distinct names over 27 bank exports; **361** events name one of them.
- searched: JC3 archive index **81,952** rows / **81,949** named paths / **78,907** distinct hashes over **88** archives (base + patch + dlc mounts);
  the JC3 banks' FSB5 name tables **649** sample names; the live dropzone **2** bank/pck/fsb files.
- of those 27, **9** are car/weapon banks (`BML_`/`VEH_`/`AUX_`/`WPN_`) and **18** are dialogue, sequence, prop and ambience banks the Batmobile's events also name.
- **ABSENT: 27 of 27**. Every bank was searched by name (index path, FSB5
  table, dropzone file name) and by Jenkins hash (bank name, and `sound/fmod_banks/<name>.bank`) against
  every hash the index carries, named and anonymous alike.

**The rows' wording is therefore correct for the JC3 install, and its scope is what matters:** the banks
are not files or names JC3 ships. They are BmAK assets; `AUDIO_BANKS.md` shows 27 exports of them
inside the BmAK install, so 'absent from the install' is true only when 'the install' means JC3. The loss
T-AU3/T-AU5 record is not that the banks failed a search - it is that BmAK's FEV graph cannot be authored
into JC3's bank format at all (`JC3_AUDIO.md` section 10 route b).

## 2. Method, and what each method can prove

| method | what is searched | what a hit would prove | what a miss proves |
|---|---|---|---|
| N1 | every named path in `Research/JC3Grab/INDEX.jsonl` (basename substring) | a JC3 file carries the bank's name | no JC3 path names it |
| N2 | the JC3 banks' decoded FSB5 sample-name tables | a JC3 bank owns a sample with that name | no JC3 sample is named after it |
| N3 | the live `dropzone/` tree, file names | a loose override already supplies it | the dropzone does not |
| H1 | Jenkins(name) and Jenkins(`sound/fmod_banks/<name>.bank`) vs every index hash | an anonymous archive entry is it | no entry hashes to it |

A miss is not proof of non-existence in general - JC3 could carry the bytes under a third name or hash
space. It is proof that **nothing in the install can be addressed as that bank**, which is the question
a build has to answer.

## 5. What this does and does not settle

- **Settled:** the banks are not in the JC3 install under their own names or Jenkins hashes, in the
  archive index, in the banks' name tables or in the dropzone. T-AU3/T-AU5's `why` is accurate about
  JC3.
- **Settled:** the banks DO exist as BmAK assets (27 exports read by `AUDIO_BANKS.md`), so the row must
  not be read as 'the source audio was never grabbed'.
- **Not settled:** whether any JC3 sample is an acceptable substitute. The candidate table is a
  name-level shortlist; choosing one needs an audition, which is a Q step.
- **Not settled:** whether a JC3 bank could carry a BmAK event id. `AUDIO_BANKS2.md` searched one
  (`0x6BB2C66E`) across 117 exports and found it nowhere; a wider id sweep is not this card.
