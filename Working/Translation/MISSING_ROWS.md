## 4. Why the interaction rows use the doc label `T-13i`

`t_rows.py` parses `T13_FX.md` under the tag `T-13`, and that document already owns 17
rows. `t9_interaction.py` also stamps its output `"card": "T-13"` because the backlog
calls the interaction card T-13 (`GRAB_BACKLOG.md` §7). Writing the interaction rows with
`doc` = `T-13` would merge two cards in every per-document count, so this proposal labels
them `T-13i`. That is a bookkeeping choice, not a translation decision: if the ledger owner
prefers to re-tag the FX rows as `T-17`, the same eight rows splice in unchanged with
`doc` = `T-13`.

## 5. What would make this proposal wrong

* A row with one of the proposed ids appears in `T_ROWS.jsonl` - `--check` fails.
* Doc `T-13i` gains rows, or the ledger's `T-13` gains a non-`T-FX` row - `--check` fails.
* `VALUES.json`'s gain, `MODLOG` §107's literal, or either transfer byte pair changes - `--check` fails.
* `t9_interaction.py`'s constants (band, clearances, stations, socket) or its counts move -
  `--check` fails.
* A placed transform stops equalling `surface + normal x clearance`, or a yaw stops being
  `atan2(forward.x, -forward.z)` - `--check` fails.

## 6. UNKNOWNs

* **The donor's side clearance** (left/right). G2-18 decoded the stunt areas only, so the
  side value is the chosen 0.1 m and is labelled chosen, not decoded.
* **A per-side station spread.** One station per side (y 1.15, z -0.95); the donor's world positions are
  mostly inherited container origins (70 of 85), so there is nothing finer to copy.
* **Which gain a future build will use.** The ledger row for ALB-2 can only state what
  ALB-2 did (4); GRB-6's derived 3.4476 is a different card and is already covered by `T-MA3`.
  Note `T-MA3`'s own cells pair the derived gain with the ALB-2 byte pair (0x837d86), which no gain reproduces;
  this proposal does not edit that row, it only records the arithmetic.
* **The exact luma operands behind 3.4476.** VALUES.json's source string quotes them at 4 dp (0.1837 / 0.0533
  = 3.44653), so the unrounded operands are not recoverable from that file - recorded as decoded, not derived.
