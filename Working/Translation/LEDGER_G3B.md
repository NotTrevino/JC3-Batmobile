## 5. Findings that change the first pass

- The first pass never opened a value: its evidence table quoted card-level summaries (a census, a mass total, a JSON pointer) and paired them with rows whose claim is a different quantity. 9 of its 18 rows are `WRONG_CARD`: the cited card answers another question.
- 3 rows are `WRONG_VALUE`: the card's number is not the row's number - for colour, the card carries the *authored override* (0.025787 / 0.025787 / 0.03) while the row states the *effective* colour (0.056738 / 0.05158 / 0.06), and the card itself says the combine rule is UNKNOWN.
- 6 rows `HOLDS`, each on a line that states the value the row uses.
- One card in the named list does carry a physics value the ledger never used: `CLASS_DEFAULTS.md:317` decodes `DriftCorrectionSteerSpeed` = 1.0, which is exactly T-ST5's BmAK side. `CLASS_DEFAULTS.md:158` also decodes `ChassisMass` (SVehicle) = 210.0 - relevant to T-M1, which currently rests on a fleet class choice (6,000 kg) rather than on this number.

## 6. Method and limits

- Each status names one card and one line. `--check` re-reads that line and requires the quote to be a substring of it, so a rewritten card fails the row rather than silently passing.
- A row is `OPEN` when none of the cards read here carries it, even when the row itself cites a card: the cited file (`CHAIN.json`, `T3_FLEET.md`, `VALUES.json`, `PARTS_TABLE.jsonl`, `FX_TABLE.jsonl`) is named in §4 instead of being quoted from memory.
- No value here is a translation decision; the rows keep their own proposals.
