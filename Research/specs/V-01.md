## 3. Blockers

- **V-01/1 — no subject.** `Builds/bm-RC1/` is missing; its only producer (B-14, gate BX,
  `GRAB_BACKLOG.md:1097`) is `todo` and its spec is BLOCKED on B-05 (`blocked`, line 1338) and   B-06/B-07/B-08/B-13 (`todo`, line 1341). Seven of the eight gates cannot execute.
- **V-01/2 — no receipt to diff against.** The card's "only planned files" is a set comparison
  between `aafdiff` output and a per-file `sha256` receipt. No generator writes one today
  (`Tools/scripts/bm_rc.py` absent; `bm-002.changed_files` is names-only). Until it exists, "planned"
  has no machine-readable definition and the gate would have to invent one from prose.
- **V-01/3 — the `.toc` gate does not exist.** `eetoc.py` compares, writes and patches records; it
  does not check that every record lies inside the `.ee` stream, that every tree file has a record,
  that every record's file exists, or that modules are internal (offset ≠ 0, R8). `verify_install.py`
  checks the receipts' hashes for the installed pair, not record-level integrity.
- **V-01/4 — R9's Texture budget has no implementation and no agreed method.** `7,065 KB` appears
  only in prose (`GRAB_BACKLOG.md:71`; `Tools/scripts/appearance_plan.py:478,497` explicitly:
  "Per-skin texture budget is **UNKNOWN**"), and no script counts texture bytes. Model has a cap
  constant only (`bm_parts.py:97 CAP_MODEL_KB = 4915.0`, `bm_lights.py:71 BUDGET_KB = 4915.0`).
- **V-01/5 — the Model budget is contested, and today's method fails.** `bm-002`'s `--check` prints
  `model bytes …: 8271315 B = 8077.5 KB (222 files); bm-001 7032.4 KB (151 files), delta +1045.1 KB`
  — i.e. **over** `4,915`. The base is already `7,032.4`, so either R9 counts something other than
  distinct referenced `.rbm` bytes, or the split blew the budget. `Research/specs/B-04.md:54-57`
  records the same number and does not resolve it. A gate cannot be built on an unresolved unit.
- **V-01/6 — the card's `--check` verbs are single-tree.** `bm_parts.py:78`, `bm_health.py:53`,
  `bm_audio.py:74` pin `TAG`; no `--build`/`--tag` flag exists. (`--check` still runs and still
  passes — on `bm-002`/`bm-009`/`bm-004`, which is not the RC.)
- **V-01/7 — two named verbs are wrong.** `jc3parts.py check` never reads a built module (B-04
  review, §"issuances"), and `spec_check.py` has no `--parts` mode (quoted in §2 row 12). The card's
  wording cannot be satisfied literally; the spec below substitutes equivalent, stronger commands.
- **V-01/8 — nothing to read back for the entity graph.** B-05 is `blocked`; 60 of its 69 skipped
  rows are `UNKNOWN` (`Working/Entity/bm_epe_edits.json`, `skipped[].why`), and its `.epe` is staged
  in `bm-005/aaf` with no `.toc` record anywhere. G7/G9 would gate a file the game can never load.
- **V-01/9 — the collision hulls are in no tree.** `Working/Collision/batmobile.physicsc`
  (`192c12479d81da6e…`) exists but no `Builds/*/aaf` carries it (B-14 spec §1), so the `.toc`/`jc3hkx`
  gates would validate the **donor** hulls while reporting green.

### 4.2 Steps, in gate order

0. **Preconditions.** `v01_gates.py --check` starts by requiring
   `Builds/bm-RC1/receipt.json` with `schema: 2` and a non-empty `files[]`. If absent:
   `BLOCKED: Builds/bm-RC1/receipt.json missing (B-14/gate BX not done)` and **exit 2**. Today that
   is the whole run.
1. **G1 `diff`** — `python Tools/scripts/aafdiff.py Builds/bm-001/aaf Builds/bm-RC1/aaf --hash --out Builds/bm-RC1/verify/v01/aafdiff.md`.
   Pass = `removed == []`, `added ∪ changed == {f.path for f in receipt.files if f.owner_card}` and
   `|added ∪ changed| == |that set|`; any unplanned path is a failure naming the path. Banks are
   compared separately (`receipt.replaced[]` ↔ `Builds/bm-RC1/banks/*`, sha256).
2. **G2 `toc`** — for the RC `.ee`/`.toc` pair: every record has `offset + size ≤ len(ee)`; every
   file under `aaf/` has exactly one record and every record's file exists; every `.vmodc`/`.epe`/
   `.onlinec` record is **internal** (`offset != 0`, R8) and its sliced bytes sha256-equal the tree
   file; external records point at bytes that exist in the archive. Prints
   `records N, internal N, bounds ok N/N, tree↔records N/N`.
3. **G3 `spec`** — `python Tools/scripts/spec_check.py --lights Working/Appearance/build_lights`
   (manifest self-check, quoted green today) **and** the RC-side comparison it cannot do itself:
   the 24 RBMs named by `lights_manifest.json` hash-equal their `bm-RC1/aaf/` copies. Parts side:
   G5's `bm_parts.py --check --build bm-RC1` (step 3 of that script: `models resolve 59/59`).
4. **G4 `budget`** — **decide the unit first** (`MODLOG §76`, `§111`, R9): if R9 counts distinct
   referenced `.rbm` bytes, then `bm-002`'s `8,077.5 KB` already fails and the gate must say so;
   if it counts something else, that method is written into `v01_gates.py` and into the report before
   the gate is claimed green. Texture: count distinct texture payloads the RC's `.rbm`s reference,
   print `texture KB` against `7,065`, and until the method is settled print `texture: UNKNOWN` and
   exit 1 — never a silent pass.
5. **G5 `parts`** — `python Tools/scripts/jc3parts.py check` (quoted for the record, with its
   donor-side scope noted) **and** `python Tools/scripts/bm_parts.py --check --build bm-RC1`, which
   re-reads the RC's module **through the RC's `.toc`** and re-checks 59 parts, 0 moved fields, models
   59/59.
6. **G6 `adf`** — enumerate every module the receipt marks edited (`.vmodc`, `.epe`, `.onlinec`), and
   for each: `jc3adf.py info` on the `.toc`-sliced bytes + a `dump` compared with the owning card's
   spec (parts 59 for B-04; 467 objects / 47 classes for B-05; 6 edit rows for B-09). Prints
   `modules K/K re-read`.
7. **G7 `epe`** — `ConvertProperty` binary → XML → binary on the RC's `.epe` (sliced via `.toc`),
   sha256 equal, and `objects 467 / classes 47` == `Working/Entity/bm_epe_edits.json.counts`. Fails
   loudly if the file is not in a record (today: no record exists).
8. **G8 `readback`** — `v01_readback.py`: for **each** spec's `from → to` rows
   (`Working/Parts/bm_vehicle_parts.json` 59 parts / behaviour rows, `Working/Damage/bm_health.json`
   6 rows, `Working/Audio/bm_bank_manifest.json` 5 slots, `Working/Entity/bm_epe_edits.json` 19
   edits + 51 additions, `Working/Collision/batmobile.physicsc` sha256 `192c1247…`,
   `Working/Appearance/build_lights/lights_manifest.json` 24 blocks) read the value out of the built
   bytes by (path, member/field) and assert `to`. Any row that is `UNKNOWN` is printed as
   `unproven` and makes the gate **fail with a count**, not pass silently.
9. **G9 `report`** — write `report.md`/`report.json`; exit 0 only if G1…G8 are all green.

### 4.3 Ordering and re-entrancy

reads it. Adding a card later means adding a spec path to G8's table, not touching the gates.

## 6. Tamper tests the gate must catch (each must turn it red)

1. `eetoc.py patch` one record's size by ±1 → G2 `bounds`/`tree↔records` fails.
2. Delete a file the receipt lists → G1 `removed` non-empty **and** G2 record-without-file.
3. Flip a byte in the `.epe` magic → G7 `not an ADF/CPF file`.
4. Re-insert the shipped value in place of a `to` value in the RC module → G8 names the row and prints
   `still from`.
5. Add a stray `.rbm` not in the receipt → G1 unplanned path.
6. Copy `bm-002`'s bytes over the RC module → G2 sliced-bytes hash mismatch (and G8).
7. Truncate the `.ee` by 1 KB → G2 bounds failure, not a crash.
