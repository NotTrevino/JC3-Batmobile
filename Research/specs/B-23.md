# B-23 build spec — the pursuit-mode and stationary spring rates: no per-mode member

Card source: `tmp/freebuff/reports/suspension-unit-bridge.md` §7/§9 (T-S6), ledger row `T-S6`
(`next`), `T-MD5…T-MD8` (mode switch, D-2 reopened), `Research/BatmobileGrab/MODES.md`. Companion
card: `B-22.md` (droop and up-travel). Opened 2026-11-06 by
`tmp/freebuff/reports/apply-suspension-rows.md`.

**SUMMARY: THE NUMBERS EXIST, THE CARRIER DOES NOT.** BmAK ships a second spring rate for pursuit
mode (`PMWheelSuspensionStiffness` **750**) plus two more bias channels
(`PMWheelSuspensionBias` **20**, `StationaryWheelSuspensionBias` **5**). JC3's `Suspension` module
carries **one** `strength` per axle and **no** mode or speed gate: 0 rows in the 166-file fleet
vocabulary name a per-mode, alternate or stationary rate. So 750 cannot be written as a suspension
value — it has to arrive through the mode switch (B-12) or a script, and the arithmetic says it
cannot share the same travel at all.

## 1. The BmAK numbers, and why 750 does not fit the 0.40 m travel

```
k_PM/m = 750 / 210 = 3.571 s^-2          (decoded 210 kg class default)
sag    = 9.81 / (4 * 3.571) = 0.6867 m   = 172% of the 0.40 m length
implied mass  at f = 0.4542, length 0.40:  750 / 13.500 = 55.6 kg
implied length at 210 kg, f = 0.4542:      9.81/(4*0.4542*3.571) = 1.51 m
```

The fleet has **2** vehicles over 100% rest sag out of 126 (bridge report §4), so 750 on the same
car with the same 0.40 m travel is out of domain. Either pursuit mode has a different travel
(1.51 m — no JC3 vehicle at radius 0.64 m authors one) or a different carried mass (55.6 kg — not a
car), or the mode's rate is meant for a stiffer, shorter spring. That reading is UNKNOWN.

## 2. What JC3 has instead

| carrier | presence | why it is not the answer |
|---|---|---|
| `Suspension.*.strength` | 166/166, 4.0–80 s^-2 | one value, no gate; a mode would need a second instance |
| `CustomLandGlobal.drift.max_drift_torque` | fleet-wide | yaw torque, not a spring rate |
| mode switch (D-2 / B-12) | **reopened 2026-11-06**, card live and unbuilt | the only route that swaps a whole handling set — `t11_variants.json` still declares 1 variant |
| script | `CGraphScriptGameObject`, 13 objects | 0 of 4,832 exit nodes write a suspension member |

Stationary bias 5 and PM bias 20 land on the same wall as the rear bias 50 in T-S6: JC3's only bias
channel is `hardpoint_offset_along_spring`, a fraction of the spring length, authored in
-0.375 … 0.500 (rear bias 50 already needs -0.50, outside the range).

## 3. Steps

1. **Do not write 750 into `strength`.** It is the value that most easily produces a car sitting on
   its bump stops; the bridge's 13.500 is the mode-neutral pick.
2. If the two-mode car ships (B-12), the pursuit variant is the place for 750 — as a **variant
   table** row, with a 1.51 m travel or a declared out-of-domain switch, not as a second member.
3. If B-12 stays unbuilt, carry 750 / 20 / 5 as named omissions on `T-S6` with these numbers and the
   172% sag as the reason, and let `T-MD5…T-MD8` hold the mode question.
4. Whatever route is taken, the mode's stationary bias 5 has no member at any speed gate: it is an
   omission unless a script sets `hardpoint_offset_along_spring` on a stop condition.

## 4. Done (gate BZ-2)

- `T-S6` names 750 / 20 / 5 as omissions with the 172% sag arithmetic, **or** B-12's variant table
  carries a pursuit row and the take shows the car sitting at the authored ride height in both modes.
- No suspension member in the build carries a value derived from 750 while `length` is 0.40 m.

## 5. Stop

If B-12 stays unbuilt and no script writes the suspension, record all three numbers as omissions with
the arithmetic above; the card is then `done` as a documented absence, not `todo`.
