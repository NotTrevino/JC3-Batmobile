### Step 0 — measure before copying (per chosen weapon)

For each of the 4 usable rows, read the donor vehicle's `.epe` and list the `jc_weapons/…` strings its
component names (the APC: 5, `w618`: 4). Decide per string:

* **edited** → copy it into the private directory (tune for `T-WP1`/`T-WP2`),
* **unchanged shared file** (e.g. `w143_rpg_fire_leach_projectile_body.model_xml`, the shared
  autoaim preset) → keep the shared path: R7 says do not edit it, and nothing here edits it.

The manifest records which of the two each path is, so "why is this file not private" is answered.

### Step 1 — private paths and renames

Private directory per weapon: `editor/entities/jc_weapons/06_vehicle/w6xx_batmobile_<name>/`, e.g.
`w602_batmobile_cannon/`. Rename rules, all `hash_jenkins`-witnessed:

* the leaf/instance name (`w602_mediumtank_canon.wtune` → `w602_batmobile_cannon.wtune`), the
  directory token, the `@files.xml` entry;
* the `.epe` component's `name` / `name_hash` if T-11 changes it, and its path strings
  (`id:9E74F03F`, `id:AA7096C9`-style members are **copied slots**, their meaning by position is
  still partially UNKNOWN — B-05's spec records that the component's ~60 unnamed members are copied,
  never authored);
* nothing inside a **shared** file may be renamed or moved (R7).

### Step 2 — apply `t7_weapons_edits.json` (3 numbers, 2 tunes)

For each edit: locate the row by its decoded path in the copied `.wtunec` via `jc3adf.py`
(`bullet_weapon[0].tuning.bullet_base_tuning…`, `fire_rate`, `velocity`), assert the current value
equals T-11's `old` exactly (`1.75`, `500.0`, `0.10000000149011612`), write the 4-byte float at its
absolute field offset, and assert the file size is unchanged. The two `conf` classes are carried
through: `decoded` for both `fire_rate`s, `derived` for the `velocity` (R4's vocabulary).

### Step 3 — pack and register

New files are added to `@files.xml`, the `.ee`/`.toc` re-packed (`eetoc patch`), and the build's
`.epe` re-emitted through `ConvertProperty --i` (B-05's round-trip gate) so no byte is hand-written.
`aafdiff` vs the B-05 build must list exactly the `.epe`, `@files.xml`, the new weapon files and the
`.ee`/`.toc`.

### Step 4 — repoint

The `.epe` string edits are **B-05's edit spec**, not a second writer: `bm_epe_edits.json` gets the
private paths, and `bm_entity.py --check` proves every path it names resolves. B-06 re-runs that
check in the B-06 tree. This keeps one writer per file (B-05 owns the `.epe`).

## Tamper tests the card's `--check` must pass

1. Change one byte of a written `fire_rate` float → Done 2 fails with read 1.99 vs expected 2.0.
2. Delete a private `.wtunec` → Done 1 fails on that dangling path.
3. Rename a private leaf but leave `@files.xml` alone → Done 1 fails (path not in the index).
4. Edit a **shared** `w618_sportsmuscle_missile.wtune` instead of the copy → the R7 assertion fails
   (the manifest pins every shared source file's sha256, the `bm_audio.py` pattern).
5. Restore `old` in a tune (write 1.75 back) → Done 2 fails against `new`.

Each is applied to `Builds/bm-006` only, captured, then reverted from a `sha256sum` manifest taken
first.
