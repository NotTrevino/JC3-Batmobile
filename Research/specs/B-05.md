### Step 0 — stage

   (6 `CPartProp` + which parts) before any edit. A different base count stops the run.

### Step 1 — `CPartProp`

Per **L-3**: no prop is added unless a row below names a part. Implement the loop anyway (the spec
supports `additions[]` of class `CPartProp`), with the members `_GUID` = `name_hash` =
`hash_jenkins(name)` (`rbmhdr.hash_jenkins`, verified 5/5 on shipped props by B-05's census),
`part_index` from `bm_vehicle_parts.json`, and `id:D04059E6` = `-1042795718` (the class hash the 6
shipped props all carry). Deliverable of the step that *is* buildable: the assertion that all
`parts_added` names in `bm_vehicle_parts.json` are present in the built module (Done criterion 2's
"every … part name resolves").

### Step 2 — weapon components and `SWeaponPoint`s (4 rows: `T-WP1`…`T-WP4`)

For each of the 4 rows:

1. **Clone** the donor `CBulletWeaponBase` node (`apc_debug.xml`) as a new object under the root,
   copying all ~60 unnamed `id:*` members verbatim; set only the named ones from T-11:
   `name` (`w602_…_cannon` etc.), `name_hash` = `hash_jenkins(name)`, `weapon_id`, `weapon_type`,
   `world` (translation from §6's `jc3_transform` chain, rotation = identity — measured, L-UNKNOWN).
2. Add its `SWeaponPoint` children, **one per point in the T-11 structural row**:
   `name` + `name_hash` = `hash_jenkins(name)`, `type` (2 fire / 4 attach / 1 hand-mount, copied
   from the donor's own roles), `fire_effect` 0 (donor value), `world` =
   `position_m` / `forward_jc3` / `up_jc3` from `SOCKETS_JC3.json` converted to the measured mat
   layout (rows 0–2 = X/Y/Z axes, row 3 = origin, det +1 asserted).
3. **Parent to the turret/cannon part** through the donor's measured mechanism:
   `id:80201E4D` = `batmobile_turret`, `id:5C19E7E0` = `batmobile_cannon` (or
   `batmobile_machine_gun` for `T-WP2`), `id:A90F5E74` = `weapon_anchor`.
4. Root pointers: `main_weapon` (`id:851CAABE`) → the cannon component; `id:00568A74` → the Vulcan
   component (the medium tank's second driver slot, G2-11 §2d). T-11's structural row is the source.
5. `T-WP4` also clones the shipped `CForcePulse` object (1 in the base) with G2-16's pulse values.
   `T-WP5` is **not written** (L-1).

The weapon *entity paths* the components name are B-06's private copies; B-05 writes the path
string T-11 records and the resolution check stops at the `.epe` (see Done 2). V-03 later owns the
"file exists" half.

### Step 3 — `SVehicleLight` (22 shipped + 6 clones)

* `Front_Secondary_Head` and `Rear_Break` are the graph's unreferenced objects (T-18's own census);

## Tamper tests the card's `--check` must pass

1. Change one `SWeaponPoint.name` in the built `.epe` → Done 2 fails on the name.
2. Remove one `SVehicleLight` object → Done 3 fails on the count **and** Done 2 on the light.
3. Flip one byte of a `world` mat → the spec-vs-built comparison fails (values are re-derived).
4. Delete the `bat_base.ctune` string → step 6 assertion fails.
5. Point a `id:80201E4D` at a part that is not in the module → Done 2 fails on the part name.

Each test edits the build, captures the failing output and is reverted from a `sha256sum` manifest
taken first (the B-09/B-11 pattern).
