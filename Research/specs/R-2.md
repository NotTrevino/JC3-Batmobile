### 4.3 `kb_facts.py --check` (what it proves)

Fails, naming the file and number, if:

1. any count in `Working/KB/note_facts.json` differs from its re-derivation;
2. `T_ROWS.jsonl` row total/dispositions differ from the JSON (198 / 60 / 16 / 40 / 26 / 13 / 36 / 7 today);
3. `FEATURE_CENSUS.json` counters (`entities`, `armed`, `weapon_ids`) differ;
4. `Builds/bm-001/receipt.json` `toc.records` / `toc.ee_entries` differ;
5. the note's `<!-- kb-facts -->` … `<!-- /kb-facts -->` block differs byte-for-byte from the JSON rendering;
6. a quoted number in that block has no entry in the JSON (no orphan numbers).

It writes nothing except with `--write`, and never touches the note.

### 4.4 Steps

1. Gate (§4.1). Record a `MODLOG.md` intent entry naming the note path and the facts script.
2. Write `kb_facts.py`; run `--write`; run `--check`.
3. Edit the KB note: numbers from the fenced block; add `## Versions` with the user-confirmed values
   (or `UNKNOWN` + the exact missing evidence), `## The four corrections`, keep/adjust `## Gotchas`;
   update the `date` and `status` front matter only as the facts allow.
4. Run the Done checks (§5). Paste outputs into `MODLOG.md`; write the card report.
5. Ask the user for approval (one message: the note path, its diff summary, the `um kb check` output,
   the version/agent evidence request). **Stop.**
6. Only on a clear yes: `um kb pr knowledge/games/just-cause-3/translating-the-batmobile-row-ledger.md --yes`,
   record the printed URL in `MODLOG.md`, flip §12.

### 4.5 Revert

Delete `Working/KB/`, `Tools/scripts/kb_facts.py`, the MODLOG entry/section, the report; `git checkout`
the KB note in the `universal-modder` clone (before any PR). After a PR, closing it is a user action.
