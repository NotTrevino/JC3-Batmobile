### 4.2 `v05_predictions.py` — how it derives the sheet

1. **Enumerate the checks from §9b**, not from a typed list: parse `GRAB_BACKLOG.md` between
   `#### Q-1` and the `**Gate QX:**` line, take the numbered items of Q-1/Q-3 and the `A1 … A16`
   take lines of Q-2 → ids `Q1-1…Q1-8`, `Q2-A1…A16` (only the takes the text lists), `Q3-1…Q3-7`,
   plus the conditional `Q2-battle` marked `skipped: D-2 / B-12`. Abort if the count is not 27 + 1.
2. **Give every row a value and a band, or mark it blocked with the card's own reason.** Sources, by
   family:
   - T ledger rows (`Working/Translation/T_ROWS.jsonl`) — `cells[3]` for the value, `cells[-1]` for
     the verify text;
   - measured baseline (`QA1_RESULTS.md`, `QA1/qa1_measure.json`) for A1/A5/A8 and for the ±5 %
     repeatability band;
   - `damage_predict.py` imported (`table`/`predict` functions — never re-implemented) for Q-1.6,
     Q-3.2, Q-3.3;
   - `CAM_TUNE.json` for A15 (7.0 m back, 1.3 m up, FOV 55–63, look-at 1.55);
   - `t8_parts.json` for Q-1.4 (turret ±179°, cannon −5…+20°, Vulcan 6 turns / 3.90 s, flaps 20/30°);
   - `t9_interaction.json` + `COCKPIT.json` for Q-1.3 (0.05–0.30 m placement, hip 0.8647 m);
   - `bm_lightrig.json` for Q-1.7 (**18 entries, 7 parts**);
   - `t19_hud.json` for A16 (2 slots, cooldown 0…1, heat = stated absence both sides);
   - `t12_audio_map.json` for Q-1.8; `t17_fx.json` for Q-3.7; `t11_variants.json` for the mode rows.
3. **Derive the arithmetic bands openly** with the formula printed in the sheet, e.g.
   braking 100→0: `d = v²/(2a)` with `v = 27.7778 m/s`, `a ∈ [3.5, 3.8] m/s²` from QA-1 →
   `101.5 … 110.2 m`; boost delta `min(3500, 600 × 2.0) = 1200 cu = 43.2 km/h` (T-B2).
4. **Refuse to fake an UNKNOWN**: a blocked row carries `status: "blocked: <blocker id>"`, the exact
   file:line that proves the value is absent, and **no band**. The script prints
   `N/27 predicted, M blocked` and exits 1 while any row is blocked — that is what makes the Done
   line honest (the card's own rule: "nothing in Q is judged without one").
5. **`--check`**: re-parse §9b, re-derive every row, assert
   (a) 27 + 1 checks parsed and one row each,
   (b) every `ready` row has a non-empty band **and** a source that exists on disk and names a row
   that exists (ledger id, JSON key or doc line),
   (c) every `blocked` row names an existing file and a line that contains the quoted token,
   (d) `PREDICTIONS.md` and `predictions.json` are byte-identical to the re-derived bytes,
   (e) no Q id in §9b is missing from the sheet.
   It prints `PASS: 27 Q checks parsed, X predicted, Y blocked, 0 without a prediction` and exits 0
   only when `Y == 0`.

### 4.4 Tamper tests (must be caught, then reverted)

1. Delete one row from `Working/Q/predictions.json` → `--check` fails on "Q id missing".
2. Change a band's lower bound (e.g. braking 101.5 → 90.0) → fails the byte comparison **and** the
   band-vs-formula assertion.
3. Point a blocked row's `source` at a line that does not contain the quoted token → fails (c).
4. Turn a blocked row into `ready` with an empty band → fails (b).
