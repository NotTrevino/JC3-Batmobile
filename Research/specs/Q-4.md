## 1. What the card asks (verbatim, `GRAB_BACKLOG.md:1217-1223`)

- Each failure → find the row → change **one** value with a provenance class → stage offline → run
  the V gates for that build → batch into the next planned session. Never tune by feel; if no row
  explains the failure, the failure is a new G/T task, not a tweak.
- A Q check that cannot be executed (e.g. pursuit not triggering) is recorded as an attempt; the
  row stays open; the pass band is never lowered.
- Maximum one extra session per original session before the user decides how to proceed.

Five words in that text are load-bearing and each becomes a check in §6: **the row**, **one value**,
**a provenance class** (`R4`, `:66`), **the V gates**, **the next planned session**. "Cannot be
executed" and "one extra session" are the other two.

## 3. Blockers

  produce its first fix record until a session writes `FAILURES.md`. *Nothing in the plan below

  validates it against R4's enum plus a citation that resolves to a row/cell — it cannot read it
  from the ledger.
- **BL-4 — no per-build V gate runner.** `v01_gates.py` absent; `bm_parts`/`bm_health`/`bm_audio`

## 4. Design the plan fixes

### 4.1 The fix record (one JSONL row per failure → change)

    {"schema": 1, "fix": "Q4-001", "session": "Q1", "target_session": "Q2",
     "check": "Q1-item6-ARM-2", "row": "T-DM1",
     "row_dispo_at_fix": "next",
     "value": {"module": "editor/…/batmobile_health_medium.vmodc", "member": "max_health",
               "from": 36000, "to": 18000},
     "class": "derived", "class_source": "Working/Translation/T10_DAMAGE.md#T-DM1",
     "band": {"sha256": "…", "text": "≥24 hits"},
     "build": {"tag": "bm-Q4-001", "base": "test-091", "receipt": "…"},
     "readback": {"base": 36000, "fix": 18000, "by": "jc3adf dump --paths …"},
     "gates": [{"cmd": "python Tools/scripts/bm_build.py --tag bm-Q4-001 --check",
                "exit": 0, "verdict": "PASS: …"}],
     "blocked": null}

Rules the record encodes: exactly one `value` object (one module, one member, one from→to);
`class` ∈ `{decoded, decoded (fleet), derived, class, epe, read}` and never `assumed` (R4);
`row` must exist in `T_ROWS.jsonl`; `target_session` ≠ `session` (a fix is batched, never re-run
in the session that found it, `Q-1.md:226`); `readback` must be from bytes, not from the edit spec.

### 4.2 What "one value" is proved against

`from` must be the value decoded out of the **fix build's base** and `to` the value decoded out of
the **fix build**, both by `jc3adf.py` on the named module inside the packed `.ee`; plus
`aafdiff.py <base>/aaf <fix>/aaf --hash` must report **exactly one changed inner file**, and that
file must be the module the record names. A record with 0 or 2 changed files is not one value.

### 4.3 The gate set (what exists today) and the path trap

| gate | command | proves |
|---|---|---|
| receipt readback | `python Tools/scripts/bm_build.py --tag <fix> --check` | the tree still matches its own receipt |
| single change | `python Tools/scripts/aafdiff.py Builds/<base>/aaf Builds/<fix>/aaf --hash` | 1 changed inner file |
| damage values | `python Tools/scripts/damage_audit.py --build Builds/<fix>/aaf` | every damage member inside the shipped range or declared |
| ledger | `python Tools/scripts/t_rows.py check` | 198 rows, dispositions intact |
| counts | `python Tools/scripts/status_audit.py --check` | R11 |
| physics (if the module set includes `.physicsc`) | `python Tools/scripts/jc3hkx.py check --all --file <path> --against <src>` | collision shape unchanged/declared |
| card gates | `bm_parts.py --check`, `bm_health.py --check`, `bm_audio.py --check` | **cannot** answer for another tag — recorded `blocked: V-01` |

**Path trap (measured).** `damage_audit.py` decodes "a folder containing `editor/`". Given
`--build bm-009` it printed `FAIL max_health: declared in damage_switches.json but absent from the
build` ×6 with `6 problem(s)`, exit 1; given `--build Builds/bm-009/aaf` the same build is
`29 members, 6 outside the shipped range, 6 declared switches` / `check ok`, exit 0. A loop that
recorded the first invocation would "fix" a failure that does not exist. Hence: **every gate's exact
`cmd` string is stored in the record and re-run verbatim by `--check`**, and the build path
convention `Builds/<tag>/aaf` is asserted once by the tool, not typed per fix.

## 5. Plan

### Step 0 — preconditions (asserted by the tool, quoted in its first run)

    ls Working/Q                                   # BL-1: absence is allowed, silence is not
    test -f Working/Q/PREDICTIONS.md               # BL-2: absence => every fix needs band.sha256 = null
    python Tools/scripts/t_rows.py check           # BL-3 basis: rows exist
    test -f Tools/scripts/v01_gates.py             # BL-4: absence => card gates recorded blocked
    python Tools/scripts/bm_build.py --help | grep -- --tag

### Step 1 — `Tools/scripts/q4_loop.py` (new, `--write` / `--check` / `--gates` / `--attempt` / `--session`)

- `--write` derives `Working/Q/LOOP.md` from the Q-4 card text itself (the three bullets are parsed
  from `GRAB_BACKLOG.md:1217-1223`, never retyped) plus the R4/R13/R14 lines from `:66,:75,:76`, so
  a reworded card moves the rule sheet.
- `--gates <tag>` runs the §4.3 gate list for that build in order, records
  `{cmd, exit, verdict}` per gate, and writes them into the fix record named by `--fix`.
- `--attempt` appends one row per unexecutable Q check (`Working/Q/ATTEMPTS.md`): check id, why it
  could not run, the row it stays on, the band sha256.
- `--session` maintains `Working/Q/SESSIONS.json`: `{session, base_session, extra_count, decided}`
  for the "maximum one extra session" rule.
- `--check` re-derives every invariant in §6 and prints one `PASS:`/`FAIL:` line in the `g2x_gate`
  style; exit 0 only if all invariants hold. It writes nothing except `--write`.

**Out:** `Working/Q/FIXES.jsonl`, `Working/Q/ATTEMPTS.md`, `Working/Q/LOOP.md`,
`Working/Q/SESSIONS.json`, `Working/Q/BATCHES.md`.

### Step 2 — `Working/Q/LOOP.md` (generated)

The card's rules + the record schema + the gate table + one worked example **that is labelled
`example only`** (no values invented: it reuses `T-DM1`'s `from 2000 → to 36000` as read from
`Working/Damage/bm_health.json`, and says so).

### Step 3 — ingest the first failure (runs when BL-1 lifts)

    python Tools/scripts/q4_loop.py --ingest Working/Q/Q1/FAILURES.md --session Q1 --write
    python Tools/scripts/q4_loop.py --check

Ingest refuses a failure row that has no check id, no band, or no T row: that failure is a **new
G/T task** (card bullet 1, last clause), and the tool says so instead of opening a fix.

### Step 4 — stage and gate the fix offline

    python Tools/scripts/bm_build.py --tag bm-Q4-001 --base test-091 --edits Working/Q/fix_Q4-001.json
    python Tools/scripts/q4_loop.py --gates bm-Q4-001 --fix Q4-001
    python Tools/scripts/q4_loop.py --check

No install, no launch: the build lands in `Builds/` only (R6), and `install.ps1` is generated but
not run. Any gate that cannot run for this tag is written `blocked: V-01` and **`--check` fails the
fix** until it is either gated or explicitly parked as an attempt.

### Step 5 — batch into the next session

    python Tools/scripts/q4_loop.py --batch Q2 --write     # writes Working/Q/BATCHES.md from target_session
    python Tools/scripts/q4_loop.py --check

`BATCHES.md` is derived from the records (`target_session`), so it cannot list a fix that has no
record and cannot omit one.

### Step 6 — journal, ledger, §12

MODLOG `§"Q-4 — fix loop"` with the `PASS:` line and every gate command/output (R14); `§12` row
`Q-4 | ongoing | Tools/scripts/q4_loop.py --check …` (Q-4 never becomes `done` — it is `ongoing`,
so the row states the loop's live state, and `t23_closeout`/`status_audit --check` must stay green).

## 7. Tamper tests (each must be caught, then restored)

| tamper | expected |
|---|---|
| add a second `value` object to a fix | `FAIL Q4-00n: 2 values, one per fix` exit 1 |
| set `class: assumed` | `FAIL Q4-00n: class 'assumed' is not buildable (R4)` exit 1 |
| set `row: T-DM9` (no such row) | `FAIL Q4-00n: row not in T_ROWS.jsonl` exit 1 |
| delete one gate from `gates[]` | `FAIL Q4-00n: no gate block` exit 1 |
| flip one hex digit in a gate's recorded verdict | `FAIL Q4-00n: gate verdict does not re-run green` exit 1 |
| change `target_session` to `session` | `FAIL Q4-00n: batched into its own session` exit 1 |
| edit the pinned band sha256 | `FAIL Q4-00n: band changed without user_decision` exit 1 |
| set `extra_count: 2` with `decided: null` | `FAIL sessions: 2 extra sessions, no user decision` exit 1 |
| hand-edit `Working/Q/LOOP.md` or `BATCHES.md` | `FAIL: … differs from the re-derived text` exit 1 |
