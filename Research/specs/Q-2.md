### 4.2 `q2_session.py` — the four modes

1. **`--plan`** parses §9b (Q-2 takes) and `T_PLAN.md` §5.A (rows + pass text), joins each take to a
   `predictions.json` row, and writes the take sheet. It **refuses** to emit a band for a take whose
   prediction row is `blocked`, writing `band: null, status: "blocked: V-05/…"` instead — that is how
   A2/A3/A4/A7 stay honest.
2. **`--preflight`** (run at the session, never offline) checks, in this order and fails loudly:
   game closed (`um win ps` shows no JC3 process), `um backup` receipt for the save folder, RC
   installed (`install.ps1 -Action Verify` green), `MODLOG.md` carries `VX-APPROVAL:` whose approved
   `.ee`/`.toc` sha256 equal `Builds/bm-RC1/receipt.json`, windowed fixed size, one screenshot test
   (`um win shot`). It never launches the game; the user starts it, then the session uses the exact
   PID for `um win kill`.
3. **`--measure <take>`** runs `qa1_hud.py crops|build|trace|measure|runs` on the take and stores the
   numbers plus the band comparison; a take whose measurement falls outside the band is written
   `FAIL`, never re-read until it passes (§9b: "a check passes or fails against its band — it is never
   re-interpreted").
4. **`--check`** proves the Done line:
   - every take §9b lists has a `RESULTS.md` row with `measured`, `band`, `pass|fail`, `recording`
     and `timestamp`; a take whose prediction is `blocked` must say so instead of inventing a band;
   - each recording exists, its duration covers the take window, and each measured number in
     `take-<Axx>.json` equals the value in `RESULTS.md`;
   - the five queued ledger rows no longer read `next` (before/after printed), and
     `t_rows.py check` + `status_audit.py --check` exit 0;
   - prints `PASS: 12/12 takes recorded (1 excluded: battle/D-2), 12 compared to V-05, 5 next-rows
     resolved` and exits 0.

### 4.4 Tamper tests (must be caught, then reverted)

1. Delete a `take-Axx.mkv` a `RESULTS.md` row names → `--check` fails ("recording missing").
2. Mark a take `pass` with an empty `band` → fails the band requirement.
3. Leave T-B2 at `next` → fails "5 next-rows resolved".
4. Write a measured value that contradicts `take-<Axx>.json` → fails the equality check.
5. Set a take's `pass` while its measured value is outside the band → fails the band comparison.
