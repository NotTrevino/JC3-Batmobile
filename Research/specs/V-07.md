### 4.2 `v07_gate.py` — what `--write` and `--check` do

`--write` (only when 4.3's preconditions hold, otherwise it refuses and prints the blockers):

1. **Read the six results** from their artefacts, not from prose:
   `Builds/bm-RC1/receipt.json` + `verify/` (V-01), `Working/Q/geometry.json` (V-02),
   `Working/Q/wiring.json` (V-03), `Working/Q/audio_gate.json` (V-04),
   `Working/Q/PREDICTIONS.md` + `predictions.json` (V-05), `Working/Q/V06_DRYRUN.json` (V-06).
   Each row records path, sha256, the tool that produced it and its verdict line.
2. **Session plan**: parse §9b → 3 sessions (Q-1/Q-2/Q-3) and their check counts; compute the
   recording estimate as `takes × 222.13 s` (QA-1's measured take) rounded up, print the formula in
   the file and label it `estimate (plan)`, not a game value.
3. **Regenerate `STATUS.md`**: run `status_audit.py --write`, then `--check`, and record both
   outputs.
4. **Write** `Working/Q/VX.md`, `Working/Q/SESSION_PLAN.md` and the `### VX` MODLOG section ending
   with the approval request (`VX-REQUEST: install <RC sha256> + start Q-1, 3 sessions, ~N min each`)
   — *asking* is the card's Do; *recorded approval* is its Done.
5. Never writes an approval line. That line is only ever added verbatim from the user's answer.

`--check` (the gate):

- parse `GRAB_BACKLOG.md` §12 and require `V-01 … V-06` all `done` (a `blocked:` row fails);
- require the six artefacts to exist, hash-match `Working/Q/VX.md`, and each verdict to be a
  `green` reading — not an empty string;
- run `status_audit.py --check` as a subprocess and require exit 0;
- require `MODLOG.md` to hold a `### VX` section that names **all six** artefacts and the session
  plan, and a `VX-APPROVAL:` line with a date, the scope (`install` + `Q-1`) and the approved
  `.ee`/`.toc` sha256 that match `Builds/bm-RC1/receipt.json`;
- require `Working/Q/PREDICTIONS.md`'s own check to pass (`v05_predictions.py --check`, exit 0), i.e.
  27/27 predicted — V-05's Done is a precondition of this gate;
- print `PASS: VX gate — 6/6 V results green, STATUS.md current, 3 sessions planned (N min estimate),
  approval recorded <date> <scope>` and exit 0; on any failure print
  `FAIL: <n> gate item(s)` and exit 1.

### 5a. Tamper tests (must be caught, then reverted)

1. Add a `VX-APPROVAL:` line without a date/scope → `--check` fails on the approval format.
2. Point the approval at a `.ee` sha256 that is not `Builds/bm-RC1/receipt.json`'s → fails the hash
   match.
3. Flip one V row in `Working/Q/VX.md` to `green` while that artefact is absent → fails the
   existence/hash assertion.
4. Edit `PREDICTIONS.md` so one Q check loses its band → `v05_predictions.py --check` fails first, so
   the VX gate refuses to pass.

### 5b. What is expected while the project is where it is today

`v07_gate.py --check` must print something like

FAIL: 6 gate item(s)

and exit 1. That is the honest V-07 status, recorded as `blocked: V-01…V-06` in §12 — **not**
`done`, and no approval line is invented.
