## 3. Blockers

- **V-02/1 — no subject (inherited).** `Builds/bm-RC1/` missing; BX not done (`GRAB_BACKLOG.md:1341`
  `| B-06 … B-14 | todo | |`, line 1338 B-05 `blocked`). Parts 1 and 4 of the card are defined on the
  *RC* tree; today they can only run against `bm-002`/`bm-009`.
- **V-02/2 — no assembled-car renderer.** `preview_rbm.py` takes one file; `silhouette_check.py`
  assembles 12 LOD1 meshes but only into a fixed side-view silhouette raster, with no albedo, no pose
  and no PNG output. Nothing in `Tools/scripts` writes side/front/top PNGs of an assembled car.
- **V-02/3 — turret ±yaw and cannon pitch have no limit for this build.** Our `.physicsc` is the
  B-10 hull set (`bm_collision.json` has no constraint data at all: 0 `hinge`, 0 `constraint`,
  0 `Turret`), while the only documented limits belong to the mediumtank donor
  (`Research/JC3Grab/TURRET.md:9-12`). Using them for our turret would be a guess (R4).
- **V-02/4 — canopy open, hatches open: no such parts.** The 19-part set lists no `canopy`, no
  `hatch` (quoted in the summary). Recorded as N/A with the part list as evidence, not as a pass.
- **V-02/5 — aero-flap deployed angle UNKNOWN.** `hinged_parts.rows = [56,57,58,59]` carry part
  indices only; the module has no angle fields (`GRAB_BACKLOG.md` B-04 Done names only "behaviour
  entries", and `bm_parts.py` checks `part_index` only).
- **V-02/6 — the 30 cm surface rule has no surface.** `bm_collision.json` stores `vertices: 36`
  (count) and a box, not coordinates; the decoder can emit them (`bm_collision.py:136`) but nothing
  writes them out. Distance-to-hull therefore cannot be computed from what is on disk.
- **V-02/7 — `t9_interaction.json` contradicts itself on the seat socket.** Object
  `interaction.seat.driver` carries `measure {"inside": false, "nearest_m": 0.0279}` **and**
  `verdict: "inside by design (the seat is in the cockpit)"`. The card's rule ("every point outside
  the hull ≥ 5 cm") would fail the driver seat on its own measurement while the research says it is
  inside by design. The gate needs T-9's per-role verdicts as explicit exemptions — decided in the
  plan, not silently.
- **V-02/8 — the built interaction set is 15 of 77.** `Working/Entity/bm_epe_edits.json`
  `counts.interactions_written 15`, `skipped 69` of which 60 are `UNKNOWN` ("no named `world` member
  … member hash only"). Reading points from the built `.epe` therefore proves 15 points, not the 77
  T-9 places; and `bm-005` has no `.toc` record, so "as the engine reads it" is unavailable.
- **V-02/9 — albedo coverage is body-only.** `--albedo` needs one `.ddsc` per diffuse slot; the
  directory holds 28 files (body, wheels, decals). Whether the 16 part RBMs and 8 lamp RBMs resolve
  every diffuse against it is unmeasured — the gate must report unresolved slots, not tint them grey.

## 4. Plan

### 4.1 Files to create

| file | role |
|---|---|
| `Tools/scripts/v02_assemble.py` | assembles body LODn + 16 part RBMs + 8 lamp RBMs into one triangle soup at `parent_space_offset` pivots (reusing `rbm_geom.decode` and `preview_rbm.render`, no fork), applies per-part pose rotations about their pivots, writes the PNG set |
| `Tools/scripts/v02_geometry.py` | the four measurements (envelope, intersections, silhouette, interaction distances) and `verify/v02/geometry.json`; `--check` re-runs everything and exits non-zero on any miss |
| `Working/Collision/hulls.json` | hull vertices + planes exported from the private `.physicsc` — produced by a **new `--dump-hulls PATH` flag on `Tools/scripts/bm_collision.py`** (default behaviour unchanged), because the decoder already has the data (`bm_collision.py:136`) |
| `Builds/bm-RC1/verify/v02/` | `{lod1…lod5}_{side,front,top}.png` (15), `pose_*.png`, `geometry.json`, `geometry.md` |

### 4.2 Steps

0. **Preconditions.** `v02_geometry.py --check` requires: `Builds/bm-RC1/receipt.json`; the parts spec;
   `Working/Collision/hulls.json`; and it **counts** `hkpLimitedHingeConstraintData` in
   `Builds/bm-RC1/aaf/…sportsmuscle.physicsc` (`jc3hkx.py`), printing
   `hinges Turret=n Cannon=n`. If both are 0, pose limits are `UNKNOWN` and G2 runs with donor values
   **labelled as donor** (`TURRET.md` citation in `geometry.json`), or G2 fails if a limit is required
   for a pass. Today the run stops here: `BLOCKED: Builds/bm-RC1 missing`.
1. **G1 renders, LOD1…5, three views.** `python Tools/scripts/v02_assemble.py --build Builds/bm-RC1
   --views side,front,top --albedo Working/Appearance/build/ddsc --out Builds/bm-RC1/verify/v02`.
   Pass = 15 PNGs, each ≥ 1 px wide/tall, non-empty silhouette, the car bbox centred in its frame;
   per-LOD triangle counts printed (`body 40,248` at LOD1 on `bm-002` per `silhouette_check`); every
   diffuse slot resolved or listed as `unresolved` (V-02/9).
2. **G2 poses + envelope + intersections.** `--poses`: turret `+yaw`, turret `−yaw`, cannon `+pitch`,
   cannon `−pitch`, aero flaps deployed (angle `UNKNOWN` ⇒ rendered at the limit named in
   `geometry.json`, or `N/A`), gun spin (visual), canopy/hatch = `N/A` (no part, V-02/4). For every
   pose: all vertices inside `envelope.placed` ± 2 cm; no triangle of the moved part intersects any
   part at rest (per-part AABB from `rbm_geom` first, triangle test on candidates only). Prints
   `pose turret+yaw: 12,345 verts, max outside 0.7 cm, intersections 0`.
3. **G3 silhouette.** `python Tools/scripts/silhouette_check.py --manifest Working/Appearance/build_parts/parts_manifest.json`
   — must print `coverage ≥ 0.999`; today `0.9997` (quoted), so the gate is green on `bm-002`.
4. **G4 interaction points.** Read `Working/Translation/t9_interaction.json` (77 placed) and, when a
   packed `.epe` exists, the values in the built module (G4b: 15 rows); for each point compute the
   distance to the hull surface from `hulls.json`; pass if `outside` and `5 cm ≤ d ≤ 30 cm`; the
   `inside by design` roles (`seat.driver`, `seat.passenger1`, `seat.stunt`) are printed as exempt
   with T-9's `verdict` text and never counted as passes. Prints
   `points 77: 73 pass, 3 exempt, 1 unknown`.
5. **G5 report.** `geometry.json` (machine-readable) + `geometry.md` (one section per gate, with the
   command and its output). Exit 0 only if G1…G4 are green.
6. **Attach renders.** append the PNG list and the `geometry.md` summary to `MODLOG.md` under the card
   heading (the card's Done asks for exactly this; nothing else is appended).

### 4.3 Ordering

G1 → G2 (poses reuse the assembly), G3 independently, G4 needs `hulls.json` (step 0's `--dump-hulls`)
and is independent of G1/G2. A missing RC stops the run before any render, so no PNG can be mistaken
for an RC proof.

## 6. Tamper tests the `--check` must catch

1. Shift one part 3 cm along its pivot → G2 `max outside 3.0 cm` fails.
2. Scale the turret by 1.05 → G2 envelope failure naming the part.
3. Rotate a flap 40° past its own limit → G2 fails on the limit assertion (or on the envelope).
4. Delete one lamp RBM → G1 assembly count `23/24` fails.
5. Widen `envelope.placed` by 5 cm in the copied json → G2 must read the json it was given but G3/G1
   must not change (proves the gates are independent).
6. Move one interaction point to 40 cm from the hull → G4 names the object and the distance.
7. Feed `silhouette_check` `bm-001`'s decimated body → `coverage < 0.999` fails G3.
