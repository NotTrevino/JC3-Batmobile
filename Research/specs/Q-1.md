### Step 1 — checklist generator: `Tools/scripts/q1_checklist.py` (new, `--write`/`--check`)

Derive the session checklist from the card and V-05, never by hand (R11):

```
python Tools/scripts/q1_checklist.py --write      # writes Working/Q/Q1/CHECKLIST.md + q1_checks.json
python Tools/scripts/q1_checklist.py --check
```

- Parse `GRAB_BACKLOG.md` between `#### Q-1` and `#### Q-2`; one row per numbered item (8 items) and
  one row per named check inside an item (the prose is split on its sentences/commas, so the count
  comes from the card, never typed), each carrying: `check_id` (e.g.
  `Q1-1.1`), item, feature code(s), the V-05 prediction reference and band, instrument
  (`shot`/`record`/`manual`/`hud`), the pass condition text, and a recording name.
- Require **every** row to have a V-05 prediction or an explicit `out of scope — <T row> blocked`
  band. A row with neither fails `--check` (this is V-05's Done carried into Q-1).
- Cross-check the feature codes against `T_ROWS.jsonl`: a code whose rows are all `out`/`blocked`
  must be marked `named omission`, not given a pass condition (catches `T-WLD4`, `T-WP13`, …).
- `--check` re-derives and compares byte-for-byte; it never writes.

**Out:** `Working/Q/Q1/CHECKLIST.md`, `Working/Q/Q1/q1_checks.json`.

### Step 2 — results schema + checker: `Tools/scripts/q1_results.py` (new, `--write`/`--check`)

```
python Tools/scripts/q1_results.py --init        # creates Working/Q/RESULTS.md with one row per check
python Tools/scripts/q1_results.py --check       # the Done line
```

- Row shape: `check_id | measured | band | pass/fail | recording | timestamp | note`.
- `--check` fails when: a checklist id is missing or duplicated; `measured`/`band`/`verdict` is
  blank; `verdict` is not `pass`/`fail`/`named omission`; a `recording` path does not exist under
  `Working/Q/Q1/` or is 0 bytes; a `fail` has no entry in `Working/Q/Q1/FAILURES.md`; a
  `named omission` has no T row id.
- It must not "repair" anything (R11): a missing recording is a FAIL, never a skipped row.
