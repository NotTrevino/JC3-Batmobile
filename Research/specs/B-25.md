# B-25 build spec — the lock-on reticle's entity → HUD link

Card source: `tmp/freebuff/reports/wp4-fire-leech.md` §1/§4/§6, `tmp/freebuff/reports/lock-on-reticle-hud-link.md`,
`Research/JC3Grab/JC3_HUD_WEAPONS.md` §5, ledger row `T-WP4` (`next`). Opened 2026-11-06 by
`tmp/freebuff/reports/apply-weapon-slot-rows.md`.

**SUMMARY: THE ART EXISTS, THE CALLER DOES NOT.** JC3's HUD movie ships
`POI_TYPE_LOCK_ON_TARGET` **21** with a 1.5 s rotation and a 0.5 s `MCI_missile_locked` banner, and
`CreatePoi(type, use_progress_bar, is_minor, label)` is the script entry point. But **0 of 260 HUD
scripts call it with type 21**, and nothing decodes the entity→HUD call: the weapon tune's `AutoAim`
state is what a native aim manager would read, and that link is not data. So the marker can be
authored, and it will not be driven by the missile's own lock state without a caller.

## 1. What is decoded

| item | value | where |
|---|---|---|
| reticle POI type | `POI_TYPE_LOCK_ON_TARGET` = **21** | `JC3_HUD_WEAPONS.md` §5 |
| rotation time | **1.5 s** | same |
| locked banner | `MCI_missile_locked`, **0.5 s** | same |
| script API | `CreatePoi(type, use_progress_bar, is_minor, label)`, no distance field | same |
| callers of type 21 | **0 of 260** HUD scripts | `wp4-fire-leech.md` §1 |
| lock beep RTPC | `BML_AP_Rocket_Lock`, `LockOnBeepProportionParam` | `WEAPONS.md` (T-WP12) |

## 2. Steps

1. Author the marker through the mission-style tracker graph pattern (B-21's
   `graphs/mission/mm130/mm130_tracker.gdc` precedent): create POI type 21 on the acquired target
   and drive the banner with the weapon's fire state.
2. Because no data says when the native aim has a lock, take the trigger from the **closest decoded
   signal**: the `AutoAim` cone is authored (T-WP4), so a script-side re-check of the same 120 m /
   0.12 rad cone reproduces the acquisition decision in the open.
3. Record on `T-WP4` that the marker exists as art + an authored caller, and that the native
   entity→HUD link is UNKNOWN.

## 3. Done (gate BZ-4)

- A take shows the reticle appearing on the vehicle the missile actually acquired and disappearing
  when the missile is fired or the target leaves the cone.
- `T-WP4` and T-19's HUD rows name card B-25 as the owner of the marker.

## 4. Stop

If the graph cannot see the weapon's state, ship the marker on a plain aim-raycast script and record
the native link as UNKNOWN — never as "no reticle exists", which the movie contradicts.

## 5. Revert

Remove the marker graph and re-run `t19_hud.py --check`, `t_rows.py build`, `t_blocked.py --write`.
Nothing here touches a game install.
