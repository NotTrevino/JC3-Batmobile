## 4. Exact gaps

- **control flow inside every body (jumps, branches, conditions)** - the repo walk is one left-to-right pass without a jump table. A call in a body proves the body contains it, not that the button's path executes it; each function's unexplained byte count is reported so the residue stays visible.
- **what an `EX_VirtualFunction` (0x1B) FName dispatches to** - 0x1B carries a name, not an object. name_match lists every export with that name (state, class and unrelated classes); the engine's dispatch is not stored in the package.
- **the arguments inside an `EX_Context` (0x19) / `EX_Skip` (0x18) window** - these tokens carry a nested expression and a skip offset, so they have no fixed operand width; the argument list stops there and the offset is reported.
- **the effect of a native/imported callee** - a call whose operand is <= 0 (an import such as Core.*) has no body in this package; it can only be reported by name.
- **which weapon or mode an integer argument selects** - the literals are decoded, but the objects behind the *PrimaryWeapon / SecondaryWeapon slots and the weapon class indices are not resolved here.
