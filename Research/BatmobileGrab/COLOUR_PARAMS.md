  line assumed a multiply and is not repeated here.
- **No combine rule.** The 11 Batmobile `MaterialFunction`s hold 944 expression slots,
  **0 non-zero** in this read, so no operator, input or output link is in the
  package.
- **No socket mapping.** Which parameter feeds base colour, roughness, anisotropy or
  dirt is in the stripped graph.
- **No pixels.** Texture parameters are object references; their payloads are assets.
- **No lighting or tonemap.** Shader code (`COLOUR.md` §5-6).

## 6. UNKNOWNs

1. **the rule that combines the parameters (what multiplies what, in which order)** - every `FunctionExpressions` slot of the 11 Batmobile MaterialFunctions is zero (944 slots, 0 non-zero in this read), so no operator, input or output link is in the package; G3-04b recorded the same dead end
2. **the authored default of the body base colour** - MIC 767 overrides `Material0_BaseColour` to [0.025787, 0.025787, 0.03, 1], and the material's own expressions for it (716 in `Batmobile_Worn`, 720 in `Batmobile_Worn_NoRain`, 683 in `Batmobile_V3_Body_NoRain_MAT`) carry no `DefaultValue` tag, so only the override value exists in bytes
3. **which parameter feeds which material socket (base, dirt, roughness, anisotropy, ...)** - the sockets live in the stripped expression graph; this card decodes parameter identity and values only
4. **whether the MIC value is what the shader receives** - no runtime oracle exists in the project; this is a file read, not a game measurement
5. **the pixel/texture contents behind the texture parameters** - only the texture object reference is decoded here (e.g. 5431); the texture payload is an asset, read by another extractor
6. **lighting, reflection probe and tonemap terms** - shader code, not serialised in the material package (COLOUR.md §5-6)
