# The packed bool at `FKBoxElem+0x4C` - can it be named from the fleet?

**STATUS: UNKNOWN.** No property is shared by every nonzero `0x4C` box and absent
from every zero box, so the card's rule forbids a name.

Generated by `Tools/scripts/box_flag_0x4c.py` (`--write` / `--check`). Every number and
every row below is recomputed from the package bytes by `--check`, which requires this
file to come back byte-identical.

## 1. Answer

The element layout is the settled one: `grab_collision_shapes.parse_aggregate()` reads
`[nSphere][spheres][nBox][boxes][nSphyl][sphyls][nConvex][convex][9-byte zero footer]`
(`chase-G3-01b-boxes-u2.md`), so a box is a `TM` struct + three FULL extents at
0x40/0x44/0x48 + the `BoolProperty` word at 0x4C, 118 bytes (`G3-01b-boxes.md`).

Across **3563** boxes in **3079** bodies the `0x4C` word takes **9** distinct values. The
**1068** hit boxes (nonzero word) sit on **722** bodies in **8** packages.

| question | answer |
|---|---|
| boxes checked | **3563** |
| boxes whose `0x4C` byte is nonzero | **1068** |
| one property shared by **all** hits and absent from every zero box? | **NO** |
| name adopted for the `0x4C` flag | **UNKNOWN** |
| bits that pass the rule on their own | bit 0 (`0x01`) by `bone_unnamed`, bit 1 (`0x02`) by `bone_unnamed` |

The word as a whole: no property in the fixed list holds for all 1068 hit boxes, so
the rule cannot adopt a name from any of them.

Even where a bit passes, that is a **correlation in the census, not a decode**: the
element's tags record an *offset* and a *word*; nothing in the bytes says which bool a
bit is. §5 reports every bit against every property so the reader can see exactly how
strong or weak each one is.
