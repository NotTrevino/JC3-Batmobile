## The rule

| class | verdict | why |
|---|---|---|
| `*Property` | irrelevant | property declaration - names a slot in a script struct or function; the value itself lives on the archetype |
| `State` | irrelevant | script state header (state machine label, not a value) |
| `FaceFXAnimSet` | irrelevant | FaceFX facial-animation asset for a dialogue line - audio/vis data, counted by the audio cards |
| *(unresolved)* — script-class export (outer `BmScript`) | relevant | declares a class; its defaults live on the `Default__*` object the grab already decodes |
| `Function` | relevant | script bytecode - **not decoded**; numeric literals are possible and their meaning is UNKNOWN |
| `RInteractionComponent`, `ParticleSystemComponent`, `SkeletalMeshComponent`, `CylinderComponent`, `SpotLightComponent`, `AkDialogueComponent`, `RVehicleThreatComponent` | relevant | a component instance whose class can carry a light, FX, threat or collision value |

### What the pass recovered

- **44 of 44 objects yielded no property tag**: the 24 script-class and component payloads
  start with a zero type-id at byte 0, which is an empty property list, so `upk_read`'s
  walker stops before reading anything (`stop=end`, 0 parsed bytes). The other 20 are
  `Function` payloads - live bytecode, not an empty list - and stay undecoded (next bullet).
- **7 script-class rows (5 distinct classes) decode their parent class** from the first
  object reference after that empty list (negative index = import):
  `Core.RBatmobileMissileLauncher`,
  `Core.RDummyTarget_Spawnable`,
  `Core.RHidePoint`,
  `Core.RPawnVillainThug`,
  `Core.SequenceEvent`,
  which is what an `(unresolved)` class export is: a script class compiled into the
  package, outer `BmScript`, declaring no properties of its own. That identification is
  **inferred from the name correspondence** (all 5 parents match the export names), not a
  decoded `UClass.SuperField`.
- **17 component rows stop at their own name**: the tail is `NameIndex + Number`, i.e. the object's name
  read against the name table (verified per row: the index resolves to the object's own
  name, and to an unrelated export when read as an object index - so it is a header, not a
  value). **7 of those 17 payloads carry a float-like value** in the unmodelled tail:
  `CollisionCylinder` +40 = 0.60686, `NewHydraPFX1` +48 = 0.93112, `CriticalPfxCompBase` +40 = 0.23984, `GenericHeadParticleSystem` +40 = 0.84841, `XCS` +40 = 0.82546, `GadgetMesh` +40 = 0.77383, `Mesh` +40 = 0.49544.
  Their meaning is **UNKNOWN** - this walker does not model the tail, so whether any is a
  value the mod could use is not decided here.
- **20 `Function` exports (5,562 B) are live bytecode and were not decoded**: payloads are
  45-793 B, 17-553 non-zero bytes each. A numeric literal (damage, impulse, velocity) could
  sit in the instruction stream, so they are classified **relevant**; none of the names
  appears in `WEAPONS.md`, and `DAMAGE_RULES.md` carries only the unrelated substring
  `bDamagedByCloudburstTank`. The card's second pass records them as bytecode, not a value.
- The grab's own reference scan recovered **96 native references across 29 of the 140 rows**
  (`native_refs` in `objects.jsonl`) - references, not values.

## What this settles - and what it does not

- **The 44 objects this card calls relevant yielded no property tag.** 7 script-class rows
  resolve their parent class (name-inferred), 17 components stop at their own name (7 with
  an unlabelled float in the unmodelled tail), and 20 `Function` exports are bytecode.
- **No weapon, sim or damage value was extracted anywhere in the 140.** That is a result of
  the pass, not a proof of absence: the 20 `Function` payloads (5,562 B) were not decoded, so a
  literal inside them is **UNKNOWN**, and the 7 component tails are not modelled, so their
  floats have no meaning yet. Both are stated again under Gaps.
- The values the relevant classes do have live on their `Default__*` objects, which the grab
  decodes as ordinary tagged rows (`Default__RBatmobileMissileLauncherJoker` and friends).
- The card's `relevant` set adds no *decoded* number to G1-08/G1-14/G1-21: the families those
  cards list are all in `OFFSETS.json` / `CHAIN.json` already. Whether an undecoded literal
  belongs to one of them is UNKNOWN until the bytecode is read.
- Gaps.md's "refs recovered" column is explained: 29 of the 140 rows carry 96
  references the native scan found by index probing; a reference is a pointer to another
  object, not a value.

## Gaps (stated, not filled)

- The 17 component tails are **not modelled** by `upk_read`: after the empty property list
  they hold an FName header and then native bytes this walker does not decode. 7 of the
  payloads carry a float-like value there (listed above); what each one means is UNKNOWN.
- The 20 `Function` exports (5,562 B) are **undecoded bytecode**. A numeric literal could be
  in the instruction stream; nothing here reads it, so the card's 'decoded or explained'
  exit is 'explained: not decoded', never a value.
- The 785 untagged objects at or below 8 B are not individually classified - the card sets

  The six-byte rows include `AkVehicleSound`, `RVisualDamageComponent`, `PointLightComponent`, whose classes are not in the rule above; they are
  below the card's cut, so they are named here and not classified.
- This pass needs the BmAK install at `E:\Games\Batman - Arkham Knight\BmGame\CookedPCConsole`; without it `--check` cannot re-run and fails
  with that path in the message.
