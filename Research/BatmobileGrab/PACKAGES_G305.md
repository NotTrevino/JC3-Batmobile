**Two payload shapes hide behind "untagged", and the sweep separates them.**

1. **The 30-byte class-default property objects do not parse.** Byte 0 reads as `int16 0`,
   the property-list terminator, so the walk that resolves every other object in the grab
   stops at once (0 tags, 0 bytes). Sweeping start offsets 0..19 closes 34 of the 145
   `RVehicleBatmobile` + `RBatmobileRemoteBm` payloads, and **every close is a single**
   `ByteProperty` at offset `0x0000` with an empty payload - a payload that happens to end
   on the `0000` terminator the object carries, not a property stream. No value is taken
   from them; the names are the deliverable.
2. **The component payloads are a record with a 12-byte prefix.** 19 Startup payloads and
   2 StartupPatch payloads close a **two-tag** stream from start 12. That prefix is the
   object's own record: its `int32` at offset 4 equals the export record's name index on
   every one of them (checked against the export table - `0x64E3` = `FrontCollisionCylinder`,
   `0xDB8E` = `RearCollisionCylinder`). The tags behind it are recorded verbatim in the
   JSON and are **not interpreted**: which class slot each offset is - and therefore what
   the cylinder dimensions are - is G3-01's question, not this census's.
