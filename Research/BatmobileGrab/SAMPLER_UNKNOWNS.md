`StealthOrGadgetPressed|OnReleaseEndStealthMove|OnReleaseGadgetReleased|ButtonbCrouchButton|FloorTakedownModifierPressed|OnReleaseFloorTakedownModifierReleased|LedgeToCeilingPressed|LandPressed`

`bThrottleButton` is +780, and it does **not** appear in the resolved RT writer set - so 780
never moving is the expected result of this binding, not an anomaly.

`aThrottleAxis`, so 0.0 across both runs is consistent with the bind tables.

## U6 - byte names 783/771/772 and the TArray strides: ANSWERED

(A), 772 = `bCrouchButton` (a side effect of RT's `StealthOrGadget` binding).

**Strides.** `TArray<T>` stores the pointer, `Num` and `Max` (pointer at +0, count at +8, max at
+12 - `Classes/Core/TArray.cs`), and the element stride comes from
`MarshalUtil.GetSizeUnmanaged<T>()`, decoded in `Framework/MarshalUtil.cs`:

| rule | returns |
|---|---|
| `IsValueType` | `Marshal.SizeOf<T>()` |
| `IsInterface` | `sizeof(FScriptInterface)` (two `IntPtr` fields) |
| assignable to `GameObject` | `sizeof(IntPtr)` = 8 on x64 |

- `CurrentTargets` +2400 (`RBatmobileMissileLauncher.g.cs:300`), element `BmSDK.Engine.Actor`
- `FiredProjectiles` +2632 (`RBatmobileMissileLauncher.g.cs:549`), element `BmSDK.BmGame.RProjectile`
- `LastTargets` +2416 (`RBatmobileMissileLauncher.g.cs:309`), element `BmSDK.Engine.Actor`
- `MaxTargetsPerLevel` +2592 (`RBatmobileMissileLauncher.g.cs:513`), element `int`
- `MissileSockets` +2608 (`RBatmobileMissileLauncher.g.cs:522`), element `BmSDK.FName`
- `VolleyDamageMultiplier` +2572 (`RBatmobileMissileLauncher.g.cs:495`), element `float`

Element types read from the getters: `CurrentTargets` and `LastTargets` are `TArray<BmSDK.Engine.Actor>`,
`FiredProjectiles` is `TArray<BmSDK.BmGame.RProjectile>`; `Actor : StateObject : GameObject`
(`Generated/Engine/Actor.g.cs`, `Generated/Core/StateObject.g.cs`), both classes, so both arrays
stride **8** bytes per element. The count at +8 is enough to count; +8-strided walking is now
