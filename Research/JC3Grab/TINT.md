# JC3 dynamic paint tint: the on-disk parameter (G3-09d)

Generated by `Tools/scripts/jc3_tint.py --write`; `--check` re-parses every entity
graph, every `.rbm` and the header, and fails on any change.  Static only: no game
process was started, attached to or injected into.

## 1. Answer

**The paint tint is an entity-graph parameter, not a `.rbm` one.**  Each of the 76
entities that ship a paint table carries it inline as a `Palette` module: the
`tints[i].tint_r`, `tint_g`, `tint_b` RGBA records plus their `occurrence` weight and
the `specular_gloss` / `metallic` / `clear_coat` look scalars.  The table is the
palette `.vmodc`'s own content, inlined into the entity by the cooker; the module files
exist on disk too, and the fleet references 26 distinct ones.

The shader receives that colour in `cb6` - `m_TintColorR` at 0, `m_TintColorG` at 16,
`m_TintColorB` at 32 - but the `.rbm` `CarPaintMM` block does **not** hold the per-car
value: its authored dynamic float4[0] is one constant on every paint block (see §4),
and no palette tint occurs in it.  Who writes the palette into `cb6` is **UNKNOWN** —
that is engine code, and no file on disk names the binding (G3-09 measured the same).

## 2. The parameters, with the oracle

A parameter is called the tint only if it differs between two cars that ship different
paints.  `O3` finds such a pair by *disjoint* `tint_r` sets:

* `v0000_car_autostraad_oldjeep` - tint_r values [(0.2027, 0.3067, 0.304), (0.2027, 0.368, 0.4307), (0.2107, 0.2693, 0.2347), (0.2293, 0.256, 0.2347)]
* `v0001_car_autostraad_armoredtruck` - tint_r values [(0.2, 0.2, 0.2), (0.2765, 0.3147, 0.3294), (0.6118, 0.6176, 0.6029), (0.6382, 0.6382, 0.5941)]

Disjoint, and the two graphs name different palette modules, so the parameter passes
the oracle at that pair; every car with a `Palette` module carries the same fields.

A shared module (`general_palette_strong`, `sports_modern_palette`, …) gives several
cars the same table; a car-specific module (`*_palette.vmodc`) gives one car its own.
The `name.hash` column follows that split: the shared palettes carry a distinct hash per
tint name, the car-specific ones carry the single value `2930093752` for every tint (so
that value is not the name's hash).
The donor's own table (`jc_vehicles/01_land/v0300_car_kensington_sportsmuscle/modules/default/v0300_car_kensington_sportsmuscle_palette.vmodc`) holds 10 tints: `White`, `Evergreen Pearl`, `Garnet Red Metallic`, `Black`, `Grey`, `Silver`, `Blue`, `Brown`, `Red`, `Green`.

| paint (`_body_dif`) | 43 | (0.14, 0.19, 0.25, 1.0) |
| non-paint | 351 | (0.0, 0.0, 0.0, 0.0) · (0.022, 0.02, 0.02, 1.0) · (0.0393, 0.0393, 0.0393, 1.0) · (0.0608, 0.0542, 0.0376, 1.0) · (0.14, 0.19, 0.25, 1.0) · (1.0, 0.0, 0.0, 0.0) |

The 43 paint blocks all share one value; the non-paint blocks carry 6 different ones
(mostly the identity `(1, 0, 0, 0)` plus a few dark default uniforms).  Neither set
contains any of the 401 palette tint_r values, including the donor's own 10 tints, so
the authored `.rbm` value is a per-material default and the per-car colour cannot be
read from the model.

## 5. The loose palette file is not vanilla

`v0300_car_kensington_sportsmuscle_palette.vmodc` (1897 B) decodes to 10 tints, every one `tint_r` [(0.05, 0.05, 0.05)], gloss [0.45], metallic [1.0] -
the default of `palette_black.py` (`--rgb 0.05 --gloss 0.45 --metallic 1`).  It is a
repainted copy, so every colour in §2 is read from the entity graph (the `.ee`'s own
inlined table), not from this file.

## 7. UNKNOWN

- **What writes the palette into `cb6`.**  No file names the binding: not the `.rbm`,
  not the `.epe`, not the `Palette` module (G3-09 measured all 566 inner files).  It is
  engine code or a runtime write; a live constant-buffer dump would answer it.
- **Whether the engine sends `tint_r/g/b` verbatim.**  The three vectors are separate
  colours on disk (`tint_g` is not `tint_r` in the shared palettes), which matches the
  header's three members, but which channel the shader multiplies where is in the SHEX,
  and the shader body is not on disk.
- **Cars with no `Palette` module** (156 of 232 entity graphs).  Their paint must come
  from the material's own static/dynamic defaults; no file ties them to a tint table.
- **The paint of the donor's model set under another car.**  Only one car's `models/`
  tree is extracted, so the `.rbm` side cannot be compared across cars even in
  principle; the cross-car oracle exists only at entity-graph level.
