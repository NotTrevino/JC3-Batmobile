# Review: does JC3 have an eject? (G2-20R, of G2-20)

Generated by `Tools/scripts/jc3eject2.py` (digest `53d406793d11f6a0`). Reviewed: `Research/JC3Grab/EJECT.md`.

**VERDICT: PARTLY CONTRADICTED.** The reviewed report's data conclusion is sound and re-derives exactly: no exit in any shipped interaction graph carries a launch, and no vehicle module carries a driver impulse. Two of its supporting statements are wrong, though: (a) its headline, **"JC3 has no eject", is wrong as an engine statement**: `JustCause3.exe` carries `ACT_EJECT_FROM_VEHICLE` and `ACT_EJECT_FROM_VEHICLE_MG` as actions, `S_EJECT_FROM_VEHICLE_ALIVE` / `S_EJECT_FROM_VEHICLE_DEAD` as states, a `VehicleBailExplosion` heat-tuning name and a vehicle member `is_rico_bail_vulnerable_timer_active`; Rico's animation set carries a clip `PPparachute_vehicle_eject`, and the game ships four `bark_rico_parachute_ejecting_*` voice lines. What is true is narrower: **no shipped graph, state machine or script references any of those names** - the eject exists as engine vocabulary with no data-side trigger. And (b) the 9-key exit census is incomplete: the donor `.epe` carries 17 further hash-named members per exit that the detail JSON drops; they are all int/event/matrix typed, so the no-launch finding survives - by type, not by key count.

## 8. UNKNOWNs

1. **Whether the engine's eject is reachable at all.** The names exist, no data references them. The trigger lives in native code (or in a code-side default not stored in any `.epe`/`.afsmb`/script). Testing it needs a Q-1 probe with an input or a debug command, which this review cannot do read-only.
2. **Whether `S_EXIT_VEHICLE_PARA` / the `PPparachute_vehicle_eject` clip applies a vertical impulse.** Clip bodies are not decoded; the reviewed report's Q1-EJ-A probe is still the only way to answer it.
3. **What `EJECT_FROM_VEHICLE_MG` selects.** The exe names a mounted-gun variant; the two mount graphs (`w201_minigun_mount`, `w205_mounted_urga_uzhas_120_mount`) exit through `S_EXIT_MOUNTED_WEAPON` and never name it, so which weapon/vehicle state it belongs to is UNKNOWN.
4. **Whether the four `parachute_ejecting` barks are reachable.** Dialogue files ship for four lines; no script or bark table in the index names them as a triggered event (the bark table itself is audio middleware data, not decoded here).
5. **The 17 hash-named exit members.** Their types are known (no float/vector) and one is the class-hash field, but their **names** are not decoded; a dictionary of 15,150 exe tokens found none. Naming them needs the epe property name list, which is not in the grab.
