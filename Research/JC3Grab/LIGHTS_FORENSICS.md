## 3. The gap the build stage fills

**T-L10**

- JC3 has **no light member on a weapon tune**: 34 tune blocks in 25 WEAPONS.jsonl records, 444 distinct member paths, 0 light-ish members (measured).
- No `.effc` carries a light node: 25,025 decoded `.effc` rows, 0 member paths matching light/glow/lumin/flash (measured FX_VOCAB).
- A lamp cannot be pulsed by the shot: the only time-varying members are `blinking` (664 rows carry 1) whose period no decoded file states (UNKNOWN), and the behaviour names, which have no forensics or weapon mode.
- The BmAK cone (Radius 4096, OuterConeAngle 50) has no unit bridge to `range`/`angle` (G2-33 §8): the build picks fleet values and records the choice.
- The visible flash has to come from the effect side: `SAttachedEffect` with `Usage` = `Fire` (5,342 objects / hash 4131019937), pointing at e.g. effects/jc_weapons/muzzle_flash/rico_50cal_muzzleflash.effc (21 vehicle carriers).

**T-L21**

- The rig is a **state, not a lamp**: `RVehicle.bForensicsLightActive` is a bool at 0x0884 (offset 2180); JC3 lights have no enable member and no forensics behaviour (vocabulary: HeadLight, LeftSignal, None, Reverse, RightSignal, SirenLightOffOnFast, SirenLightOn, SirenLightOnOffFast, TailLight).
- `RHelicopterSpotLightComponent` has no JC3 class: it declares only `AbsoluteRotation` (0x0334) on top of SpotLightComponent, and none of the aim/helicopter behaviour survives as data - the build keeps the lamp fixed to the bone transform.
- Inner cone exists only on the graph side (`SVehicleLight.spot_inner_angle`), never on the module row that binds the part: the build must author both sides with the same numbers.
- Colour alpha is not representable (`diffuse` is R/G/B only), and the BmAK red [255,0,0,255] / cyan [195,255,244,0] carry an alpha JC3 drops.
- The emissive mesh side is a `CarLight` block per mesh (11,367 blocks in 220 vehicles): 'UNKNOWN - the material/emissive parameter bytes are not decoded (MODLOG §102d), so a CarLight block can be copied byte-exact but not authored from numbers' - so the build copies a donor block instead of authoring one.
- No time base: `blinking` is a flag only (664 rows set it, no period anywhere) and the forensics pulse/sweep in BmAK is C++ / Blueprint, not data in the packages.
