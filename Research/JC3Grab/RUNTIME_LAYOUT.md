## 5. The recipe

1. Find the module base (EnumProcessModules), then read the part node's world pointer at +0x150 (and the raycast world at +0x158).
2. Read the slot count at world+0x68 and the slot array base at world+0x60.
3. For a handle h (int16, < 0 means none): slot = world[+0x60] + h*128.
4. Per slot: flags at +0x0c, float4s at +0x30/+0x40, shape pointer at +0x50, free byte at +0x60.
5. Per shape: byte +0x10, byte +0x13, float +0x14.
6. Every read above is a fixed offset from a pointer already dereferenced by the game's own code path (0x1402020d1 -> 0x141505490 -> 0x1415140f0); a sampler does not need to interpret any of them to copy them.

## 6. What is NOT decoded

- **the entity/vehicle list root (a global that leads to a spawned vehicle)** — no anchor in MODLOG reaches it and no self-validating structure exists in the file image: the part node is reached from its parent, never from a global that the static image proves. Tried: verified callers of the four anchors (0x201de0 3, 0x1505490 4, 0x15140f0 4, 0x201d4e 0) and every `.data` operand they touch; the only `.data` object on the chain is 0x142dad020, passed by `lea` as an argument and holding (52.079925537109375, 1) - a value block, not a root pointer. Where it would be: a read-only probe that scans `.data` for a pointer whose target holds the part list's node layout (+0x150/+0x158 non-null).
- **which slot field is the world transform and which is the AABB** — 0x1415140f0 copies +0x40 and +0x30 as float4s and 0x140201ebd builds a 3x4 from node +0xc8..+0xf8, but no instruction in the anchors writes them back into an AABB or compares min/max, so 'transform' vs 'bounds' is a reading, not a decode.
- **the render-instance transform** — the anchors are physics-side only; no anchor dereferences a render instance. Tried: the call graph of the four anchors (all bodies' `.data` operands listed). Where it would be: the draw/instance path, which no MODLOG dump names.
- **the loaded-resource table (path hashes)** — not on any anchor's path; the only hash-keyed structure the project has decoded is the `.epe` palette reference (0x6187A56B at 0x266), which is asset-side. A static search for it would need a name list and an xref method this card does not have a self-validating oracle for.
- **whether a slot handle is global or per-world** — 0x140222ef0 enumerates handles 0..count-1 of ONE world and writes them into a caller buffer; the transfer to the parts' +0x100/+0x102 fields is not in that function.
