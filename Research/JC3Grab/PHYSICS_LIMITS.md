# JC3 joint limits, tied to atoms and byte offsets (G3-10e)

Generated by `Tools/scripts/jc3_physics_limits.py` from the shipped bytes. `decoded` = read at the stated offset with the oracle named; `UNKNOWN` = no header or decoder pins it.

Fleet: **419 hinges** and **71 ragdolls** over 51 `.physicsc` files (extents [304] / [416]).

## 1. The atom list (decoded boundaries, numeric types)

a hkpConstraintAtom starts with a 16-bit type code; the code at each listed offset is identical in every object of the class across the fleet, while the payload after it varies per car.

| class | atom start | type code | extent | same code in all objects |
|---|---:|---:|---:|---|
| hinge | +0x020 | 2 | 144 B | 419/419 |
| hinge | +0x0B0 | 23 | 16 B | 419/419 |
| hinge | +0x0C0 | 18 | 40 B | 419/419 |
| hinge | +0x0E8 | 17 | 16 B | 419/419 |
| hinge | +0x0F8 | 14 | 16 B | 419/419 |
| hinge | +0x108 | 12 | 16 B | 419/419 |
| hinge | +0x118 | 5 | to the object end | 419/419 |
| ragdoll | +0x020 | 2 | 144 B | 71/71 |
| ragdoll | +0x0B0 | 23 | 16 B | 71/71 |
| ragdoll | +0x0C0 | 19 | 96 B | 71/71 |
| ragdoll | +0x120 | 17 | 16 B | 71/71 |
| ragdoll | +0x130 | 15 | 32 B | 71/71 |
| ragdoll | +0x150 | 16 | 32 B | 71/71 |
| ragdoll | +0x170 | 16 | 32 B | 71/71 |
| ragdoll | +0x190 | 5 | to the object end | 71/71 |

**UNKNOWN:** the type *names* (limits / motor / ball-socket / friction). A Havok 2014.1 `hkpConstraintAtom` enum is not in this project, so a name would be a guess; only the code and its position are decoded. Every code above is constant in 100 % of its class at that offset - that constancy is what makes it an atom start rather than payload.

Inside atom 0 the two frames are **3 rows of 4 floats at +0/+0x10/+0x20, translation at +0x30 (64 B per frame)**. Oracle: hinges A 419/419, B 419/419; ragdolls A 71/71, B 71/71, C 71/71 (rows orthonormal, det +1). The third frame of a ragdoll sits at +0x0D0, inside atom 2, not in atom 0.

The 4th float of each row is 0 in 410/419 hinges (frame A) and 71/71 ragdolls (frame C); in **9** hinges it holds a scalar instead (`A.w[1]` between -0.92 and 0.94). The rotation still decodes there, so the scalar is a separate field in that slot, not a damaged row: atv.physicsc 0x94B20 w=-0.918929, combatdirt.physicsc 0x436C0 w=0.937178, modernmoped.physicsc 0x32510 w=0.866025, modernroad.physicsc 0x3CFA0 w=0.906307 ….

## 2. The hinge's angular limit atom - type code 14 at +0x0F8

| field | offset | value in the donor (left door, 0x4DA80) |
|---|---:|---|
| atom type | +0x0F8 | 14 |
| atom flags | +0x0FA | 1 |
| **min angle** | +0x0FC | **0 deg** |
| **max angle** | +0x100 | **80 deg** |
| factor (not a limit) | +0x104 | [1.0] in 419/419 |

Oracle over the fleet (the reason this is a decode and G3-10b's column was not):

| property | result |
|---|---|
| min <= max | **419/419** |
| both values on a 0.5-deg grid | 405/419 |
| both within +/-pi | 419/419 |
| min = 0 (a closed-at-zero joint) | 227 |
| distinct (min,max) pairs | **64** |
| the +0x104 float | [1.0] in every hinge |

The pairs that ship: (-180, 180), (-179, 179), (-90, 0), (-75.621, 0), (-75, 75), (-60, 0), (-50, 0), (-50, 25), (-50, 50), (-45, 0), (-45, 45), (-35, 0).

So the hinge has **one angular limit pair**: min at +0x0FC, max at +0x100, radians. The limited hinge has a single angular degree of freedom (the class name is decoded from the packfile), so the pair bounds that one angle; which column of the frames is that axis is UNKNOWN - no byte here names it.

## 3. The ragdoll's three limit atoms

Same shape in each: type code at the atom start, min at +8, max at +12, a constant factor at +16.

| atom start | type | min offset | max offset | factor | min <= max | distinct pairs |
|---:|---:|---:|---:|---|---:|---:|
| +0x130 | 15 | +0x138 | +0x13C | [0.8] | 71/71 | 15 |
| +0x150 | 16 | +0x158 | +0x15C | [0.8] | 71/71 | 17 |
| +0x170 | 16 | +0x178 | +0x17C | [0.8] | 71/71 | 7 |

**UNKNOWN:** which of the three is the cone, the plane and the twist limit. The three atoms have identical shape and nothing in the bytes orders them; a Havok header or a posed ragdoll would settle it.

**Decoded sentinel:** the min at +0x158 is exactly **-100.0 rad** in every ragdoll in the fleet, far below any cone angle; `derived`: it means "no lower limit" rather than a pose. The 0.8 at atom+16 is a constant per atom and is not a limit.

## 5. What G3-10b's 66 values actually were (re-derived)

From `PHYSICS_ROLES2.json`'s own `angle_like_tail` offsets, re-classified here against the frames this pass decoded:

| where the value sits | count |
|---|---:|
| inside a frame's rotation rows (+0x30..+0x5F, +0x70..+0x9F) | 10 |
| inside a frame's translation (+0x60..+0x6B, +0xA0..+0xAB) = the pivot re-listed | 24 |
| **in transform bytes total** | **34** |
| elsewhere in the object | 32 |
| total reported | 66 |

The review's **34** and **24** are both re-derived. They overlap: the 24 pivot values are a subset of the 34, because G3-10b's 40-float window started at +0x90 and so swallowed frame B's translation. **34** of the 66 values were therefore never a limit at all.

## 7. UNKNOWNs

- the atom type names (limits / motor / ball-socket / friction): the 2014.1 hkpConstraintAtom enum is not in this project, so only the numeric code is decoded
- which ragdoll axis each of the three limit atoms is (cone / plane / twist): the three atoms carry the same shape (min, max, 0.8) and nothing in the bytes orders them
- the non-limit atoms' fields: their bytes are constant per class but no oracle pins a name
- for hinges the joint's free axis is not named by these bytes; only that the class has one angular limit pair
