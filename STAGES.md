# Project stages (operator ruling 2026-11-06)

Goal: a **100% lore-accurate BmAK Batmobile in JC3**. One rule runs through every stage:
**"JC3 has no system" is never an answer.** Find the **closest JC3 system**, record it with member paths and values, and name the **gap**; the **build stage closes the gap** (compose, clone, author, repack). A row is never omitted, kept at a donor value "for character", or accepted as a limit.

| stage | question it answers | does | does NOT do | exit (done when) | where |
|---|---|---|---|---|---|
| **GRAB** | What exactly is the target, and what can the engine do? | Decode BmAK (source of truth: meshes, materials, numbers, audio, animation, HUD, controls) and catalogue JC3 (every system, member, format, archive entry) with evidence; label decoded / derived / UNKNOWN | change files, judge, translate | every BmAK feature has decoded values; every JC3 system relevant to a feature is catalogued; each UNKNOWN names what would settle it; all `--check` scripts pass | `Research/BatmobileGrab`, `Research/JC3Grab`, G1/G2/G3 cards |
| **TRANSLATE** | For each BmAK feature, which JC3 system carries it and what is left over? | One ledger row per feature: BmAK value -> closest JC3 system/member + unit bridge (derived, error shown) + **gap** + the build action that closes it. Exact carrier = gap none | omit a row, keep a donor value, say "no system", build anything | every row is `exact` or `closest + gap + build action`; 0 rows out, 0 assumed, 0 compromised; ledger and BLOCKED_PROPOSALS pinned and consistent | `Working/Translation/T_ROWS.jsonl`, T-xx cards, `BUILD_BATCHES.md` |
| **BUILD** | Produce files that carry every row, including the gaps | Offline, into NEW private trees (`Builds/bm-RC4*`): edit private copies of tunes/modules/entities/effects, author geometry/textures/banks, compose several systems where the closest one is short; package a release candidate with receipt and installer; read every value back through the built `.toc`; budgets and gates (V-01..V-07) | launch or install into the game | RC receipt complete; every ledger value read back 100%; gates V-01..V-06 green on a simulated dropzone; gate VX written for the operator | `Builds/`, B-xx and V-xx cards |
| **PILOT** | How does an agent drive the game without guessing? | Write the controls reference and numbered cards (launch, load, spawn, enter, drive, fight, screenshot, record, kill by PID), each with a checkable observation and a recovery; known traps from earlier failures; prove the cards on a stock car | run the Batmobile tests | a small model completes every card on a stock car with no operator help (Q-0) | `Working/Q/PILOT/`, Q-PILOT card |
| **TEST** | Does the built car behave and look like BmAK? | In-game sessions Q-1..Q-5 run via the cards, each check against its V-05 prediction band; record with audio; failures become fix cards that go back to TRANSLATE/BUILD (never retuned on the spot, never downgraded) | judge by feel, re-interpret a band | every check passes or is a named fix card; RESULTS.md complete; then release (R-1, R-2) | `Working/Q/`, Q-1..Q-5 |

Order: GRAB -> TRANSLATE -> BUILD -> (verify offline) -> PILOT -> TEST. A later stage that finds an earlier stage was wrong sends a fix card back to it; the queue (`tmp/freebuff/queue`, map in `tmp/freebuff/QUEUE_MAP.md`) encodes the order with `AFTER:` gates, and review briefs between waves rewrite later briefs. The test ban (no game launch or install) lifts only when `tmp/freebuff/APPROVED_Q.txt` exists.
