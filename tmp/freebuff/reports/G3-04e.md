# G3-04e — JC3 paint constant-buffer slots without RDEF

**VERDICT: holds, with the brief's premise corrected.** The paint constants are not in
`cb0`; they are `cb2` (`CarPaintStaticMaterialParams`), `cb6` (`CarPaintDynamicMaterialParams`)
and `cb7` (`CarPaintDynamicObjectParams`), and every slot is named from on-disk data with
12/12 agreement across the paint family. The 6,943 Arkham uniform records name **0** slots.

Output: `Research/JC3Grab/CB0_SLOTS.md` + `.json`, produced by
`Tools/scripts/jc3_cb0_slots.py --write`; `--check` re-parses every input and compares the
document byte for byte.

## What the brief supposed, and what the files say

The brief starts from G3-04d (tracker row: "shader caches decoded, no RDEF (0/40,299) ->
cb0[n] unnamed; 6,934 uniform records remain") and asks to name *cb0 slots* from the shipped
`.rbm`/`.epe` parameter lists, the uniform records and the fill order.

The premise does not survive the reflection headers. `carpaintmm.fb.txt` — a JC3 shader
reflection dump kept in the project at `Tools/JCMR-src/assets/jc3/shaders/` — declares the
four cbuffers and the binding table:

```
// CarPaintStaticMaterialParams      cbuffer  ... cb2  1
// CarPaintDynamicMaterialParams     cbuffer  ... cb6  1
// CarPaintDynamicObjectParams       cbuffer  ... cb7  1
// RBIInfo                           cbuffer  ... cb8  1
```

With bind numbers and offsets, the slot naming no longer needs `RDEF` at all: `RDEF` names
cbuffer members, and the `.fb.txt` dump already carries exactly that table (name, offset,
size) for all 961 shaders on disk.

## The family test (the brief's ">=3 other shaders")

Family = every header that declares `CarPaintStaticMaterialParams`: **12**, all the
`carpaintmm*` variants (`carpaintmm`, `_blend`, `_blend_effects`, `_blend_effects_stipple`,
`_blend_stipple`, `_effects`, `_effects_stipple`, `_mask`, `_mask_effects`,
`_mask_effects_stipple`, `_mask_stipple`, `_stipple`). One more header
(`carpaintrsm.fb.txt`) declares the dynamic cbuffer without the static one.

| cbuffer | declared by | identical member tables | bind |
|---|---:|---:|---|
| `CarPaintStaticMaterialParams` | 12 | 12/12 | `cb2` |
| `CarPaintDynamicMaterialParams` | 12 | 12/12 | `cb6` |
| `CarPaintDynamicObjectParams` | 12 | 12/12 | `cb7` |
| `RBIInfo` | 12 | 12/12 | `cb8` |

No member-name, offset, size or bind disagreement exists, so every slot below is agreed by
all 12 members, not just the 3 the brief asks for. Slot 0 of `cb2` is `m_SpecularGloss`,
`cb2[4]` is `m_DiffuseWrap`, `cb6[0..2]` are `m_TintColorR/G/B`, and the scalar overrides are
`cb6[4].x/.y/.z`.

## The engine fill order, from the `.rbm` payload

The shipped `.rbm` `CarPaintMM` block stores the painter's parameters in the cbuffer's own
order, so the fill order is decodable from the payload:

* `static_params` = 18 float4 at payload `+0x9`, exactly `cb2[0..17]`;
* `static_support` = 7 floats at `+0x129`, exactly `cb2[18].x` … `cb2[19].z`;
* `dynamic_params` = 4 float4 + 3 floats at `+0x145`, exactly `cb6[0..3]` + `cb6[4].x/.y/.z`.

Measured over **399 `CarPaintMM` blocks in 163 `.rbm` files**: static 288 B, support 28 B,
dynamic 76 B in every block — and the header cbuffers are 316 B (288+28), 76 B and 20 B, so
the mapping is size-exact as well as order-exact. The 76 B is independently the upload stride
(`imul ..., 0x4c` at `0x140259f00`; CPU fill `0x140289a80` copies `+0x00/+0x10/+0x20` into the
parity copy — G3-09's `TINT_WRITE.md`, cited, not re-derived here). So the tint RGB is
`cb6[0..2]` at byte offsets 0/16/32 of the dynamic block.

Three `.rbm` files are skipped and named in the document (`sportsmuscle_missile_base_
signature_lod1..3.rbm`): the shared codec stops at `GeneralMkIII`, which has no serializer.
They are reported, not guessed at.

## The 6,934 uniform records: 0 named, 0 ambiguous, all unnameable

`Research/BatmobileGrab/UNIFORM_RECORDS.json` is G3-04c/d's decode of the Arkham material
region. Measured from that file:

| question | answer |
|---|---|
| records | **6,943** (`.records.count`); G3-04d printed 6,934 because it capped names at 60 chars and missed 9 (`.prior_pass`) |
| entries | 9,553 × 32 B |
| entries with an offset / slot / bind field | **0** — the 32 B entry is class FName + parameter FName + RGBA |
| distinct parameter names available | 14 (the one record decoded end to end, `Batmobile_Worn`) |
| names matching a JC3 paint member | **0** |
| records nameable this way | **0** |
| ambiguous | **0** — nothing was guessed |
| unnameable | **6,943** — every record |

Why: the entry layout has no room for a slot, and the names are Arkham's (`SelectionColor`,
`Material0_BaseColour`, `Damage_Chapter`, …), not JC3's (`m_TintColorR`, `m_DiffuseWrap`, …).
The chunk that would map those names onto registers is `RDEF`, which G3-04d found absent from
all 40,299 containers. JC3 does not need those records: its name→offset table is the
reflection header set, present and tested above.
