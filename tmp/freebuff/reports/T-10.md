## UNKNOWNs and limits

- An absence here is an absence of **names in a decoded surface**, never of engine capability. The
  surfaces are named per row: `VOCABULARY.md` (52 module types / 1,421 member paths), `ENTITIES.md`
  (103-class fleet census) and the 260 decompiled `ui/hud.gfx` scripts. A mechanism implemented only
  in native code would appear in none of them — the same caveat G2X records.
- `ui/hud.gfx` is the **in-game** HUD movie. The other 28 `ui/*.gfx` movies in the index are not
  decompiled, so a widget living in the frontend (`main.gfx`, `reward.gfx`) would not be seen; the
  five HUD `out` rows are therefore worded "in the in-game HUD". This is the one place where a
  "proven absence" could still be wrong.

  and the D-2/D-3/D-7-gated ones stay `blocked: D-n` until the user answers §11. D-1 is the only
  resolved decision; D-2, D-3, D-7 are read as open from the register itself, not typed.

  is a build step (T-11 / B-05) that unblocks it — calling it superseded would claim a carrier that
  exists only as an API.
