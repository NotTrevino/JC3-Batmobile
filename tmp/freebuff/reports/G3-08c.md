# G3-08c — JC3 carriers for BmAK's two drive behaviours (static)

Task: find, in the whole JC3 fleet, what could carry BmAK's pursuit "spin in place when
stationary" and battle "move in the stick direction while the car turns to face the camera
(four-wheel drive)", plus the four other driving moves in BmAK's own controls menu (Side
Swipe, Dodge Thrusters, Power Slide, Afterburner). Static only. Read-only on the game
installs; no game launched, no install written, no process touched, no git, no edit to
another task's file.

## STATUS: done

Three carriers exist, three do not, and one of them is a member the project's own cache
had dropped.

## Evidence, by requirement

### 1. Per-wheel drive / differential — 0 members, decoded

Every member path of every module of all 232 decoded builds was scanned:

```

stationary turn / pivot                    distinct=  1 drive=0
camera-relative / face-camera control      distinct=  6 drive=0
directional impulse / shove                distinct=  7 drive=3
boost / nitro                              distinct= 40 drive=20
handbrake                                  distinct=  5 drive=5
steering input                             distinct=152 drive=17
driveline ratio                            distinct= 44 drive=29
```

The per-wheel regex (`per_wheel|wheel_torque|torque_split|differ|awd|4wd|drive_type|
driven_wheels|lsd|…`) matches nothing anywhere. The driveline-word matches are
`Transmission.final_drive` / `low_gears_final_drive` — one ratio for the whole car. A `CCar`
carries one `Transmission` and two `Tire` modules (front axle, rear axle); there is no
per-wheel or per-axle drive value, so **four-wheel drive cannot be written into a module**.
The only per-axle asymmetry is grip: `front_wheels.arcade_friction_multiplier` vs
`rear_wheels.arcade_friction_multiplier` (rear stiffer on 108 builds, softer on 0, equal on
37).

### 2. Stationary turn / pivot — no data carrier; the drift block is the closest

* Token scan finds 1 match, `VehicleCommon.train_common.train_track_width_scale` (rail
  gauge, `CTrain` only). No pivot / neutral-turn / counter-rotate member on any land vehicle.
* `CustomLandGlobal.drift.*` is a 20-member block on 145 builds — the only place a land car
  is rotated by a torque instead of a front wheel angle. Donor values: `min_speed_to_drift_kmph`
  10 (fleet 0..60), `max_drift_torque` 5000 (0..35000), `constant_drift_torque` 0 (0..20000),
  `counter_steer_torque_handbrake` 30000 (0..100000), `steering_sensitivity` 4 (0.5..4),
  `max_drift_angle_deg` 45 (20..60).
* The speed gate reaches **0** on 4 builds (1 chassis, `v0400_car_mugello_vintagesports`), so
  a value exists that does not gate the drift on speed. That is not proof of rotation at rest:
  the path is slip-angle driven (`drift_entry_slip_angle`, `lat_tire_*`) and a slip angle
  needs velocity. Classified **UNKNOWN**, not "JC3 cannot".

### 3. Battle camera-relative move — no member, no action

* 6 regex hits, all in `Propellers` (two propeller docking-strafe groups, 38 builds = boats
  and planes) — a docking limit, not a driving control. 0 hits in any land driving module.
* The patch gamepad keymap carries 16 land-vehicle actions, all discrete: `ACCELERATE`,
  `REVERSE`, `TURN_LEFT`, `TURN_RIGHT`, `HANDBRAKE`, the two fire actions, `PRECISION_AIM`,
  `VEHICLE_CAM`, `USE_VEHICLE_MOD`, `USE_ITEM`, `ENTER_VEHICLE`, `EXIT_VEHICLE`,
  `SOUND_HORN_SIREN`, `CHALLENGE_RESET_VEHICLE`, `VEHICLE_RELEASE_GRAPPLE`. Nothing carries a
  2D stick into a vehicle.
* The one whole-stick binding in either keymap is `LSTICKGENERIC -> MOVE_ALL`, whose name
  scope is on-foot. Whether a vehicle can consume it is **UNKNOWN**.
* `.epe` graphs do carry `CCameraModifier` (5796 objects across the fleet), but a camera
  modifier frames the camera; it is not a control path.

### 4. Power Slide — carrier found (tune only)

```
Brakes.rear.handbrake            1 (1 .. 1; n=145)      rear axle is the handbrake axle
Brakes.front.handbrake           0 (0 .. 0; n=145)      front axle never handbraked
Brakes.handbrake_friction_factor 1 (1 .. 10; n=145)
Brakes.rear.max_brake_torque     10000 (500 .. 1e7; n=145)
CustomVelocityDamper.handbrake_spin_damping      0 (0 .. 4; n=145)
CustomLandGlobal.drift.counter_steer_torque_handbrake  30000 (0 .. 100000; n=145)
CustomLandGlobal.drift.min_speed_to_drift_kmph   10 (0 .. 60; n=145)
```

The rear-axle-only lock plus a handbrake-specific yaw torque is exactly the mechanism a
power slide needs. Input exists (`HANDBRAKE`, RPADLEFT in the patch map); BmAK binds it to X
with RT, so the amendment is a rebind plus BmAK's own angles from the T rows.

The quoted values are the **player** module. The donor's `_ai` twin carries
`handbrake_friction_factor` = 2 against the player's 1 — that is why `VOCABULARY.md` shows 2;
its donor column read the AI instance.


What it already gives an Afterburner: flat extra top speed (+40 km/h, +80 upgraded), torque
x2, 15,000 N push, grip x2, a 0.2 s blend, and — new here — a **finite burn and a refill
rule** from `VehicleMisc`, present on all 232 builds (4 s burn, 2 s refill, only above
20 km/h). The `arcade.nitro_boost` block itself is on 145/232, matching T-WP13.

What needs an amendment: the **trigger**. No action in either keymap (249 bindings) is
NITRO or a vehicle BOOST; the only boost name is `WINGSUIT_BOOST`. The operator lead that
JC3's nitrous is "hold B" is consistent with the data side existing and the action side
missing, but as data it stays UNKNOWN. The timers are tunable; the semantics of "hold"
versus "4 s budget refilled by driving" are not.

### 6. New decoded member: `LandGlobal.steering_type`

The 54 patch-layer `*_land_global.vmodc` entries in `INDEX.jsonl`, decoded with
`jc3adf.Adf`/`jc3adf.walk` from the archive bytes:

```
steering_type  {'(absent)': 3, 'FrontSteered': 51}
FrontSteered  file hash 17C23DF5 == hash_jenkins("FrontSteered") 17C23DF5
```

Self-checking decode (the stored hash equals the Jenkins hash of the stored name). The
cached row set does not contain this member at all: it carries `is_rear_steered` and
`is_all_wheel_steered` instead, with 0 shared members disagreeing in value.

**Contradiction reported, not bent:** `TANKTURN.md` §2 names three monster-truck builds as
the fleet's only `is_all_wheel_steered = 1` vehicles. The bytes of `v0803_car_na_monstertruck`
say `FrontSteered` for all three builds. So the cached flag is not a member of the shipped
module. TANKTURN's conclusion (no pivot carrier) does not rest on it — the module member sets
are identical and no pivot name exists — but its `is_all_wheel_steered` candidate row should
be read as a cache artefact.

## Applying each carrier to the Batmobile module

* **Tune only (no code bridge):** the drift block, per-axle grip, the handbrake chain and the
  nitro chain are all values inside the donor's own modules (`custom_land_global.vmodc`,
  `land_global.vmodc`, `brakes.vmodc`, `custom_velocity_damper.vmodc`, `transmission.vmodc`,
  `vehicle_misc.vmodc`). They can be written by the existing module writer against the
  Batmobile's private module copies, exactly as the A/B batches already do.
* **Code bridge required:** the stationary pivot, the camera-relative move, a directional
  impulse and four-wheel drive. None has a module member or a graph object the engine reads;
  each would need new native behaviour, or an amendment to the requirement.
* The one carrier that is not a Batmobile tune at all: `LandGlobal.steering_type` — it has a
  single shipped value and no other value exists in the files, so it cannot be repurposed.
