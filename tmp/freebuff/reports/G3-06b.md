## 3. How a tag gets its name (the no-guess rule)

A cooked tag carries `type` + `offset` only. The name therefore comes **only** from a class layout
that declares a property at exactly that offset with a compatible kind:

```
RVehicleBatmobile      8640 B   41 declared
RVehicleBatmobileBase  8352 B  518
RVehicle            4560 B  226
AkVehicle           2128 B   13
SVehicle            2072 B   95
Vehicle             1608 B   36
Pawn                1480 B  203
Actor                668 B  212
```

* Layout source: `Research/BatmobileGrab/BMSDK_OFFSETS.json` (generated by `bmsdk_offsets.py` from
  the BmSDK-AK generated bindings, MIT — each property carries the absolute object offset the engine
  linked it to, the same number space as `FPropertyTagBat2.Offset`).
* Citation for every row: `<Namespace>/<Class>.g.cs:<line>` in
  `E:\Modding\_tools\BmSDK-AK\src\BmSDK\Generated`, i.e. the line the binding documents the property
  on, next to its `Ptr + <offset>`.
* `BoolProperty` payload = the **whole 32-bit bitfield word**, so an offset names a *set* of members
  and each member is `word & mask`. 449 masks were recovered from the `.g.cs` getters (the BMSDK
  entry omits signed ones), the rest from the entry; **0 conflicts** between the two sources, and
  every set bit of every bool word is claimed by a member.
* Three oracles decide whether a name is allowed: **kind** (tag type vs property kind, with
  `ObjectNCRProperty` ~ `ObjectProperty`/`ComponentProperty`/`ClassProperty` and
  `Vector/Rotator/GuidProperty` ~ `StructProperty` — the two documented spellings of one slot);
  **target class** (a pointer tag's target must be the member's declared class or a subclass, with
  ancestry from `BMSDK_OFFSETS.json` or, for classes outside its 41, from the class declaration in
  the binding itself); **offset** (inside the class extent). A tag failing all three would be printed
  as `UNKNOWN (offset only)` with the candidates tried — there are none.

## 8. What this does and does not establish

* **Establishes**: the two class default objects' full property streams, every tag's name/kind/value
  with the layout line it came from, and (by byte comparison) which values the subclass sets that
  the base does not and which two it changes on a shared offset.
* **Does not establish**: why a property is absent from a stream. A property whose value equals the
  class's constructed default is not serialised at all, so absence means "no value in these bytes",
  **not zero** — 901 of the chain's 1,344 declared properties are in that state
  (`CLASS_DEFAULTS.md` §6; for `RVehicleBatmobile` itself 10 of 41, listed by name).
* **Does not establish**: that the effective value of an inherited property is the parent CDO's. That
  follows only if the streams are delta lists against the parent's default object. This card proves
  the bytes and the comparison, not the mechanism (`CLASS_DEFAULTS.md` §9).
* **Does not establish**: what any referenced sub-object contains (the StaticMesh of the collision
  components, the cylinder radius, the sim object's own tags).
* Everything here compares files to files; no runtime measurement exists (G3-07).

## 9. Notes for other cards (evidence, not recommendations)

* **`Health` is 1000, not 1200.** The only `Health` value in either object is 1000
  (base stream, `Pawn` offset 1144). No stream carries 1200, and the subclass does not override it.
  The backlog's ARM-2 row and G1-14 both cite "`RVehicleBatmobile.Health` 1,200" — that figure has no
  support in these two objects and should be re-derived before it is used again.
* **Armour and regeneration now have numbers**: `ArmourLevels` [0, 300, 600, 900, 1200] (damage
  thresholds), `LowHealthWarningLevel` 300, `HealthRecoverRate` [8, 4, 2], `ArmourModeDamageReduction`
  20. ARM-5 ("regeneration, if BmAK has a regen value") is answered **yes, with values**, for the
  first time.
* **Collision (R-1/G3-01)**: the two dedicated collision components, the two stay-upright objects,
  the four wheels and the sim object are all present as class defaults with named targets. Their
  asset references (which StaticMesh, what size) live in those components' own payloads, which this
  card does not read.
* **Battle vs pursuit stance** has shipped numbers: width/length/height 265/430/250 vs 220/430/250,
  plus the two transformation anim names.
