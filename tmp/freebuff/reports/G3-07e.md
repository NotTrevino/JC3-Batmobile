# G3-07e — who writes the part node's `+0x150` / `+0x158` (step 1 of 2)

STATUS: done

## Summary

The writers question was asked from the bytes, and the answer is **UNKNOWN** — but it is now a
count, not an impression: **15** instructions write `[reg+0x150]` or `[reg+0x158]` inside the
33 reader functions of `RUNTIME_LAYOUT3.md` §3/§5 and their **54** direct callers, and **none**
of them stores the 8-byte value those readers load. The widths are the decisive fact: §3's own
readers (`0x140201de0` part_node_update / raycast_body_read, `0x140222ef0` body_slot_enum) load
`qword ptr [reg+0x150]` and `qword ptr [reg+0x158]`; in scope the stores are 4-byte float/dword
(6), 1-byte flags (3), one `inc dword` pair, and 4 stores into `rsp`/`rbp` stack frames (one of
which is an 8-byte slot — the only 8-byte writer in scope, and it is a local). So nothing in the
searched set shows how the two fields are filled: **UNKNOWN 2 stands**, now with every writer
enumerated and each one refuted by a type oracle that would fail if the hit were the node.

The whole-image census puts that in perspective: 1,953 write operands touch those two
displacements, and **166 functions write both offsets with 8 bytes** — 0 of them in the searched
set. The nearest is `0x1400a9690`, which does `mov qword ptr [rbx + 0x158], rdx` then
`mov qword ptr [rbx + 0x150], rdx` — one pointer reaching both fields, visibly. It is not a
reader nor a direct caller of one, so this card does not claim it; that is the candidate step 2
(7121) can test against a caller path. I stopped at the writers as instructed: nothing here links
a node into a container or a global.

Method note that matters for reproducibility: a flat capstone sweep of `.text` **stops at the
first undecodable byte** — measured, 25,252 of 36,310,271 bytes — so the cache is built
**chunk-driven**, one `.pdata` range at a time (188,670 chunks, 7,549,843 instructions, 4,786
undecodable bytes skipped, no desync can cross a function boundary). The pass took 276 s once;
every later search is a cache load plus a few thousand re-decodes (`--check` runs in seconds).
