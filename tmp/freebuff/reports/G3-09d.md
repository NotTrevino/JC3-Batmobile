# G3-09d — JC3 dynamic paint tint: which on-disk parameter carries it

**Summary.** The paint tint is an **entity-graph parameter**, not a `.rbm` one. 76 of the 232
extracted vehicle entity graphs inline a `Palette` module whose `A[Tint]` records carry the
colour: `tints[i].tint_r`, `tint_g`, `tint_b` (RGBA), plus `occurrence` and the look scalars
`specular_gloss` / `metallic` / `clear_coat`. The fleet references 26 distinct palette modules
on disk, 8 of them shared and 18 car-specific. The `tint_r` parameter passes the card's oracle:
two different cars (oldjeep vs armoredtruck) carry **disjoint** `tint_r` sets.

The shader side is already decoded (G3-04e): the colour arrives in `cb6` — `m_TintColorR` at 0,
`m_TintColorG` at 16, `m_TintColorB` at 32 — but the `.rbm` `CarPaintMM` block does **not**
carry the per-car value. All 43 paint blocks of the only extracted car model share one
authored `dynamic_params` float4[0] `(0.14, 0.19, 0.25, 1.0)`, and none of the 401 palette
`tint_r` values occurs in any block's dynamic floats. **What writes the palette into `cb6` is
UNKNOWN** (engine code; no file names the binding).

## Oracles (all re-derived by `--check`)

1. `O1-entity-graphs-parsed` — 232 graphs, 76 with a `Palette`, 156 without.
2. `O2-tints-differ-within-a-palette` — 26 modules, each with >1 distinct `tint_r`; 401
   distinct `tint_r` rgbs fleet-wide.
3. `O3-oracle-two-cars-differ` — oldjeep vs armoredtruck: disjoint `tint_r` sets, different
   palette modules. **This is the card's oracle for calling `tint_r` the tint.**
4. `O4-rbm-is-not-the-per-car-paint` — 43 paint blocks, 1 distinct dynamic float4[0]; 351
   non-paint blocks, 6 values; 0 of 401 palette rgbs occur in any dynamic float.
5. `O5-loose-palette-is-a-repaint` — 1897 B, 10 tints, one value `(0.05,0.05,0.05)`, 0.45/1.0.
6. `O6-cb6-slots` — header: `m_TintColorR` 0, `G` 16, `B` 32, `_unused` 48, overrides 64/68/72.
7. `O7-md-recomputed` — `--check` rebuilds the document.
8. `O8-name-hash-column` — per-name hashes in 8 palettes; one constant `2930093752` in 18.
9. `O9-donor-inlined-table-is-the-module` — the donor's inlined tint **names** equal the loose
   module's 10 names; the values differ (repaint), which is how O5 is spotted.

## UNKNOWNs

* **What writes the palette into `cb6`.** No file names the binding — the `.rbm`, the `.epe`
  and the palette module do not (G3-09 scanned all 566 inner files; G3-04e showed `cb6` is the
  right buffer). Engine code or a runtime write; a live constant-buffer dump would answer it.
* **Whether `tint_r/g/b` reach the shader verbatim.** The three vectors are separate colours on
  disk (in shared palettes `tint_g` ≠ `tint_r`), matching the header's three members, but the
  multiply chain is in the SHEX, which is not on disk.
* **The 156 entities with no `Palette`.** No file ties them to a tint table; their paint must
  come from material defaults.
* **The `.rbm` side across cars.** Only one car's `models/` tree is extracted
  (`v0300_car_kensington_sportsmuscle`, 272 files, 394 `CarPaintMM` blocks), so the cross-car
  oracle exists only at entity-graph level.
* **Why car-specific palettes all use hash `2930093752`.** Measured, not explained; it is not
  the Jenkins hash of any tint name seen (the same names carry other hashes in shared palettes).
