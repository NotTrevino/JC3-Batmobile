## Correction to G3-04

G3-04's JSON `expression_inventory` recorded "0 candidates for 237 expressions". The same
package holds **351** `MaterialExpression*Parameter` exports, all reachable through the export
table and all decoding to `eof`. The earlier inventory searched one array offset inside the

changed; the correction is recorded here and in `COLOUR_FUNCTIONS.md` §5-6.

## UNKNOWNs (and why)

1. **The operator graph of all 11 functions.** `FunctionExpressions` keeps its count and stores
   0 in every slot (944 slots). No input, constant or output link can be read from
   `Playable_Batmobile_SF.upk`. It would be answered by uncooked/editor content for these
   functions, or by the shader map the cooker generated from them - neither is present in this
   install's `CookedPCConsole` scope that this card names.
2. **Which parameter feeds which socket** (edge mask vs dirt vs wetness vs anisotropy): the
   parameters and their master materials are decoded, the wiring is not.
3. **The functions' own output expressions** (their `BaseColor`/`Specular`/`Roughness` pins): the
   pins live in the stripped graph, so no pin value is claimed.
4. **Vector parameter default values** (0/87 carry a value tag); only MIC overrides exist. Where
   it would be answered: the MIC chain (already in `COLOUR.json`) for the overridden ones, and
   the uncooked function graph for the rest.
5. **Lighting, reflection/probe and tonemap terms.** Shader code, not serialised; unchanged from
   `COLOUR.md` §5-6. This card's scope is the material functions, not the shaders.
6. **Whether the missing links are a licence-specific cooker setting or this build.** UNKNOWN -
   only one BmAK install is in scope, so there is no second sample to compare.
