## Issues

1. **The recorded build command no longer runs — the spec it points at is schema 2.**
   `Working/Translation/T8_PARTS.json:2` is `"schema": 2` (regenerated by `Tools/scripts/t12_parts.py`
   for T-12 on 2026-10-28), but `Tools/scripts/bat_assemble.py:64-65` is
   `if doc.get("schema") != 1: raise SystemExit(...)`. So
   `bat_assemble.py --parts Working/Translation/T8_PARTS.json` now aborts with
   `part spec Working/Translation/T8_PARTS.json: schema 2, expected 1` (I called `load_part_spec`
   to confirm). The `parts_manifest.json` still names that path as `parts_spec`. The geometry
   block survived the bump — I reloaded the schema-2 file directly and reproduced the cut exactly
   (see Spot-checks) — so nothing is lost, but B-02 cannot be regenerated as recorded. Owned by
   T-12's schema change, not by B-02's author; worth a one-line either/or fix (accept schema 2 in
   `load_part_spec`, or keep a geometry-only schema-1 spec).

2. **The manifest's own checks are never re-derived.** `MODLOG.md:8238` claims "The manifest's
   own 11 checks (face accounting, 31 ties, 5 LODs, pivots, budget) all PASS". Those are booleans
   written once by `bat_assemble.py:920-931` into `checks`; `silhouette_check.py:159-161` only
   *reads* them and dies if any is false. Nothing recomputes `model_budget_green`, `ties_31`,
   `pivots_finite`, or `five_lods_each` from the files. The one thing the check does re-derive is
   the face sum (`silhouette_check.py:167-169`), and it re-derives it from the manifest's own
   per-entry numbers, not from the mesh. A stale or hand-edited manifest would pass the gate.

3. **The reported gate is net coverage; the gross hole figure misses BUD-1's 0.3 % oracle.**
   Coverage 0.9997 is `ours/source` with 3,494 hole px netted against 3,130 extra px. Gross holes
   are **0.309 %**, which is *above* the 0.3 % that `silhouette_check.py:5-6` quotes as BUD-1's
   oracle ("decimation holes drop below 0.3% of the silhouette"). The card's Done text asks only
   for "≥ 99.9 %", so the card passes as written, but `MODLOG.md:8234-8236` quotes coverage and
   interior tears and never prints the 0.309 % it also produced. A reader comparing against
   BUD-1 would not see that the gross number is 0.009 pt over. Report both, or state that the
   gate was deliberately changed to net coverage.

4. **The silhouette check cannot see a wrong pivot — the pivot cancels.** The build stores part
   vertices as `Vw - pivot` (`bat_assemble.py:862`); the check reads the LOD1 triangles and adds
   back `pivot_m` from the same manifest (`silhouette_check.py:178`). Any pivot error is applied
   and removed in the same run, so the "reassembling every part at its pivot reproduces the body
   silhouette" half of the Done criterion is verified only in the trivial sense; what 0.9997
   actually measures is decimation loss. Pivot *values* are only supported by the `BONES.json`
   bind → `pivot_point` path (`bat_assemble.py:708-710`), which I spot-checked for the turret
   (exact match) — that is the evidence for pivots, not the silhouette number. The Done sentence
   overstates what the tool shows.

5. **`T8_PARTS.md` §"Geometry cut (unchanged, B-02)" prints the wrong pivot for 6 of the 11 parts.**
   The table (lines 24-34) lists the part's `pivot bone` but takes the `pivot (m, JC3)` column from
   the *joint* bone: `t12_parts.py:517-519` uses `r["pivots"].get(joint.bone) or first bone`. The
   manifest's part pivots differ from the printed values for machine gun (0.377 m), riot
   suppressor (0.187 m), all four flaps (0.132 m front, 0.393 m rear), e.g. line 28 shows
   `-0.407, 1.619, 0.810` where `parts_manifest.json` has `[-0.09166, 1.413141, 0.809727]`.
   Since `T8_PARTS.md` is the doc named in B-02's Out row (`GRAB_BACKLOG.md:1333`) and the section
   is labelled B-02, this reads as the point the part was cut about and is not. The manifest and
   the built RBMs are correct; the doc column is not. (Introduced by T-12's generator, so it is a
   T-12 fix, but it is the B-02 row's doc that is wrong.)

6. **Minor / unverifiable:** `MODLOG.md:8239-8240` says the old two-block body chain was replaced
   because "the merge failed `spec_check` at 2 vs 16 planned" — a past-run claim with no artifact
   left to check it against; acceptable as history, but it is not evidence a later reviewer can
   reproduce. Also `parts_manifest.json` records no build arguments (budgets per LOD, template,
   block index), so an exact rebuild depends on reading them out of `build.log` rather than the
   manifest. And the build is geometry only: `T8_PARTS.md:102-103` records that the cannon's BmAK
   joint and the shipped hinge disagree, so "movable parts" are movable about the bind pivot, not
   yet about a validated hinge — B-02 does not claim otherwise, but the row's title should not be
   read as joints working.
