## What changed in the picture (measured, not assumed)

* **`.lod` is not just paths.** All 59 files have the same shape: five lines naming the part's
  render models, then a trailing `1.0`. **16** of them carry `-` on a line — a LOD slot with no
  model (the `mshswap` parts, the seats, the engine). The first version of the tool rejected those
  and the census caught it: 59 FULL became 43 FULL + 16 PARTIAL until the rule was corrected. That
  is exactly the class of thing "named, not decoded" hides.
* **The ADF family closes byte for byte** (186/186): the layout is data-section-first, tables after
  it, which is why the tail looked opaque; padding between data and tables is 0x00 and ≤ 16 B.
* **`.ddsc` is the gap that matters by size**: 73.6 MB of the bundle's 79.9 MB, container accounted
  on all 116, payload read by nothing.
* **`.epe`** — `ConvertProperty` does not round trip this file byte-identically (the row records
  the exact sizes and first differing offset), so the entity tree's container is PARTIAL even
  though `rtpcdump` walks its 450 nodes.

## UNKNOWNs (and why)

1. **`.ddsc` texel payload.** No project decoder reads it. `u32[2]` (= 77 on the sampled files) is
   not mapped to a texture format; `tex2ddsc` writes only formats 71/83 through ConvertTexture.
   Where it would be answered: a ddsc reader (header → DDS shape, element table, mip chain) whose
   oracle is the element sizes summing to the payload.
2. **`.pfxc` payload.** Nothing in `Tools/scripts` opens one — the extension is only named
   (`_check_types`, `jc3sigdiff`, `jc3traffic` list it; `_check_pfxc.py` inspects the `.physicsc`).
3. **`.epe` byte-identical re-encode.** Measured failure of the ConvertProperty round trip on this
   file; the cause is inside ConvertProperty, not established here.
4. **`hkpLimitedHingeConstraintData` / `hkpRagdollConstraintData` layouts.** Typed but not decoded,
   so no hinge limit or ragdoll cone is quoted anywhere.
5. **`hknpShapeMassProperties` layout.** No mass/inertia/centre of mass is read.
6. **`hknpExternMeshShape` vertex frame.** Counts and AABBs are exact; de-quantization is not
   pinned, so no chassis vertex position is claimed.
7. **ADF member *semantics*.** Every byte of 186 files is accounted for, but a byte being read is
   not a field's meaning being known; those live in the per-feature docs, not here.
