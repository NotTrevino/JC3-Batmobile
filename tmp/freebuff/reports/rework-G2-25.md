# G2-25 rework — result

**STATUS: done.** The card's gate is green again. All three review issues trace to one cause —
the generator read another card's live `T-HUD5` row — and are fixed in `jc3hudwpn.py`; the two
artefacts were regenerated by `--write`, never hand-edited.

## Per-issue disposition

### 1. The check is red; the card cannot be `done` under its own gate — CONFIRMED, fixed

Re-ran the card's command before touching anything:

```
> python Tools/scripts/jc3hudwpn.py --check
FAIL: JC3_HUD_WEAPONS.json stale; md differs: @@ -190,3 +190,3 @@
...
EXIT=1
```

The diff is the `| T-HUD5 |` row. Cause confirmed in the source: `jc3hudwpn.py` `rows()`
(line 311 pre-fix) did

```python
t6 = read(T6_MD)
t_hud5 = next(ln for ln in t6.splitlines() if ln.startswith("| T-HUD5 |"))
```

and embedded that live line in both artefacts. T-19 later rewrote the row
(`Working/Translation/T6_HUD_CAMERA.md:24` now says "G2-25: 2 slots … T-11/B-05, slots per
D-7"), so G2-25's `--check` could never be green while T-19 owned the row.

Fix: `rows()` no longer reads `T6_HUD_CAMERA.md`. The T-HUD5 row is a **frozen snapshot**
(`T_HUD5_SNAPSHOT`) equal to the text the card saw on its done date (2026-10-27), with its
sha256, date, source and a pointer to the current row recorded in the JSON. `--check` asserts
the snapshot text, its digest and its prefix; it does not read another working document.

Proof of independence: the live T-HUD5 row still differs from the snapshot (T-19's text) and
the check passes; `grep -n "T6_MD\|T6_HUD_CAMERA" Tools/scripts/jc3hudwpn.py` finds only
comments and string constants, no `read(...)`.

### 2. Regenerating would print T-19's text under a false historical claim — CONFIRMED, fixed

Pre-rework `JC3_HUD_WEAPONS.md:188` introduced the block with "said this before the card ran",
and a plain `--write` would have put T-19's completed row under that sentence. The doc now says:

> T-HUD5 (`Working/Translation/T6_HUD_CAMERA.md`) as this card saw it on 2026-10-27, frozen
> here (sha256 `e41b8a5849f00e55`); T-19 later completed the row, whose current text is
> `T6_HUD_CAMERA.md section 1a (completed by T-19, 2026-10-28)`:

The frozen block below it is the exact 285-character pre-T-19 row, so the quotation is dated
and checkable instead of silently re-read.

### 3. `rows.t_hud5` was the one non-derived, byte-compared input — CONFIRMED, fixed

Everything else in both artefacts is parsed from the decompiled scripts or the repo's tables;
this was a mutable foreign row. It is now a dated quotation (date + source + sha256) that the
script verifies against itself, and it is no longer a byte-compared input from
`T6_HUD_CAMERA.md`. The JSON `rows.t_hud5` changed from a string to
`{text, sha256, date, source, current}`. It stays non-derived by nature — it is a historical
quote, not a measurement — and it is labelled as such; no number in the API reading depends on
it.

R11/R4 check: the rest of the document remains generated (the check's PASS line still reports
260 scripts, 9/6 arguments, 2 slots, 14 shapes, POI 21 at 1.5 s, 0 heat parameters, 69 icons,
5 WPN-12 rows), and no new value was typed into a table.
