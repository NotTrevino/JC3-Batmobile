## How `--check` earns the word "check"

Every evidence entry is a `(file, line, quote)` triple. `--check` rebuilds the ledger, re-opens each
card, reads that exact line and fails unless the quote is a substring of it - so a rewritten card
invalidates the row instead of leaving a stale claim. It also fails if a row's status is not one of the
four, if a non-OPEN row has no quoted line, if an OPEN row has no named card, if the row ids drift
from `T_ROWS.jsonl`, or if the first pass's marked-row count is not 18.

   effective value is a JC3-side composite (`VALUES.json`), not a BmAK number.
3. **Gloss 0.45 (T-MA4).** No card read here has a "gloss" parameter; the paint chain exposes
   roughness and reflectivity. Whether 0.45 is a JC3-side remap of roughness, of reflectivity, or of
   both is not in these files, so it stays unverified rather than refuted.
4. **Whether the first pass's 18 were meant to be read as "answered".** The verdicts above judge the
   card/row pair only. A row can be `WRONG_CARD` and still be right about the game; this pass makes no
   claim about gameplay.
