## What the card asked for

1. **How a hit becomes health loss.** Seven cited steps. Numbers are decoded for four (weapon
   damage and factor; the eight armour channels; `part_damage_types`; `max_health` + the root
   `health` 100.0 / `invulnerable` 0). The mechanism of "which part a hit lands on" is decoded from
   the fleet's only readable `VehicleParts` module (monorailflatbed). **The composition itself is in
   no decoded file** — so rather than invent it, the document carries three named models with exact
   formulas: H0 (armour ignored), H1 (percentage gate = MODLOG §97's reading, `D = damage ×
   (1 − strength/100)`), H2 (per-hit threshold + absorbing pool). Each undecoded step is marked
   UNKNOWN in its own table cell and cross-referenced to a Q-1 probe.
2. **Predicted hits-to-kill** for Rico's pistol / AR / MG / shotgun / RPG / grenade and `w602`,
   `w601`, `w604`, on the donor, the medium tank and the live build — 81 cells, all generated from
   file values. Two arms are not what their names imply: `w602`'s bullet damage is **1.0** (its work
   is the 1500 blast in 8 m) and the shotgun is **144 per pull** (8 × 90 × 0.2).
3. **ARM-1 / ARM-2.** ARM-1 needs `bullet_armor_strength` 100 (H1) or ≥ 144 (H2) — both outside the
   shipped 0..99, and test-077 already shipped 100 and failed; `invulnerable = 1` is in-domain but
   whole-vehicle, so it cannot coexist with ARM-2. ARM-2 is already satisfied (explosion strength 50
   < shell 1500). ARM-2 **at the BmAK 24-hit ratio** (G1-14: 1200 HP / 50) would need
   `max_health` 36,000 against a fleet range of 500..4000.

Every UNKNOWN became a Q-1 probe with exact expected values under each hypothesis: `Q1-DM-A`
(shell on the explosion channel — H0/H2 **2** hits, H1 **3**), `Q1-DM-B` (200 pistol rounds — H0
destroys, H1 60 HP, H2 0 HP), `Q1-DM-C` (the pool half of H2, on a vehicle that has a pool).

## UNKNOWNs and limits

- **The composition rule** (armour + strength + health + root `health` float) — not in any file the
  project has decoded. This is the honest core of the card: the prediction is a bracket across three
  models, not a single number.
- **Part → damage type for all three vehicles**: every `*_vehicle_parts.vmodc` except the monorail
  flatbed fails ConvertAdf (MODLOG §98), so all hits-to-kill numbers assume the root pool takes
  every hit.
- **Weapon → armour channel**: 0 of 1,515 weapon-tune member names mention heavy/armour/penetration,
  so whether an assault rifle is `bullet` and a tank MG `bullet_heavy` is UNKNOWN — which is exactly
  the split ARM-1/ARM-2 needs.
- **Root `health` float semantics**: 100.0 on all 233 roots, no second value in the fleet.
- **`explosion_threshold` semantics**; **`initial/damaged/loosen_health` semantics**.
- **Which pistol/rifle Rico starts with** — one named variant per class is used; no file names a
  default loadout.
- **BmAK incoming damage** — `GetDamageMod` is native (G1-14 §7), so the BmAK side of the ratio is
  the projectile `Damage`, not player-visible health loss.
- Rows whose channel is `unknown` (missile direct hit, grenade's thrown damage) are computed with
  no armour, i.e. they are **lower bounds** on hits.
