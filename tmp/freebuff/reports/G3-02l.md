# G3-02l - BmAK driving model per mode (static)

STATUS: done. The per-mode drive mode, the fields that carry the mode's torque/steer behaviour,
the steering input path that is in script, and the camera-relative carriers are decoded with
`Tools/scripts/grab_drive_modes.py` (8/8 oracles, `--check` re-derives md+json byte-identically).
The one thing the cooked packages cannot give is the arithmetic inside
`RVehicleSimBatmobile.SetDriveMode`, which is a native declaration - that stays UNKNOWN with the
reason. No game was launched, attached to or installed to; no other task's files were edited.

## What was decoded

1. **`RVehicleSimBatmobile.EBatmobileDriveMode`** (BmGame.upk export 129610) = `BMDM_Drive` 0,
   `BMDM_TurnOnSpot` 1, `BMDM_BattleMode` 2, `BMDM_MAX` 3 (decoded from the enum payload:
   count + (FName, number) pairs resolved through the name table).
2. **Which state asks for which mode.** `RVehicleBatmobileBase.PursuitMode.BeginState`
   (export 10515) calls `SetDriveMode` at script offset 69 with the byte argument **0**;
   `RVehicleBatmobileBase.BattleMode.BeginState` (export 10529) calls it at offset 88 with **2**.
   The NPC twins (`RVehicleNPCBatmobile`, exports 129841 / 129848) do the same at offsets
   58 / 103. No script body passes 1 (`BMDM_TurnOnSpot`).
3. **`RVehicleSimBatmobile.DriveMode`** = ByteProperty at class offset **0x03b0**; the sim class
   default object (BmGame.upk export 129779) carries the FName `None` there = enum 0, and the
   shipped `Default__RVehicleBatmobile.SimulationModel` (Startup.upk export 169320) carries no
   tag of its own, so it inherits the pursuit mode.
4. **The fields that decide per-mode behaviour** (class defaults from BmGame 129779, values the
   shipped sim overrides from Startup 169320, vehicle-side values from BmGame 10923):
   `TurnOnSpotFrontTorqueFactor` 0.6 / `TurnOnSpotRearTorqueFactor` -0.5 (opposite signs),
   `DesiredTurnOnSpotSpeed` 180, `TurningModeMaxSpeed` 300, `BattleModeTurnOnSpotTorqueFactor`
   0.3, `BattleModeStopAndTurnAngleStationary` 60, `...AngleMoving` 90, `BattleModeSteerAngleFactor`
   2.5, `BattleModeMaxSteering` 80, `BattleModeRearWheelTorquePower` 0.5,
   `BattleModeTrailingSteerFactorTurnOnSpot` 1.0 / `...Moving` -0.5, `BattleModeDriveForceFactor`
   75, `BattleModeMaxSpeed` 1200, `BattleModeThrottleSpeed` 5, `BattleModeLatSlipScale` 4,
   `BattleModeLongSlipScale` 10, `BattleModeEngineBrakingFactor` 0.025,
   `BattleModeDrivingForceZOffset` 10, `FrontWheelSteerPct` 1.0; shipped overrides
   `TurnOnSpotModeEngineBrakingFactor` 0.01 and `DriveModeEngineBrakingFactor` 0.003. The
   `BattleModeFrontThrottle` / `BattleModeRearThrottle` / `RearWheelSteerPct` /
   `ForceTurnOnSpotMode` fields are declared but carry no tag in any of the three objects.
5. **Steering input path in script:** `DrivingMode.CheckBattleStrafe` and `PursuitStrafe` read
   `PlayerInput.aBaseY` / `PlayerInput.aStrafe`, build a local move vector, then read
   `BatmobilePawn.Rotation` and `RVehicleBatmobileBase.BattleModeYawOffset`;
   `PursuitStrafe` calls `GetMovementAxes(X, Y, Z)` and then `VehicleStrafe(Strafe,
   BatmobileSideSwipeTarget)`; `RVehicleBatmobileBase.VehicleStrafe` (440 script bytes) applies
   `KickStrafe` with `PMDodgeTorque`/`PMDodgeForce`/`PMDodgeDuration` and spawns left/right
   exhaust bursts. `PursuitMode.Tick` reads `Core.OutputSteering` and passes it to
   `SetWantAirBrakes(OutputSteering, ..., OutputSteering)`; `BattleMode.Tick` has no steering
   call at all.
6. **Camera-relative carriers:** `RVehicleBatmobileBase.BattleModeYawOffset` (IntProperty,
   class offset 0x1910 = 6416, vehicle CDO value **16384 = 90 deg** in UE3 rotator units) is
   compared with a value in the mode bodies (`0x9a` at 95 in PursuitMode.BeginState; `0x9b` at
   248 / 421 in BattleMode.BeginState/EndState) and is read while `BattleDodge` builds its
   strafe direction from `Core.Rotation`; the int32 constant 16384 appears in `PursuitStrafe`
   at 223 and `CheckBattleStrafe` at 251. `RVehicleSimBatmobile.AbsoluteMoveDirection`
   (StructProperty 0x0378) is read/written by `PursuitMode.Tick` and by
   `DrivingMode.StartRun`/`EndRun`; `RVehicleBatmobileBase.bForceBattleModeMovement` (Bool,
   0x11dc) has no script writer in the corpus scan.
7. **Controls-menu moves:** pursuit *Side Swipe* = `CheckBattleStrafe` -> `PursuitStrafe` ->
   `VehicleStrafe(Strafe, BatmobileSideSwipeTarget)`; battle *Dodge Thrusters* =
   `BattleStrafe` / `DelayedBattleStrafe` -> `BattleMode.BattleDodge` (impulse 54484 + afterburner
   pulses + FF waveform). *Power Slide* (left stick + RT + X) is UNKNOWN: no `PowerSlide` or
   `Drift` return in the Batmobile classes and the X binding selects a weapon slot.

## Operator leads vs the files

- "Pursuit sliding-turn spins the car in place / four-wheel drive": the **carrier exists**
  (`BMDM_TurnOnSpot` + `TurnOnSpotFrontTorqueFactor` 0.6 / `TurnOnSpotRearTorqueFactor` -0.5,
  i.e. front/rear counter-torque, which is a four-wheel torque split, not a steer-angle trick),
  but **no script site selects mode 1**, so what triggers it is UNKNOWN. This is a partial
  confirmation, not a decoded behaviour.
- "Battle mode moves in the stick's direction and turns to face the camera": the **carriers are
  present** (`AbsoluteMoveDirection`, `BattleModeYawOffset` = 90 deg, the `BattleModeSteer*` /
  `TrailingSteer*` family, `bForceBattleModeMovement`) and the stick-vector path is in script in
  `CheckBattleStrafe`; the arithmetic is native and UNKNOWN.
- "Battle mode is four-wheel drive": `BattleModeFrontThrottle`/`BattleModeRearThrottle` exist but
  carry no shipped value; `SVehicle.NumPoweredWheels` / `SVehicleWheel.bPoweredWheel` carry no
  tag in either stream, so four-wheel drive per se is UNKNOWN.

No contradiction between the leads and the files was found; nothing in the files contradicts
the claims, and nothing proves the arithmetic either.

## UNKNOWNs

1. **Body of `RVehicleSimBatmobile.SetDriveMode`.** It is a native declaration: script is the
   5 bytes `29 <param ref>` and nothing else. The per-mode torque/steer arithmetic is in
   `BatmanAK.exe`; only the mode argument and the fields it consumes are in the package.
2. **What selects `BMDM_TurnOnSpot` (value 1).** Tried: corpus-wide scan of every Function export
   for the `SetDriveMode` export index — four sites, all 0 or 2. `ForceTurnOnSpotMode` and
   `DesiredTurnOnSpotSpeed` exist but no decoded body writes them. Where it would be found: the
   native `SetDriveMode`/sim tick condition on speed or throttle.
3. **The operator of the `DriveMode` guard in `BattleMode.BeginState`.** The read (offset 59/74)
   and the call (88/103) are decoded; the comparison goes through an `EX_Context`, which the
   one-pass scan does not classify.
4. **Exact arithmetic of the camera-relative move.** `CheckBattleStrafe`/`PursuitStrafe` read
   `aBaseY`/`aStrafe`, `Pawn.Rotation` and `BattleModeYawOffset` in one expression window; the
   operator chain is not flattened, so only the inputs, the 16384 constant and the call targets
   are decoded.
5. **Per-wheel powered flags.** `SVehicle.NumPoweredWheels` (1908) and
   `SVehicleWheel.bPoweredWheel` (116) exist in the layout but carry no tag in the shipped sim or
   either CDO. Where it would be found: the spawned wheel objects at run time, or the native sim.
6. **`Power Slide` (left stick + RT + X).** No `PowerSlide`/`Slide`/`Drift` function exists under
   the Batmobile classes; the X binding (`QuickGadgetX` -> `SelectVehicleWeapon(2)`, G3-02i /
   `DefaultInput.ini:269`) selects a weapon slot. Likely the native handbrake/skid path
   (`HandBrakePct`, `bHoldingDownHandbrake`, `SkidToStop*`), whose values are in the note.
