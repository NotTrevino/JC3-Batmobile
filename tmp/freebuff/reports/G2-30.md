## UNKNOWNs and limits

1. **Brand-new hulls are still blocked, but on one block, not the whole table.** The face table is
   one 4-byte record per plane (`u16 first, u8 count, u8 min`); the census `face_table()` is
   generated and fits **54/54** hulls — records start at index 0, chain `first + count`, and end at
   `index_count`. It is only found after skipping an unnamed, 16-byte-aligned block between the
   plane block and the table: **0 B on 17 hulls, 16 B on 16, 32 B on 9, 48 B on 12**. That block's
   *content* (floats in one hull, `0xFF` words in another) and the record's `min` byte (1 on 31
   hulls, 0 on 17, 3 on 16, 2 on 15 …) have no reading, and the writer copies both rather than
   building them. So a hull authored from a convex decomposition of the body mesh is **not possible
   yet**; hull *replacement* (same topology, or a donor hull in a donor slot) is.
2. **The chassis mesh cannot be re-authored.** `hknpExternMeshShape` vertices are 3 × u16 quantized
   and the de-quantization frame is still unpinned (`SHAPES.md`, *Still open*). The body's
   `sportsmuscle_body` instance is an extern mesh, so DIM-4's "collision hull matches the Batmobile
   body" still needs convex hulls (or that frame).
3. **The object count is fixed.** The writer keeps the three fixup tables' sizes, so it cannot add or
   remove objects; a new hull must replace an existing slot. Growing the tables is a separate,
   unproven step (named as §7 step 4 of the report).
4. **`hknpShapeMassProperties` (56 objects) and the 80/64-byte body entries are not decoded** — a
   hull write leaves inertia and the shape↔body binding as they were. Whether that is physically
   right is not claimed.
5. **No runtime claim.** Every check here is the reader's own. Whether Havok and the game accept a
   written file is a **phase-Q** question and is not asserted anywhere in the report.
6. **The assembly variant is not a station bake.** `Working/Assembled/sportsmuscle_true.physicsc`
   differs from the donor in one `f32` (`hknpPhysicsSystemData` +0x3598, `-2.5699999…` →
   `-2.5699000…`) and `stations()` reads no station set from either file; "same station table" in
   the plan therefore means "the writer copies the bytes it was given", which it does.
7. The `T-P3` / `T-CO2` / `T-CO3` rows in `Working/Translation/T_ROWS.jsonl` were **not** edited
   (not in this card's Out list): their `why` ("no `.physicsc` writer") is now answered and T-22
   resolves them.
