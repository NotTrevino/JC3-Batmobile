## UNKNOWNs (with why)

1. **Which of these files the shipped game reads, and in which order.** The `BasedOn` lines give a
   chain; no file states that the runtime reads the derived file first or the base last. No runtime
   oracle was used (G3-03 is a file-only card).
2. **The merge rule across a chain for a key defined more than once.** Duplicate keys and the UE3
   operators `+ - . !` are written in the files; their load-time effect is not stated in any file.
3. **The relationship between cooked `Bm*.ini` and its chain.** See the containment table: not exact in
   any family, so no conclusion.
4. **Where the Batmobile's handling values (steering, suspension, torque, wheel setup) live.** Measured:
   no such key in the 37 files (probe table). Their location was not searched beyond the ini set; that
   is G3-01 / G3-06 territory and is not claimed here.
5. **Which tonemap / exposure / colour-grading values reach the screen.** The set carries only `PP_*`
   multipliers, `Bloom`, `DepthOfField`, `MotionBlur` and MLAA switches. Whether BmAK's on-screen
   tonemap/exposure come from packages or from level volumes was not decoded.
6. **The consumer of `EnableCameraAssist`.** The key and value are decoded; the class property that
   reads it was not looked up in this card.
7. **Which `[SystemSettingsBucketN]` applies at runtime.** Buckets exist with
   `BasedOn=SystemSettings` / `SystemSettingsMobile` / `SystemSettingsMobileTextureBias`; the selection
   logic is not in the ini set.
8. **Semantics of the settings-profile `BasedOn`** (51 lines, listed verbatim): how a bucket composes
   its parent is not stated in any file.
9. **`DefaultCompat.ini`'s terminal.** `BasedOn=..\Engine\Config\BaseCompat.ini` resolves to a file that
   is not in the install.
10. **`[IniVersion]` semantics.** The section exists in several files with numeric rows; nothing in the
    set says what reads it.
11. **Encoding of values containing non-ASCII text.** Not an issue here: no non-ASCII key or value was
    found; UTF-16LE+BOM detection is byte-exact for the two UTF-16 files.
