# The BmAK paint numbers → JC3 `CarPaintMM` slots: write plan, conversions, proof, and the unwritable rest

**Task.** Take the JC3 paint-constant slots (`cb2` `CarPaintStaticMaterialParams`, `cb6`
`CarPaintDynamicMaterialParams`, `cb7` `CarPaintDynamicObjectParams`) named by
`tmp/freebuff/reports/G3-04e.md` and `Research/JC3Grab/CB0_SLOTS.md`, and place every BmAK paint value
from `tmp/freebuff/reports/colour-bmak-wet-look.md` — base **0.025787 / 0.025787 / 0.03**,
roughness **0.4**, reflectivity **0.2**, metalness **1.0**, clear coat **1.0**, wet multipliers
**0.6 / 0.6 / 1.6 / 0.75** — into a slot and offset, with the value written after conversion, the
measurement that proves it on the built result, and the part that cannot be written with its
closest-system answer.

**Inputs, as found on disk.** `tmp/freebuff/reports/G3-04e.md` (not `reports/G3-04e.md` — there is no
`reports/` checkout of it; §"R-4" is the slot table), `Research/JC3Grab/CB0_SLOTS.md` (+ `.json`,
generated by `Tools/scripts/jc3_cb0_slots.py`), `tmp/freebuff/reports/colour-bmak-wet-look.md`.
Supporting, all read: `Research/JC3Grab/TINT_WRITE.md` (the palette write path),
`Research/JC3Grab/TINT.md`, `tmp/freebuff/reports/apply-colour-and-material-rows.md` (the T-MA3/T-MA4/
T-MA7 replacement values), `Tools/scripts/factors.py`, `Tools/scripts/bat_assemble.py`,
`Tools/scripts/appearance_bake.py`, `Research/BatmobileGrab/VALUES.json`.

**Labels.** **decoded** = a named member/value read at a file offset. **derived** = arithmetic on
decoded values, shown. **UNKNOWN** = searched and absent, with the file that settles it.

**One correction carried from the inputs, not re-litigated.** The paint constants are **not** in
`cb0`. All 12 headers of the paint family bind `CarPaintStaticMaterialParams` → `cb2`,
`...DynamicMaterialParams` → `cb6`, `...DynamicObjectParams` → `cb7`, `RBIInfo` → `cb8`, with 12/12
identical member tables (`CB0_SLOTS.md` §2; `G3-04e.md` "the family test"). Every offset below is from
that table.

## 1. The slot map these values land in

### 1.1 `cb2` — the static block (316 B: 18 float4 + 7 floats)

Block payload offset: `static_params` float4[0] starts at **payload +0x9**; `static_support` at
**+0x129** (`CB0_SLOTS.md` §3). Within `static_params`, float4 *i* is at `+0x9 + 16·i`; component *c*
of float4 *i* is at `+0x9 + 16·i + 4·c`.

| slot (cb2 offset) | member | what the BmAK value uses it for |
|---|---|---|
| `cb2[0]` @ **0** (`+0x9`) | `m_SpecularGloss` | the satin: roughness 0.4 |
| `cb2[1]` @ **16** (`+0x19`) | `m_Metallic` | metalness 1.0 |
| `cb2[2]` @ **32** (`+0x29`) | `m_ClearCoat` | clear coat 1.0 |
| `cb2[3]` @ 48 | `m_Emissive` | — (not a paint value here) |
| `cb2[4]` @ **64** | `m_DiffuseWrap` | candidate base-colour vector, role **UNKNOWN** |
| `cb2[5..7]` @ 80/96/112 | `m_DirtParams` / `m_DirtBlend` / `m_DirtColor` | dirt path, disabled by the build |
| `cb2[8..14]` @ 128…224 | decal count / width / 4 colours / blend | 0 (no livery decals) |
| `cb2[15..17]` @ 240/256/272 | `m_Damage` / `m_DamageBlend` / `m_DamageColor` | 0 (chapter damage, not hit damage) |
| `cb2[18].x..w` @ 288/292/296/300 | `SupportDecals` / `SupportDmgBlend` / `SupportLayered` / `SupportOverlay` | 0 |
| `cb2[19].x..z` @ 304/308/312 | `SupportRotating` / `SupportDirt` / `SupportSoftTint` | 0 |

### 1.2 `cb6` — the dynamic block (76 B: 4 float4 + 3 floats)

| slot (cb6 offset) | member | role |
|---|---|---|
| `cb6[0]` @ **0** (`payload +0x145`) | `m_TintColorR` | tint, linear float4 |
| `cb6[1]` @ **16** (`+0x155`) | `m_TintColorG` | tint |
| `cb6[2]` @ **32** (`+0x165`) | `m_TintColorB` | tint |
| `cb6[3]` @ 48 | `_unused` | — |
| `cb6[4].x` @ **64** (`+0x185`) | `m_SpecularGlossOverride` | overrides `cb2[0]` |
| `cb6[4].y` @ **68** (`+0x189`) | `m_MetallicOverride` | overrides `cb2[1]` |
| `cb6[4].z` @ **72** (`+0x18d`) | `m_ClearCoatOverride` | overrides `cb2[2]` |

### 1.3 `cb7` (20 B) and `cb8`

`cb7` `CarPaintDynamicObjectParams` = 1 float4 + 1 float; `cb8` `RBIInfo` carries
`ModelDiffuseColor` at `cb8[8]` — the second **role-UNKNOWN** base-colour candidate (`CB0_SLOTS.md`
§5). Neither is written by any project tool, and no BmAK value maps to a `cb7` member.

### 1.4 The second carrier: the palette record

The tint also exists as a **palette** record, and that is the path the engine is known to read for the
per-car colour (`TINT_WRITE.md` §1/§2.1):

| field | offset | size |
|---|---|---|
| `tints[i]` element | `0x50 + 80·i` | 80 B |
| `tint_r` / `tint_g` / `tint_b` (`ColorRGBA`) | `+20` / `+36` / `+52` | 16 B each (4 × float32) |
| `specular_gloss` / `metallic` / `clear_coat` | `+68` / `+72` / `+76` | 4 B each |

so `tints[i].tint_r.R` is at file offset `0x50 + 80·i + 20`, and a one-float edit changes exactly 4
bytes (`TINT_WRITE.md` §3 round trip: 1897 B → 1897 B, 4 bytes at `0x74`).

## 2. The write path the plan has to use (what actually writes these slots)

| writer | what it writes | evidence |
|---|---|---|
| `Tools/scripts/bat_assemble.py:831` | `blk.static_params = pack("<72f", …)` from the `factors.py` spec, in `FX.STATIC` order | decoded (code) |
| `Tools/scripts/bat_assemble.py:832` | `blk.static_support` (7 floats) | decoded |
| `Tools/scripts/bat_assemble.py:833-835` | `blk.dynamic_params = pack("<16f3f", …)` — `TintColorR/G/B` + 4 zeros + the three overrides | decoded |
| `Tools/scripts/appearance_bake.py:534-546` | per-material patch of `static_params[0:4]` (gloss), `[4:8]` (metallic) and `dynamic_params[16:19]` (the `cb6[4]` overrides), then a byte-identical re-encode check | decoded |
| palette `.vmodc` (`TINT_WRITE.md` §2) | `tints[i].tint_r/g/b`, `specular_gloss`, `metallic`, `clear_coat` | decoded |

So the values are writable **as block floats** (`.rbm`), and the tint is *additionally* writable in the
palette. `FX.STATIC` order is `SpecularGloss, Metallic, ClearCoat, Emissive, DiffuseWrap, DirtParams,
DirtBlend, …` (`factors.py:42`), i.e. float4 *i* = `cb2[i]`, which is the same order `CB0_SLOTS.md`
decoded from the shipped `.rbm` payload — the writer and the container agree.

**A blocker found while reading the writer, stated before any value.** `factors.py:250-256` computes
gloss as `1 − roughness` and then **caps it at `VALUES["paint"]["gloss_cap"]`**, and
`Research/BatmobileGrab/VALUES.json` still holds **`gloss_cap: 0.4`** and **`albedo_gain: 3.4476`**.
The T-MA3/T-MA4 rows (`apply-colour-and-material-rows.md` §2) establish that the cap is a wrong
inference (the donor palette ships 8 of 10 tints at 0.45) and that the gain must be 1.0, with
replacements **0.600** and **gain 1.0**. Until those two `VALUES.json` inputs change, a build run
today writes **0.400**, not 0.600, and multiplies the albedo by 3.4476. That is write-plan step 0.

## 3. Value-by-value placement

Column "written value" is the number to place in the slot **after** the conversion named in the row;
"proof" is the read-back on the built files (all of it is a file read, so it can run today).

### 3.1 Base colour — `[0.025787, 0.025787, 0.03]` linear

The colour is authored on `Batmobile_V3_WheelArchs_NEW_MIC` #767 and multiplied by BmAK's own
`Diffuse_Adjust` `[2.2, 2.0, 2.0, 1]` → effective `[0.056738, 0.05158, 0.06]` linear
(`colour-bmak-wet-look.md` §2; `apply-colour-and-material-rows.md` T-MA3).

| target | slot / offset | conversion | written value | proof on the built result |
|---|---|---|---|---|
| **body albedo** (the carrier the build uses) | `CarPaintMM` `s0` `DiffuseMap` / `t0` — not a cbuffer slot; the texture is generated per block | **linear → 8-bit sRGB**, `factors.srgb8` (`factors.py:169`) | **`0x43 / 0x41 / 0x45`** (= 0.0566 / 0.0516 / 0.0600 linear) — T-MA3 replacement | read the generated `.ddsc` RGB mean and assert 67/65/69 ± 1; assert `albedo_gain` no longer applied (T-MA3's error was 3.44×) |
| authored base, if written raw | same `s0` | linear → sRGB | `0x2D / 0x2D / 0x30` (= sRGB 45/45/48) | same read; this is the authored value, not the shipped look |
| **tint slots** (only if the block's tint is the carrier) | `cb6[0]` @0 / `cb6[1]` @16 / `cb6[2]` @32 | **none** — the tint is linear float4, written verbatim | `[0.025787, 0.025787, 0.03, 1.0]` | decode `dynamic_params[0:4]`, `[4:8]`, `[8:12]` and assert those floats |
| palette record (alternative carrier) | `tints[i].tint_r/g/b` @ `0x50+80i+20/+36/+52` | none | same three floats, `A = 1.0` | re-export the palette and assert the three floats at the named file offsets (TINT_WRITE §3 method) |
| base-colour *vector* members | `cb2[4]` `m_DiffuseWrap` @64 and `cb8[8]` `ModelDiffuseColor` | — | **not written** | role UNKNOWN (§5) |

Note on which of these is right: `factors.py:315-330` assigns **channel 0 to the generated `s0`** and
**channels 1–3 to `TintColorR/G/B`**, so the body colour is an `s0` byte triple in the current build
and the tint slots carry the other channels. The palette is the per-car colour the engine is known to
read (`TINT_WRITE.md` §1), so both carriers are listed; the plan writes `s0` (delivered today) and the
palette (so a player tint change cannot silently replace the charcoal).

### 3.2 Roughness 0.4 → gloss

| target | slot / offset | conversion | written value | proof |
|---|---|---|---|---|
| static gloss | `cb2[0]` `m_SpecularGloss` @ **0**, components 0–3 at `+0x9/+0xD/+0x11/+0x15` | **gloss = 1 − roughness** (`factors.py:250`) → 0.600; the `gloss_cap` clamp must be raised first (§2) | **`[0.6, 0.6, 0.6, 0.6]`** | decode `static_params[0:4]` on every paint block of every LOD and assert exactly `0.600` (4 dp) |
| palette gloss | `specular_gloss` @ `+68` of each tint | none (already a gloss) | **0.600** for all 10 tints (T-MA7) | re-export the palette, read the 10 floats at `0x50+80i+68` |
| override variant | `cb6[4].x` `m_SpecularGlossOverride` @ **64** | same | `0.600` where the override is used, else left neutral | decode `dynamic_params[16]` |

The polarity ("is the float gloss or roughness?") is a **derived convention**, not a decoded fact
(`colour-bmak-wet-look.md` §8 item 7). The pass band on the rendered result is the test (§4).

### 3.3 Reflectivity 0.2 — no slot exists

| target | slot / offset | status |
|---|---|---|
| `m_SpecularGloss` / `m_Metallic` / `m_ClearCoat` | `cb2[0..2]` | the members that exist; none is a reflectance level |
| `cb8` / `cb2` F0 member | — | **absent**: `cb2` has gloss, metallic, clearcoat only; `Card-T-21 A11` "no F0 / no anisotropy / no weather input on `CarPaintMM`" holds |

**Written value: none.** The closest system is the D2 route: the reflectance *band* round the
dielectric F0 (`F0_d = 0.04` **assumed**) obtained by switching `m_Metallic` and adding the second
`m_ClearCoat` lobe — 6 of 20 decoded values land in band, 14 miss by 0.0058…0.1551
(`apply-colour-and-material-rows.md` §3). Recorded, not written, because writing a guessed band value
would be a fabricated pixel response.

### 3.4 Metalness 1.0

| target | slot / offset | conversion | written value | proof |
|---|---|---|---|---|
| static metallic | `cb2[1]` `m_Metallic` @ **16**, components at `+0x19+4c` | none — `Material{c}_Metalicity × Metalicity_Multiplier` (`factors.py:270-272`) | **`[0.0, 0.0, 1.0, 0.0]`** — BmAK's 1.0 is `Material2_Metalicity`, i.e. **component 2**, and `Material0` has no metalness member | decode `static_params[4:8]` and assert component 2 == 1.0, components 0/1/3 == 0.0 |
| override | `cb6[4].y` `m_MetallicOverride` @ **68** | none | `1.0` where the override is used | decode `dynamic_params[17]` |
| palette metallic | `metallic` @ `+72` | none | **1.0** (8 of 10 tints already 1; the other 2 are 0) | read the 10 floats at `0x50+80i+72` |

**Conflict that changes the proof, not the value.** `CB0_SLOTS.md` names `m_Metallic` a float4 and
`factors.py` fills it per material channel, while `colour-bmak-wet-look.md` §6 records it as "one
value for the whole block". Both readings put 1.0 in the same float4; they disagree on whether
component 2 is independent. The read-back above asserts the per-channel form the writer produces and
records the block-wide reading as the alternative — the rendered pass band (§4) is what decides it.

### 3.5 Clear coat 1.0

| target | slot / offset | conversion | written value | proof |
|---|---|---|---|---|
| static clearcoat | `cb2[2]` `m_ClearCoat` @ **32**, components at `+0x29+4c` | none | **`[1.0, 1.0, 1.0, 1.0]`** | decode `static_params[8:12]` and assert 1.0 |
| override | `cb6[4].z` `m_ClearCoatOverride` @ **72** | none | `1.0` where overridden | decode `dynamic_params[18]` |
| palette clear coat | `clear_coat` @ `+76` | none | **1.0** (already 1 on all 10 tints) | read the 10 floats |

**Caveat in the writer.** `factors.py:274` sets `ClearCoat` to 1.0 **only where `Normal_Map_Lacquer`
is bound**, 0 otherwise. The body therefore currently gets 0 unless the lacquer normal is authored;
the write plan sets the paint channel to 1.0 unconditionally, because BmAK's `clear_coat` is a palette
constant (1.0 on all tints, `COLOUR.md` §4), not a texture-presence test.

### 3.6 The wet family 0.6 / 0.6 / 1.6 / 0.75 — not carriable

| BmAK member | value | slot | status |
|---|---|---|---|
| `Wetness_Refl_Fresnel` | 0.6 | **none** | 0 of 13 `carpaintmm*` headers declare a wetness member or a rain sampler (`app-wetness-and-rain.md` §2; `colour-bmak-wet-look.md` §6) |
| `Wetness_Reflectivity_Multiplier` | 0.6 | **none** | same |
| `RainReflectivityMul` | 1.6 | **none** | same |
| `RainRoughnessMul` | 0.75 | **none** | same |
| — derived combination — | 0.4 × 0.75 = **0.3 roughness → gloss 0.7** | `cb2[0]` @0 | the only expressible form: a *static* wet state |
| — closest per-material lever — | `Window` `s9` `RainOccluderSampler` (`t40`), `GeneralMkIII` `WetnessNoiseTexture` (`t41`) | not `CarPaintMM` | D8's named route |
| — the scene term — | `TEST_WETNESS_FACTOR` @ 104 in `deferred_clusteredlightingtunable` | scene cbuffer, not ours | value UNKNOWN, not a per-car write |

**Written value: none of the four.** Two honest options, both recorded rather than silently chosen:
(a) keep the dry satin 0.600 and accept that the wet look is the scene's; (b) ship the *wet* composite
gloss **0.700** as a single baked value, accepting that the car then looks wet in dry weather. The
plan takes (a) as the default because the dry value is the authored one and the wet state is a scene
input; (b) stays as the fallback if the reference look is judged wet-first.

## 4. Measurements that prove each value

Two classes, and the distinction matters because the visual probe is not available today.

**A. Read-back assertions on the built artefacts (runnable now, no game).** After the build, decode
each `*_lod*.rbm` with `Tools/scripts/rbm_geom.py`, and for every `CarPaintMM` block assert:

| # | assertion | expected |
|---|---|---|
| M1 | `static_params[0:4]` | `[0.6, 0.6, 0.6, 0.6]` |
| M2 | `static_params[4:8]` | `[0.0, 0.0, 1.0, 0.0]` (component 2 = 1.0) |
| M3 | `static_params[8:12]` | `[1.0, 1.0, 1.0, 1.0]` |
| M4 | `dynamic_params[0:12]` | the tint triple if the tint is the carrier, else unchanged |
| M5 | `dynamic_params[16:19]` | `[0.6, 1.0, 1.0]` where overrides are used |
| M6 | re-encode | `decode(write(block)).write() == bytes` (the existing byte-exact oracle, `appearance_bake.py:550`) |
| M7 | palette | `tint_r/g/b` = the three floats, `specular_gloss` 0.6, `metallic` 1.0, `clear_coat` 1.0 across 10 tints |
| M8 | population | all 185 `CarPaintMM` blocks (16 per body LOD ×5 + 5 per wheel LOD ×5 ×4) carry the same values — a block missed is a slot that renders with the donor's blue-grey (`T-MA1`) |

`Tools/scripts/spec_check.py` already does this comparison against the `factors.py` spec
(`spec_check.py:125-160`), so M1–M3 are one command once the spec holds the new numbers.

**B. Pass bands on the rendered car (needs the probe the test ban currently forbids).** Stated so the
plan has a stop condition when it runs:

* **base colour** — mean body-pixel albedo in neutral daylight within **±3 code values** of
  `(0x43, 0x41, 0x45)`; a reading near `(0x7D, 0x77, 0x7E)` is the withdrawn 3.44× gain (`T-MA3`).
* **satin (roughness 0.4)** — the specular lobe's half-width on a flat body panel between **0.6× and
  1.6×** the donor block's at gloss 0.4; a mirror (half-width < 0.5×) means the gloss landed near 1.0,
  a matte (> 2×) means the polarity is reversed.
* **metalness 1.0** — in the same lighting the paint's diffuse term drops to **≤ 20 %** of the
  dielectric donor's while the reflection keeps its colour; no change means component 2 is not the one
  the shader reads.
* **clear coat 1.0** — a second, tighter highlight appears over the base lobe (two lobes visible at
  grazing angles); one lobe only means `m_ClearCoat` is still 0 via the lacquer test.
* **wet 0.6/0.6/1.6/0.75** — **not measurable as a material value**, because nothing is written. If
  option (b) is taken, the band is: gloss reading within ±0.05 of 0.700 in dry weather, i.e. the
  recorded approximation, not a reproduction of the rain response.

## 7. Ordered write plan

0. **Unblock the writer:** set `Research/BatmobileGrab/VALUES.json` `paint.gloss_cap` → **1.0**
   (or 0.6) and `paint.albedo_gain` → **1.0**, per T-MA3/T-MA4. Without this the build writes 0.400
   and a 3.44× albedo whatever the spec says.
1. **Base colour:** `s0` diffuse = `0x43/0x41/0x45` (effective), palette `tint_r/g/b` =
   `[0.025787, 0.025787, 0.03]`, `A = 1.0`.
2. **Gloss:** `cb2[0]` = `[0.6]*4`; palette `specular_gloss` 0.6 across 10 tints; `cb6[4].x` = 0.6
   if overrides are used.
3. **Metallic:** `cb2[1]` = `[0, 0, 1.0, 0]`; palette `metallic` 1.0; `cb6[4].y` = 1.0.
4. **Clear coat:** `cb2[2]` = `[1]*4` unconditionally (drop the lacquer-texture gate);
   palette `clear_coat` 1.0 (already); `cb6[4].z` = 1.0.
5. **Record, do not write:** reflectivity 0.2 and the four wet members — with the D2 band and the D8
   closest-system strings above, so the gap is carried by the plan and not by a guessed value.
6. **Verify:** `spec_check.py <dir> <template>` for M1–M3/M6, the palette re-export for M7, the block
   census for M8; then the §4B pass bands when a visual probe is permitted.

## 8. Limits of this document

* Static reads only: no build was run, no `.rbm`, palette or `.dds` was modified, no game launched.
* The conversion in §3.1 for the tint slots is "none" because the block stores linear floats
  (`bat_assemble.py:833` packs the values it is given, and the palette ships `White` at 0.05 linear,
  `TINT_WRITE.md` §2.1). The albedo texture is the one place a transform is required, and the transfer
  is named (`factors.srgb8`, standard 2.4-piece).
* The `0x43/0x41/0x45` triple is quoted from T-MA3's replacement row, not recomputed here; the raw
  authored conversion `0x2D/0x2D/0x30` is stated beside it so the two are never confused.
* Nothing in this plan re-tunes a value to a screenshot; the pass bands are stop conditions for a
  later probe.
* **Revert:** delete this file. Nothing else was touched.
