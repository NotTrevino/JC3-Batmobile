## Answer

The drivable car's rigid-body collision is **Physics.Batmobile_V3_Physics**
(BmGame.upk export 158266, 194 bytes). Its arrays, decoded:

- `BodySetup` count **2** -> RB_BodySetup exports **169750** (`Batmobile_Chassis`) and
  **169751** (`Batmobile_Rig_Weapons_Trans`)
- `BoundsBodies` count 2, `Bounds` count 2
- `ConstraintSetup` count **1** -> RB_ConstraintSetup export **171462**
- `PhysicsAssetInstance` -> export **158308**, which itself holds `Bodies` count 2 and
  `Constraints` count 1

It is reached from `Batmobile.SVehicleMesh` (Playable_Batmobile_SF.upk export 5289): the
component's `PhysicsAsset` reference is serialised at property offset **824** of the BmGame
base template `Default__RVehicleBatmobileBase.SVehicleMesh` (export **175716**). The same
template carries the AnimTree at 656 (`Anims.Batmobile_Drivable_AnimTree`).

Oracle for full-vs-half (derived): body 0's `Bounds` entry spans (-339.793, -172.844, 27.25)
to (350.75, 175.5, 227.75) = 690.543 x 348.344 x 200.5 cm; divided by the extent triple that
is a ratio 1.000 / 0.930 / 0.966. Half-extent triples would give ~0.5, so the triples are
full sizes.

Constraint (171462, 86 bytes): FNames `Batmobile_Rig_Weapons_Trans`,
`Batmobile_Rig_Weapons_Trans`, `Batmobile_Chassis`; vectors (-0.004818, -1.3e-05, 1.677767),
