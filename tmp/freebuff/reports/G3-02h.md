# G3-02h — Which keyboard and mouse bindings drive the Batmobile

`STATUS:` **done**.

**Answer: in the effective PC ini chain, exactly one keyboard key is bound to a
Batmobile-specific command — `C` → `ToggleDrivingCamera` (DefaultInput.ini:186) — and it is
matched by name only. Nothing on the keyboard or mouse is bound to accelerate, brake, boost,
fire, exit, eject or a battle-mode switch: those commands exist only on `XboxTypeS_*` lines.
Keyboard driving (if any) can only come from the generic movement axes `W`/`S`/`Up`/`Down`
(`Axis aBaseY`), `A`/`D` (`Axis aStrafe`) and `Left`/`Right` (`Axis aBaseX`), which are matched
by name and whose vehicle consumers are UNKNOWN. That is why G3-02 lists keyboard driving as
open: the bindings are not missing from the files, the *vehicle-side consumers* are undecoded.

`BINDINGS_MERGED.json` (G3-02g) does not exist, so this was derived from the raw chain. Game never
run; everything is read from the four ini files and `BmGame.upk` (read-only).

## 5. Where keyboard driving is actually set (lead, not a decode)

The ini chain never binds a vehicle command to a key, yet a driven Batmobile needs keys. G3-02b
decoded a runtime rebind path (quoted verbatim from `CONTROLS_CONSUMERS.md`, re-checked by P6):

- `SetPursuitModeKeyBinds` virtual-call sites: `BattleMode.EndState@112`,
  `RGameInfo.SetPCBinds@94`, `RPlayerController.ResetBindsToDefault@4055`,
  `DrivingMode.BeginState@275`
- `DrivingMode.ToggleBattleMode` (export 105028) callers: `BattleMode.Tick@382/@502`,
  `RadioMode.PlayerTick@167/@2343`, `RVehicleBatmobileBase.PrepareForBatmobileTakedown@58`,
  `DrivingMode.ToggleBattleMode@145/@188`

So the game installs vehicle keybinds at runtime (`SetPCBinds` / `BeginState`), outside the ini
chain. That is where a keyboard accelerate/steer mapping would be found — not in `Config/*.ini`.
