## Value → mesh table

**Label: `derived`** (rule stated in `COLLISION_SELECTOR.md` and in the JSON). Inputs are all
`decoded`: comparison constants at 45/75/102/132, call targets at 48/78/105/135, mesh properties
9797/9798.

| mode value | mesh component property | detach at | attach at |
|---|---|---|---|
| 0 | — (never appears in a mesh pair) | — | — |
| 1 | `BatmanCollisionMeshPursuitMode` | 48 | 105 |
| 2 | `BatmanCollisionMeshBattleMode` | 78 | 135 |

The pairing is polarity-independent: detach(old = k) and attach(new = k) use the same k for the same
mesh, so k names the mesh whatever `0x9A` means. Under the inverted polarity the function would attach
a mesh whenever the value is *not* k, which contradicts its own detach/attach pair; that reading is
rejected in the doc.

**Decoded negative:** `SetHidden`, `SetActorCollision`, `SetBlockRigidBody` appear **nowhere** in the
selector body (oracle `call_set` asserts the exact call set). The G3-01b-mode card's hypothesis —
that the selector would hide/show meshes through those calls — is not how it works: it uses
`DetachComponent` / `AttachComponent`, one `SetCollisionFilter(ECollisionFilter 0, bool)` and
`SetBatmanCanClimb`.

## The runtime fact, explained

Sampler logs (`Research/BatmobileGrab/runtime/samples-*.jsonl`, 7 files, 23 samples with a mode
value) recomputed here: values `{0: 17, 1: 6}`, 7 transitions, all `0↔1`.

- every sample with mode 1 has no driver seated (5/5); mode 0 occurs seated (7) and with the vehicle
  dormant/no driver (9) — so 0 is "Batman not outside", not "seated";
- the 0→1 transitions at `10:05:15.778`, `11:48:22.562` and `11:48:38.572` are exactly the exit
  events; the 1→0 at `11:48:25.206` is the re-entry.

Explanation (`derived`, inputs decoded): the exit path's callers pass **1** (`OnSleepRBPhysics`, and
`DriverLeft`'s 1-branch), so "Batman left the Batmobile" puts the vehicle in the mode that carries
`BatmanCollisionMeshPursuitMode`; entering passes **0**, which attaches no collision component (the
old mesh is removed by the old-value detach). Mode 2 is only reachable through `DriverLeft`'s other
branch.

## Why the branch encoding is UNKNOWN (recorded, not guessed)

The repo token table names `0x06 EX_Jump` / `0x07 EX_JumpIfNot`, but that name does not survive a
test. Over **74,632** `0x06`/`0x07` sites in `BmGame.upk`, the 2-byte word after the token was read as
an offset under five encodings (absolute, relative to the token, relative to the operand end,
relative to the script end, and negated-relative): the best scores **10.2%** of sites landing on a
statement-start byte, against a ~3–8% chance level, and **51%** of the words are larger than the
script they sit in. A real offset encoding would be near 100%. So the words are not offsets, and
"body on true vs on false" cannot be read from them. Consequence for this card: the table is
`derived` from the constant↔mesh pairing and the old/new split, and the doc says so; the guard
polarity is listed as UNKNOWN rather than assumed.
