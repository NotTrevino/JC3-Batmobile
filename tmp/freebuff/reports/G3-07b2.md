## Method in one paragraph

`RUNTIME_LAYOUT.md` O5 had already pinned the slot-index idiom `shl R, 7` (handle × 128 =
`sizeof(body_slot)`) followed by `add R, qword ptr [B + 0x60]` (the world's slot-array base).
The script byte-scans `.text` for `shl r64, 7`, accepts it only where the bytes decode as that
instruction at an instruction boundary, and keeps the 132 sites followed by that add (seed S1),
3 more where the add uses a register loaded from `[B+0x60]` (S2), and any `imul R,R,0x80` + add
(IM: 0 in this image). That taint travels inside each function (mov/lea aliases, cleared on any
other write, call arguments `rcx/rdx/r8/r9` reach the callee's parameters) to a fixpoint:
135 seeded functions, 139 reached. Every read at `[base+0x30]`/`[base+0x40]` from a tainted base
is collected (425), and a read is accepted as a *slot* consumer only when the same function also
touches the record's distinguishing fields `+0x0c` / `+0x50` / `+0x60` through a tainted base —
that fingerprint leaves 4 reads in 2 functions and rejects 421 reads belonging to other
128-byte-stride records. Each accepted read is then classified by following the loaded value
(xmm register and its stack slot, resolved through the live `rsp` delta) into the operations
that consume it.

## The values, labelled

### decoded (instruction + address, quoted in `SLOT_FLOAT4.md` §4/§5/§6)

- `0x141514105` `movaps xmm2, xmmword ptr [rcx + 0x40]` — the read of `+0x40`, inside
  `0x1415140f0`, `rcx` = slot (`.pdata` 80 B is a chunk, real body 381 B).
- `0x14151411f` `movaps xmm0, xmmword ptr [rcx + 0x30]` — the read of `+0x30`, same function.
- `0x1415141f8/1fc/1ff` `mulps xmm2,[rsi+0x20]` / `mulps xmm0,[rsi]` / `mulps xmm1,[rsi+0x10]`
  with `rsi = rcx = the slot`: the `+0x40` value, broadcast lane by lane, is multiplied by the
  record's own `+0x00`/`+0x10`/`+0x20` rows.
- `0x14151424f/252` `addps xmm0, xmm2` / `subps xmm1, xmm2` and `0x141514255/25b`
  `movaps [r12 + 0x10], xmm0` / `movaps [r12], xmm1`: the AABB is the caller's `[r12]`
  (min) / `[r12+0x10]` (max), expanded by the shape radius from `[shape+0x14]`
  (`0x14151422d` `subss xmm0, dword ptr [r11 + 0x14]`).
- `0x141513ff5` `movaps xmmword ptr [rcx + 0x30], xmm1` (source `[rdx + 0x30]`), after
  `0x141513fc0/0f513fd9/0f513fea/0f513ff5` write `+0x00/+0x10/+0x20/+0x30`: `+0x30` is row 3 of
  the 4x4 at `+0x00`, and `0x141513fb7` `mov ebx, dword ptr [rcx + 0xc]` treats `+0x0c` as flags.
- `0x1415140d6` `movaps xmmword ptr [rcx + 0x40], xmm2` with `0x141514088` `cmpneqps` and
  `0x14151409d` `cmpltps`: `+0x40` is one float4 written from a source float4, with lane tests
  that set flag bits in `+0x0c`.
- `0x141505846`/`0x14150584e` read `+0x30`/`+0x40` and `0x141505852`/`0x14150584a` write them
  elsewhere, in the sequence `+0x00,+0x10,+0x20,+0x30,+0x40,+0x50` — one 0x50-byte body plus a
  shape pointer at `+0x50`.
- `0x14119fa30` (14 instructions) `out = v.x*[rdx] + v.y*[rdx+0x10] + v.z*[rdx+0x20]`; the
  consumer calls it at `0x1415141ab` with `rdx = rsi = the slot`.
- The slot index idiom, as RUNTIME_LAYOUT O5 stated: `0x1415054e4` `shl rbx, 7` +
  `0x1415054e8` `add rbx, qword ptr [r15 + 0x60]`.

### derived (rule + inputs)

- "slot-record base register" = the taint of the seeds above (S1 132 / S2 3 / IM 0 in 135
  functions) propagated through aliases and call arguments to a 139-function fixpoint.
- 425 reads at `+0x30`/`+0x40` from a tainted base; 4 accepted (2 functions) and 421 rejected
  because their function never touches `+0x0c`/`+0x50`/`+0x60` through a tainted base.
- Classification: `0x141514105` and `0x14151411f` → vector arithmetic (`0x1415141cd` `addps`
  for the `+0x30` copy, the three `mulps` for the `+0x40` value); `0x141505846`/`0x14150584e`
  → copy (their only consumer is the store at `0x14150584a`/`0x141505852`). No instruction
  anywhere in the accepted set does `minps`/`maxps`/`cmpps`/`comiss` on either value.
- Verdict per the brief's rule: one independent classifying consumer for each offset, so
  **UNKNOWN**; `+0x30` 1 transform / 0 AABB, `+0x40` 1 transform / 0 AABB.

### UNKNOWN

- **The either/or itself.** One function (`0x1415140f0`) classifies both offsets; the only
  other accepted consumer (`0x141505820`) copies them without classifying. Tried: the full
  `shl 7` seed family (893 sites), `imul …,0x80`, S2 seeds, and interprocedural argument taint
  to a fixpoint. Where a second classifying consumer would be: a reader that gets the slot
  pointer from a parent record rather than computing `handle*128`, which this taint does not
  follow.
- **Whether `+0x40` is a position or a scale/extent vector.** It is used both as a broadcast
  against the three rows (a per-axis scale reading) and as a point through `0x14119fa30` (a
  position reading); the two are consistent with either. Proving it needs the shape virtual
  method called at `0x141514218` (`[rax + 0x30]` on the shape vtable), whose target is resolved
  at run time — out of reach for static analysis here.
- **`+0x30` after the copy.** The consumer copies it to `[r11 - 0x28]`, reloads it at
  `0x1415141c0` and adds one float4 (`0x1415141cd`), after which the frame slot is not read
  again on that path; no bound comparison uses it.
- **The 421 rejected reads.** They belong to other 128-byte-stride records that also use
  `shl 7`; the fingerprint separates them from body slots, but no stronger oracle was built, so
  they are reported as rejected, not as contradictions.
- **The slot's writer for `+0x00…+0x3f` from world data.** `0x141513fa0` copies a 4x4 in from
  `rdx`; who fills that source (and whether it is world or local) is not traced here — that is
  the neighbouring call-chain card's subject, which this one deliberately does not depend on.
