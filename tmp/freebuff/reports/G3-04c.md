## 1. What the rework changes, against `review-G3-04b.md`

**Item 1 — vector defaults (review I-1).** A `MaterialExpressionVectorParameter` serialises its
default as a `StructProperty` whose own tag name is **`DefaultValue`**, at field **0xCC**,
**size 16** (four floats). G3-04b looked for `FloatProperty`/`VectorProperty` at that offset only,
so it reported 0/87. Now **82/87** decode; the five that genuinely carry none are **669
`Anisotropic_Channel_Choice`, 683 `Main_BaseColour`, 716 `Material0_BaseColour`, 720
`Material0_BaseColour`, 724 `Direction`**. The tag's name is the evidence, not a UE3 convention:

```
export 711 MaterialExpressionVectorParameter  size=102  outer=Batmobile_Worn
    DefaultValue   StructProperty   off=0x00cc size=16
    None           NameProperty     off=0x00ac val=Diffuse_Adjust
    None           GuidProperty     off=0x00b4 val=5fda350dbab7e545aefca9400c4a12e6
    None           BoolProperty     off=0x0064 val=True
    None           ObjectNCRProperty off=0x0068 val=359
```

**Item 2 — pairing by owner, not by name (review I-3).** Each `*ParameterValues` item is a
terminated tag stream: `NameProperty` @0x00, the value tag @0x08, `GuidProperty` @0x0C (scalar) /
0x10 (texture) / 0x18 (vector). The `GuidProperty` payload's first int32 is the name
**`ExpressionGUID`** (name 1310) and its last 16 bytes are the GUID, which equals the expression's
own `GuidProperty` (0xB4; 0x124 on texture-sample parameters). Every one of the 52 overrides
resolves, and every matched expression carries the same parameter name (oracle
`pairing_agrees_on_name`, 52/52). The two cases the review named now read:

- MIC 767 `Diffuse_Adjust` `[2.2, 2, 2, 1]` → **export 711**, `MaterialExpressionVectorParameter`
  in `Batmobile_Worn`, default `[1, 1, 1, 1]` — not scalar 453 in `Batmobile_V3_Tyre_V2_MAT`.
- MIC 767 `Material0_BaseColour` `[0.025787, 0.025787, 0.03, 1]` → **export 716** (same GUID also
  on 720 in `Batmobile_Worn_NoRain` and 683 in `Batmobile_V3_Body_NoRain_MAT`); **716 carries no
  `DefaultValue` tag**, so the override is the only value in bytes for that parameter.

**Item 3 — no operator, no product (review I-2).** `COLOUR_PARAMS.*` contains only single-tag
values: `float`, `linear_colour_4f` or `object_ref`. There is no `base x adjust`, no sum, no "final
colour". The combine rule is reported as UNKNOWN with its own measurement: the 11 Batmobile
`MaterialFunction`s hold **944** `FunctionExpressions` slots, **0 non-zero** in this read.

## 3. The chain, and how its start is proven

| step | export | class | name | parent | parent's export | field |
|---:|---:|---|---|---|---:|---|
| 1 | 763 | MaterialInstanceConstant | `Batmobile_V3_Mainbody_NEW_MIC` | `Batmobile_V3_WheelArchs_NEW_MIC` | 767 | 0x84 |
| 2 | 767 | MaterialInstanceConstant | `Batmobile_V3_WheelArchs_NEW_MIC` | `Batmobile_Worn` | 359 | 0x84 |
| 3 | 359 | Material | `Batmobile_Worn` | — | — | — |

The start is not taken from a document: the `Batmobile_V2` SkeletalMesh (export 5284) has exactly
one `int32 count` + references run in its first 32 KiB whose references all resolve to material
exports (at payload byte 8287, 19 slots), and **slot 2 is export 763**. The parent link is the
MIC's `ObjectNCRProperty` at 0x84, whose value resolves to a `MaterialInstanceConstant` then a
`Material`.

So a body-slot override is inherited from `Batmobile_V3_WheelArchs_NEW_MIC`, and if not set there
from `Batmobile_Worn` — which is the skeleton of the review's I-6 concern, now in the record.

row keeps all three and marks which one is in the chain material.

present arrays), the same `size − 2` shape the G3-04b review noted on `FunctionExpressions`. It is
reported per array, not assumed away.
