## The oracle

`--check` does not trust the table; it recomputes from the source bytes:

1. the in-scope row set is derived from `T_ROWS.jsonl` and must equal the table's exactly (a missing
   or extra row fails), and each row's `doc` must match the ledger's;
2. every quoted `file:line` is re-opened and the quote must be a substring of that line after
   whitespace normalisation, as must each `must` value - a moved line or a changed number fails;
3. every "not in the class defaults" claim (29 names: `WheelRadius`, `Suspension`, `SteerSpeed`,
   `LatSlipFactor`, `TurnOnSpot`, `TurningModeMaxSpeed`, `BattleModeVSpeedCurve`,
   `StandardTorqueVSpeedCurve`, `TransformationAnimNode`, `BattleModeCamFOV`,
   `AirControlYawTorque`, `BootLight`, `RiotSuppressor`, ...) is asserted against the file it names,
   so an absence claim that becomes false fails the check;
4. the status/relation/document/per-card counts are recomputed and compared with the committed JSON,
   and the Markdown is byte-compared.

The oracle earned its keep on the first run: it rejected the three `LensFlareComponent` citations
(`REMAINDER.md:1124` -> the correct line is **1127**), which were then fixed. T-L25..T-L34's flare
evidence is the only place a line number was wrong; no value was.
