# G3-02k - the eject's special move, and what actually launches Batman

**STATUS: DONE.** The `TriggerSpecialMove` call in `DrivingMode.EjectFromVehicle` is decoded:
it dispatches on `Car.ShortRangeGlideKick`, whose class default is the move asset
`GlideKick.GlideKickShort_FromBatmobile`. The move's asset, its config, its instance class and
its animation are all read from the packages, and the launch comes out as numbers from the
animation's root-motion translation. Three residuals are named as **UNKNOWN** (the name of one
`AnimSequence` field, the per-frame distribution inside the animation, and the meaning of the
`0x4a` argument token).

## 1. Result

**The call at `+1103` is a *virtual* `TriggerSpecialMove` (`0x1b`, name index 79525), not a
final call, so the callee is resolved on the runtime class of its receiver.** The receiver is
the Context chain

```
Context(object = Context(object = LocalVariable "EjectFromVehicle.Car",
                         skip=9, prop="RVehicleBatmobileBase.ShortRangeGlideKick", flag=0,
                         func=InstanceVariable "…ShortRangeGlideKick")
        skip=17, prop=null, flag=0)
  -> TriggerSpecialMove(Self, EjectFromVehicle.Loc, <0x4a>)
```

Raw argument bytes (`17 00 e0 99 01 00 4a 16`): `Self`, the local `Loc`, and one unnamed
1-byte token. `Self` is the `DrivingMode` object, `Loc` the move location.

The three-argument order is confirmed by the config class's own forwarding body,
`RSpecialMoveConfigConfigurable.TriggerSpecialMove` (export 20377, 41 bytes), which passes its
own locals `Controller, MoveLocation, ForceReplicateToClient` straight through to
`Config.TriggerSpecialMove`.

The vehicle's class default for the receiver member names the move:

| member | default | source |
|---|---|---|
| `RVehicleBatmobileBase.ShortRangeGlideKick` | `GlideKick.GlideKickShort_FromBatmobile` (`RSpecialMoveConfigConfigurable`) | `CLASS_DEFAULTS.json` (decoded from `Default__RVehicleBatmobile`, field 5484) |
| `RVehicleBatmobileBase.ShortRangeGlideKickRange` | `2500.0` cm | same, field 6848 |

In `Startup.upk` that asset is export 169053, 10 bytes, outered to
`Batman_Batmobile_Moves.GlideKick`, with exactly one property - `Config` at field 400 - pointing
at export 168882 `RSpecialMoveConfig_GlideKick` (122 bytes), which holds `AnimName` (field 400)
= `[Batmobile_Short_Range_Glide_Kick, Batmobile_Mid_Range_Glide_Kick]` and `AnimSet` (field 124)
= `Code.BM_Batmobile` (export 81597, 55 sequences).

The instance class is not guessed either: `Default__RSpecialMoveConfig_GlideKick` (export 31678)
sets `InstanceClass` (field 140) to `RSpecialMoveInstance_GlideKick`.

**No scripted velocity and no class-default velocity exist anywhere on that chain.**
`RSpecialMoveInstance_GlideKick.TriggerSpecialMove` (111 bytes) calls its parent once and then
does window-villain bookkeeping; its parent `RSpecialMoveInstance_RelativeAnimMove.TriggerSpecialMove`
(3256 bytes) calls, in byte order: `RSpecialMoveInstance.TriggerSpecialMove`,
`GetEndMovementStance`, `GetAnimSet` x2, `PickRandomAnim`, `OnPlayerHasBeenMoved`,
`BeginQueuedChangePose`, `BeginChangePose`, `FinalAnimStarted`, `GetCustomIdle`,
`EndChangePose`, `Core.ActivateOutputLink`, `TunnelCamera`, `SetCameraState` - no
`SetVelocity` / `SetRBLinearVelocity` / `AddForce` / impulse call. The config class's defaults
carry an `InstanceClass`, two bools and a rumble object, no numeric field.

**So the launch is the animation's root motion.** `Batmobile_Short_Range_Glide_Kick` (export
75836) carries it in field 108:

| quantity | value |
|---|---|
| root translation | `(764.945, 0, 0)` cm |
| forward distance | **764.945 cm = 7.649 m** |
| vertical rise | **0 cm** |
| frames / rate | 113 @ 30 fps |
| duration | 3.733333 s (field 156; equals (113-1)/30) |
| mean speed | **204.9 cm/s = 2.049 m/s** |
| mean step per frame | 6.83 cm |

The mid-range sibling `Batmobile_Mid_Range_Glide_Kick` (export 75835) carries
`(949.433, 0, 0)` cm over 114 frames - 3.7667 s, 252.1 cm/s - so the pair bounds the launch at
**7.65 - 9.49 m forward, 0 cm rise**.

## 2. Why field 108 is the root-motion translation (evidence, not assumption)

A cooked `AnimSequence` stores simple properties inline with no FName, so the offset is the only
handle. All 55 sequences of `BM_Batmobile` were read:

- field 108 is **absent on 39 of 55** sequences and present on the other 16 - exactly the ones
  whose names describe travel (`Abseiling_*`, `grapple_In`, `BatMobile_90_Stand_*`,
  `BatMobile_Stand_Out_Roof`, `In_*_Remote_Batmobile`, `Drive_Idle`,
  `Steering_Left_To_Right`, the two glide kicks). A bounding box, a scale or a per-frame
  constant could not do that.
- field 156 (`SequenceLength`) equals `(NumFrames-1)/Rate` on **every** one of the 55
  sequences, which fixes fields 156/160/168 as length/frames/rate.
- both glide-kick vectors are `+X`-only with `|Y| = |Z| = 0`, i.e. straight along the
  character's facing, no rise.
- the two kicks travel farther along `+X` than any `Stand` sequence in the same set
  (the largest standing value is `BatMobile_Stand_Out_Roof` at 59.6 cm).

Field 124 is the paired root-motion rotator (non-zero only where the sequence turns, e.g.
`grapple_In` `[16384, 0, 0]`, `BatMobile_Glide_Abseil_Out` `[0, 32768, 0]`).

## 3. UNKNOWN residuals (stated, not filled in)

- The **name** of field 108: the tag is a simple property and stores no FName. The content is
  identified by the census above.
- The **per-frame** root-translation curve: the keyframe block (28,812 bytes after the tag
  stream, which ends at 860 of the export's 29,672) is zip-compressed; its format is not
  decoded. Only the total and the mean are given. The `AnimZip_LinearMotion` struct at field
  992 (`true`, `[313.805267, 10.643361, 58.19133]`, `[531.536682, -43.152721, -18.314209]`,
  a 16-byte rotation blob) is recorded verbatim in the JSON, not interpreted.
- Which of the two animations plays on a given eject: `AnimName` is an array and the parent body
  calls `PickRandomAnim`; the selection logic is not decoded.
- The `0x4a` third argument: a one-byte token whose meaning is not established (G3-02j reports
  it too). It is read as `ForceReplicateToClient` only because that is the forwarding body's
  third parameter name.
