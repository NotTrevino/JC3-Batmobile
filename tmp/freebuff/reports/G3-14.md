## Method, and the measurements that fix it

1. **References** — *declared*: `AUDIO_MAP.json` event rows → `bank_ref` (`package.bank`),
   `AUDIO_FEATURES.json` media rows, `objects.jsonl` `AkBank`/`AkEvent` objects. 361 event rows,
   29 distinct `package.bank` references, 10 claimed-missing banks / 90 rows.
2. **Package presence** — *decoded*: all 4,145 `.upk` under the install root. Chunk stream is
   decompressed **only as far as the export table end**, names/imports/exports are parsed from
   that prefix, and each export's class is resolved exactly as `upk_read.Package.class_name`
   does (negative class index → that import's object name; positive → that export's name).
   Measured layout facts this rests on: chunk 0 ends at the import table (`Engine.upk` chunk 0
   = 824,108 B = imports end, so the export table starts in chunk 1), the first chunk tag is
   256 B after `name_offset` (`Engine.upk`: name_offset 873, tag 1129), and a compressed image
   is larger than its file (38.8 MB image, 26.6 MB file).
3. **Payloads** — *decoded*: bytes are read only for the banks this card is about (117 exports
   in the packages that hold them). Verified byte-identical to `upk_read`:
   `cand == truth` on `Engine.upk` export 37004 `BML_Batmobile` (2,268,588 B, offset 5,742,291).
   An `AkBank` payload is a UE3 object, not a bare bank: `BML_Batmobile` starts
   `03 00 80 00 01 00 00 00 …`; `BKHD` is located, not assumed (`WEA_Rain_Materials` puts it at
   payload offset 6,265).
4. **Event counts** — *decoded*: `HIRC` chunk = `u32 size`, `u32 object count`, then per object
   `u8 type + u32 size + body`; type 0x04 = Event. (Reading the chunk size as the count is what
   yields six-figure "event counts"; that bug was caught by the AUDIO_MAP cross-check.)
5. **Bank files** — *decoded*: every `.bnk`/`.pck` in the tree: size, magic, `BKHD` id/version,
   HIRC counts, ASCII bank name.
