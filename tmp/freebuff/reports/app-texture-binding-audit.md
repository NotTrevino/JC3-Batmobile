# Texture binding audit — all 405 grabbed Batmobile textures, by role, binding and shipping

**What this is:** the table the build briefs consume. Every one of the **405** grabbed texture rows is
classified by role (albedo, normal, mask, ramp, emissive, damage, UI, other), by whether a BmAK
material reaches it (and which), by whether it is a duplicate, and by whether the build ships it —
with the reason when it does not. The table itself is `Working/Appearance/TEXTURE_AUDIT.md`, the
machine form is `Working/Appearance/TEXTURE_AUDIT.json`, and both are regenerated by
`Tools/scripts/app_texture_audit.py --write`; `--check` re-derives both and fails if a name marked
unused appears anywhere in `MATERIALS.md`.

## 2. Sources and the rule for "unused"

| source | what it contributes |
|---|---|
| `Research/BatmobileGrab/TEXTURES.md` | the 405-row census: package, texture, size, format, bytes, `bound by` (the material/parameter that reaches it) |
| `Research/BatmobileGrab/MATERIALS.md` | every master material and instance parameter row; searched for each texture name before anything is called unused |
| `Research/BatmobileGrab/SLOTS.json` | the 19 mesh slots and their material instances (the slot-binding column) |
| `Working/Appearance/build/ddsc/*.ddsc` | the 28 files the build actually ships |
| `Working/Appearance/build/*.rbm` | the 25 built parts, cross-check of which slots reference which texture |
| `Working/Translation/T_ROWS.jsonl` | row T-MA6 (405 / 38 / 28) — reconciled below, not copied |

A texture is `used` when the census binds it to a material **or** a `MATERIALS.md` row names it;
`unused` only when neither is true — `--check` re-reads `MATERIALS.md` and fails on a contradiction.
`duplicate` is a separate column: the name occurs in more than one package, or another name has the
same size/format/byte count.

## 4. Reconciliation with row T-MA6

T-MA6 records **38** textures bound to slots and **28** shipped. This audit re-derives **29** names
bound through the 19 slot materials' rows, **40** bound within the Batmobile's own package, **56**
bound in any of the five packages, and reproduces the **28** shipped files exactly. The 38 sits
between the 29 and the 40; the difference is bindings that live in a master material's expression
graph rather than an instance/parameter row, which this parser does not read. Recorded as a
reconciliation item; the table was not bent to match.

## 5. The 28 shipped files

The full list is the "The 28 shipped textures" table in `TEXTURE_AUDIT.md` (file, census name, role).

## 6. Where JC3 has no exact carrier — closest system, gap, build action

Decoded carriers are the ones in the generated table's last column; the gap is BmAK's data shape.
Every row below is a mapping to a real JC3 sampler, not a claim that the texture is unusable.

| role | closest JC3 carrier | gap | build action |
|---|---|---|---|
| albedo | `DiffuseMap` s0 | none | ship as today |
| normal | `NormalMap` s1 | none | ship as today |
| mask | `PropertyMap` s2 / `AOBlendMap` s3 — one RGBA slot | BmAK ships separate metal/rough/reflectivity masks; JC3 wants them packed into one RGBA | pack per material (R metal, G rough, B reflectivity, A AO); the mask rows of `TEXTURE_AUDIT.md` are the input list |
| ramp | `CarPaintMM.TintMap` s3 plus the four `m_Emissive` bands | no standalone ramp sampler; a 1-D ramp becomes a 2-D tint map | ship `Batman_BM3_V2_Leather_Ramp` only if the seat's `CarPaintMM` gains a tint slot; otherwise the bands carry it (`app-emissive-mask-channel.md` §5.1–5.2) |
| emissive | `CarLight.EmissiveMap` s5 (RGB) | only lamp blocks have the sampler; `CarPaintMM` has a constant `m_Emissive` | `app-emissive-mask-channel.md` §5.1/§5.2: lamp atlas in BmAK UV space, or four bands on `CarPaintMM` |
| damage | `CarPaintMM.DamageAlbedo` s5 / `DamageNormal` s4 / `Damage_Chapter_Mask` parameter | the build writes no chapter-mask slot | add the parameter to the damaged materials and ship the `*_Damage_ChapterMask` names, or keep damage on the two damage samplers |
| UI | `hud.gfx` POI/clip art | no vehicle material can reach a UI texture | ship the `Ace_Factory_Screen` family only as authored HUD art, not as a material texture |
| texture sets | `TEXTURES.md` packs four-byte names per set | the 405 rows carry no BC format per row for every package | the build brief consumes the audit's `format` column; missing formats name the package row |
