## Answer to the card

**1. Every interaction object with its transform and animation/state string.** 85 objects match
`entry.*` / `exit.*` / `point.*` / `transition.*` / `trigger.*` / `interaction.*`:
29 entries, 26 exits, 12 transitions, 8 points, 7 triggers, 3 interactions. **15 carry their own
`world` matrix** (the 8 points + 7 triggers); **70 inherit** a parent's; none is without a
transform. The 32 whose nearest transform is the identity `graph`/`context` node are marked
`n/a (container origin)` rather than being handed a verdict at 0,0,0 — an entry is defined by the
point it transitions from, not by a matrix. 36 distinct `state` strings are recorded
(`S_ENTER_DRIVER_VEHICLE`, `S_EXIT_VEHICLE_90L`, `S_GRAPPLE_REEL_TO_STUNT_LAND`, …), plus the
`interaction` hash (`00000000`) and the 9 exits that carry a `modifier`.

The 7 `trigger.*` are the only **volumes**: their matrices carry scale, read as half-extents
(e.g. `trigger.driver` 2.65 × 1.91 × 2.83, `trigger.stunt.vehicle.to.vehicle` 19.1 × 14.1 × 23.4).

**2. Stunt areas decoded.** `StuntAreas` **declares 3 areas in a 32-slot array** (29 empty
`NoName` slots): `front_area` and `front_signature_area` — coincident geometry, 6 points /
4 triangles, 6 valid edges, bound to `sportsmuscle_hood` vs `sportsmuscle_hood_signature` — and
`main_area`, 10 points / 8 triangles on `sportsmuscle_body`. Each is a real triangle set
(`vertices3D_local`, `triangle_indices`, `bounding_box_local`, `center_local`), not a box. The
64 `welding_info` rows contain **8 real welds** (areas 0↔1 ×6, 0↔2 ×1, 1↔2 ×1) and 56 `-1`
placeholders.

**3. Where each lands on the Batmobile.** Frames: Serpente = the 135-point deform envelope
(x −1.33…1.33, y 0…1.524, z −2.560…2.527, agreeing with the 198-mesh union in z), Batmobile =
`stations.json` `body_bbox` (−1.747…1.748, 0.091…2.362, −3.420…3.605); wheelbases 3.003 m vs
5.0289 m, tracks 1.77 m vs 2.416/2.569 m; per-axis normalisation 1.3139 / 1.49 / 1.3809.

## UNKNOWNs and limits

- **Body watertightness.** The Batmobile body mesh is a shell with wheel-arch and window gaps, so
  the three-ray parity `inside` test can disagree with itself; the majority vote is recorded per
  point, and an `inside` verdict near an opening is weak evidence.
- **What a trigger transform's scale means.** Read as a half-extent (translation sits in the last
  row); no file states it, so box sizes are *derived*.
- **Which animation plays.** Only the `state` strings are in the `.epe`; the `.asb` state machine
  that consumes them was not decoded here, so the animation file per state stays UNKNOWN.
- **Whether Rico can actually stand on a mapped area in game.** Not testable offline; geometry is
  the only evidence.
- **A decoding gap worth flagging:** the decoded `detail/*.ee.json` drops the `world` of
  `trigger.driver.fast` and `trigger.stationary.stunt`. The XML has them, so the doc reports all
  7 trigger positions, but a reader limited to the JSON would report those two as UNKNOWN.
- **Parent links.** The decoded JSON's `node` paths cannot resolve a parent (26 duplicate paths,
  `?` placeholders), so the hierarchy is read from `Research/Epe/serpente_civilian.xml` and the
  JSON serves as the value cross-check.
- **Analysis mapping ≠ build transform.** The bbox normalisation is this card's measuring tool.
  Assets keep `bat_assemble.py`'s single `T(p)` (R2); nothing here moves a mesh.
