### What the pass recovered

- **24 of 24 objects yielded no property tag** - every payload starts with a zero type-id
  at byte 0, which is an empty property list, so `upk_read`'s walker stops before reading
  anything (`stop=end`, 0 parsed bytes). That is the failure reason for the whole set, not
  a per-object mystery.
- **7 script-class rows (5 distinct classes) decode their parent class** from the first
  object reference after that empty list (negative index = import):
  `Core.RBatmobileMissileLauncher`,
  `Core.RDummyTarget_Spawnable`,
  `Core.RHidePoint`,
  `Core.RPawnVillainThug`,
  `Core.SequenceEvent`,
  which is what an `(unresolved)` class export is: a script class compiled into the
  package, outer `BmScript`, declaring no properties of its own.
- **17 component rows stop at their own name**: the tail is `NameIndex + Number`, i.e. the object's name
  read against the name table (verified per row: the index resolves to the object's own
  name, and to an unrelated export when read as an object index - so it is a header, not a
  value). At 14-62 bytes there is no room for a value field in any case.
- The grab's own reference scan recovered **96 native references across 29 of the 140 rows**
  (`native_refs` in `objects.jsonl`) - references, not values.

## What this settles

- **No weapon, sim or damage value hides in the native remainder.** The relevant half is 5
  script class declarations (parent class now known) and 17 component instances whose
  payloads are header-only; the values those classes have live on their `Default__*`
  objects, which the grab decodes as ordinary tagged rows (`Default__RBatmobileMissile-`
  `LauncherJoker` and friends).
- The card's `relevant` set produces no new number for G1-08/G1-14/G1-21 to add: the
  families those cards list are all in `OFFSETS.json` / `CHAIN.json` already.
- Gaps.md's "refs recovered" column is explained: 29 of the 140 rows carry 96
  references the native scan found by index probing; a reference is a pointer to another
  object, not a value.

  the byte layout itself stays unexplained.
